# 1. C

**HTML title tag:** 1. C

**Subtitle:** Procedural, closest to the metal — the language kernels are written in

## Callout (philosophy box)

**Core trade-off:** Closest-to-hardware high-level language. You manage memory, you manage pointers, you see exactly what the machine does. Maximum control, maximum responsibility.

## Attribute table

| Attribute | Value |
|-----------|-------|
| What It Is | A procedural, statically-typed compiled language designed in 1972. Provides minimal abstraction over assembly — what you write maps almost directly to machine instructions. No objects, no garbage collector, no runtime. |
| Unique Contribution | Procedural programming closest to low level. Best for kernel programming. Direct memory access via pointers. The lingua franca of systems programming for 50+ years. |
| Strengths | Minimal runtime overhead, predictable performance, runs on every platform imaginable, 50+ years of stability, ABI compatibility, tiny binaries, the foundation almost every other language builds on or calls into. |
| Weaknesses | Manual memory management leads to buffer overflows, use-after-free, double-free bugs. No built-in strings or collections. Undefined behavior lurks everywhere. No namespaces, no modules, primitive error handling (return codes). |
| Business Use Case | Operating system kernels (Linux, Windows NT), embedded systems, device drivers, database engines (SQLite, PostgreSQL), network protocol implementations, real-time systems where predictable latency matters. |
| Example | Code block (see below) |

**Example code block (inside `<pre><code>` in the Example row):**

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    // Allocate memory for 5 integers
    int *arr = (int *)malloc(5 * sizeof(int));
    if (arr == NULL) return 1;

    for (int i = 0; i < 5; i++) {
        arr[i] = i * 10;  // Direct pointer arithmetic
    }

    printf("Third element: %d\n", *(arr + 2));  // 20

    free(arr);  // You must free what you malloc
    return 0;
}
```
