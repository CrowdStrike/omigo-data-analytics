40. Semantically Informative Unique IDs

IDs that carry meaning — type, origin, time, hierarchy — while remaining globally unique.

Core tension: UUIDs guarantee uniqueness but are opaque. Sequential IDs are readable but collide across systems. The goal: an ID scheme where seeing the ID tells you what kind of thing it is, roughly when it was created, and where it came from — without a lookup.

Examples

run_20260811_143022_7f3a — pipeline run, date-sortable, short random suffix

feat:ames:lot_area:profile_v2 — feature profile, dataset scoped, versioned

mod-cnn-v3-shape-20260801 — model artifact with version and date

Design Constraints

1. Must be valid in filenames, URLs, JSON keys, and SQL columns without escaping.

2. Lexicographic sort = chronological sort (at least within same type).

3. Prefix alone sufficient to route to the correct subsystem/table.

4. Collision probability < 1 in 10⁹ within a single pipeline execution context.
