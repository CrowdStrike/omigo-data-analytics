Movement Patterns

MOVEMENT PATTERNS

5. Batch Processing

Collect data over a period, then process it all at once on a schedule — like doing laundry once a week instead of per sock.

scheduled jobs nightly runs throughput
MOVEMENT PATTERNS

6. Streaming

Process each piece of data the moment it arrives, so answers stay seconds fresh instead of a day old.

real-time low latency continuous
MOVEMENT PATTERNS

7. Event Streams: Everything Is a Log

Record every change as an event in an ordered, append-only log — the full story of what happened, in the order it happened.

append-only log ordering replay
MOVEMENT PATTERNS

8. Pub/Sub

Producers publish messages to a topic and any number of subscribers pick them up — senders never need to know who is listening.

topics decoupling fan-out
MOVEMENT PATTERNS

9. Change Data Capture

Watch a database's own change log and forward every insert, update, and delete to other systems as it happens.

database log sync replication

Shape Patterns

SHAPE PATTERNS

10. Transactional Records vs Event Logs

A record stores the current state of a thing; an event log stores every step that led there — two views of the same reality.

current state history audit trail
SHAPE PATTERNS

11. Wide vs Long Tables

The same data can sit as one column per measure or one row per measurement — each shape makes different work easy.

pivot melt tidy data
SHAPE PATTERNS

12. Snapshots vs Deltas

Save a full copy of everything each time, or save only what changed since last time — a storage vs reconstruction trade-off.

full copy incremental point-in-time
SHAPE PATTERNS

13. Append-Only vs Update-in-Place

Add a new row for every change and keep the old ones, or overwrite the existing row — keeping history versus keeping it simple.

immutability overwrite versioning
