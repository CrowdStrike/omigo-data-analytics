## A Map of a Thousand Handwritten Digits

Tags: `core idea` (blue), `visualization` (green), `running example` (orange)

- **The data** — 1,000 images of handwritten digits, each an 8×8 grid = 64 pixel columns
- **The wish** — see all thousand at once and check whether the 3s really look alike
- **The move** — give every image a spot on a 2D map so its nearest images stay nearest
- **The result** — islands appear: a 3-island, an 8-island, a 1-island, with no labels used
- **The promise** — only "who is my neighbor" is preserved; everything else may be distorted

*Example (italic):* It's a subway map: stations keep their neighbors, but lengths and angles are fiction.

**Key point:** **t-SNE / UMAP:** place points in 2D so that high-dimensional neighbors stay neighbors. The layout is built for eyes, not for rulers.

## Three Digits and Their Distances, Before and After

Tags: `worked example` (green), `neighborhoods` (blue)

- **The cast** — A and B are two "3"s; C is an "8" (illustrative pixel distances)
- **Before, in 64D** — dist(A,B) = 4, dist(A,C) = 40: C is exactly 10× farther
- **After, on the map** — dist(A,B) = 0.5, dist(A,C) = 9: now 18× farther
- **What survived** — the order: B is still A's neighbor and C still isn't
- **What didn't** — the ratio: 10× became 18×; the map exaggerated the gap
- **The lesson** — read the map for "near vs not near", never for "how many times farther"

*Example (italic):* Both algorithms will happily stretch a gap or shrink an island if it makes neighbors sit cleaner.

**Key point:** **Rank in, ratio out:** neighbor ranks are the contract; distances, densities, and cluster sizes on the map are side effects of the layout, not measurements.

## One Dataset, Three Different Pictures

Tags: `read with care` (orange), `knobs` (blue)

- **The knob** — t-SNE's "perplexity" (UMAP's "n_neighbors") sets how many neighbors count
- **Small setting** — the map shatters into many tight blobs, some of them accidental
- **Large setting** — blobs merge and smear; fine structure disappears
- **Same data every time** — only the knob changed; all three pictures are "correct"
- **Practice** — run several settings; trust only the structure that survives all of them

*Example (italic):* A team once "discovered" six customer segments that vanished when perplexity went from 5 to 50.

**Key point:** **The picture is not unique:** a t-SNE/UMAP plot is one of many possible renderings — a finding that appears in only one rendering is a property of the knob, not the data.

## Safe Reads and Forbidden Reads

Tags: `common mistake` (red), `rule of thumb` (green)

- **Safe** — "these points form a neighborhood"; "this point sits among the 8s, check its label"
- **Forbidden: island size** — a wide island is not a more varied group; layout sets the spread
- **Forbidden: island gaps** — "cluster A is far from B" is not evidence they differ more
- **Forbidden: density** — a dense blob is not higher probability; t-SNE equalizes densities
- **Risky to model on** — validate on the original columns before feeding map coordinates to models
- **t-SNE vs UMAP** — UMAP runs faster and keeps a bit more big-picture layout; both distort

*Example (italic):* The classic slide: circling two distant islands and announcing "our users split into two very different groups."

**Key point:** **Use it to look, then verify elsewhere:** confirm any pattern with the original columns — real distances, real cluster metrics — before it goes into a decision.
