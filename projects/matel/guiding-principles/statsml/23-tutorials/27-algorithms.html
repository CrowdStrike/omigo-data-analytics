Algorithms

The classic problem-solving recipes of computing — how to sort, search, route, and split work so answers arrive in seconds instead of centuries.

SORTING & SELECTION

1. Quicksort

Pick one item as a pivot, split everything else into a smaller pile and a bigger pile, then repeat — every split leaves the pivot in its final place.

pivot partition recursion
SORTING & SELECTION

2. Merge Sort

Only ever does one easy move — combining two already-sorted piles — so it takes the same predictable number of steps no matter how scrambled the input.

merging piles predictable stable sort
SORTING & SELECTION

3. Quickselect

Find the median — or any k-th smallest value — by splitting around a pivot and chasing only the half that holds your answer, no full sort needed.

median k-th smallest half the work

4. Why Sorting Matters

Sorting 1,000 items costs only about 10,000 steps — cheap enough that "sort first, then scan" turns compare-everything problems into a single easy pass.

5. Two Pointers & Sliding Windows

Two fingers walking down sorted lists, or one window sliding over a stream — answer join, dedup, and running-total questions in a single pass.

single pass sorted lists running totals

6. Divide and Conquer

Split one big job into small copies of the same job, solve the tiny ones, and combine the answers back up — most of the real work hides in the combining.

split the job recursion combine step
DESIGN PARADIGMS

7. Greedy Algorithms

Take the best-looking step right now and never look back — brilliantly fast when the problem rewards it, quietly wrong when it doesn't.

local choice no lookback when it fails
DESIGN PARADIGMS

8. Dynamic Programming

Break a big problem into small overlapping questions, write each answer down the first time you find it — and never solve the same subproblem twice.

memoization subproblems reuse answers
DESIGN PARADIGMS

9. Backtracking

Build a solution one guess at a time, and the moment a guess breaks a rule, undo it and try the next option — try, fail, undo, try next.

try and undo search tree constraints
DESIGN PARADIGMS

10. Constraint Satisfaction

Solving sudoku is not about being clever with numbers — it is crossing off what the rules forbid until only one option survives, and guessing only when crossing-off stalls.

sudoku pruning backtracking

11. Graph Algorithms Overview

A graph is just dots joined by lines — and BFS, DFS, shortest path, and PageRank are one family of recipes for walking that drawing.

12. Dijkstra's Algorithm

Grow a bubble outward from the start and always settle the unvisited spot with the smallest total cost — once cheapest on the frontier, its answer is final.

shortest path frontier cheapest first
GRAPH ALGORITHMS

13. A* Search

Dijkstra with a compass — every corner is scored by distance so far plus an honest guess of the distance left, so the search leans toward the goal.

heuristic goal-directed pathfinding
GRAPH ALGORITHMS

14. Bellman-Ford & Negative Edges

When some roads cost money and some pay you, re-check every road again and again — and if re-checking never stops paying off, you have found a money loop.

negative edges re-checking money loops
GRAPH ALGORITHMS

15. Topological Sort

When tasks depend on each other, find an order that never breaks a "must come before" arrow — the trick every build tool and pipeline scheduler runs first.

dependencies task ordering build tools
GRAPH ALGORITHMS

16. Minimum Spanning Tree

To connect every house with the least total cable, always dig the cheapest trench that links something new — and this greedy move is provably never wrong.

cheapest link Kruskal Prim
GRAPH ALGORITHMS

17. Max-Flow / Min-Cut

The most you can push through a network equals the capacity of its tightest cut — find one shipping plan and one cut that match, and both are proven optimal.

networks bottleneck matching bound

18. String Searching

Find a word inside a long text without re-reading letters — Rabin-Karp updates a window's number cheaply, and KMP never steps backward.

pattern matching Rabin-Karp KMP
STRINGS & NUMBERS

19. Euclid's GCD

Keep replacing the bigger number with the remainder of dividing it by the smaller — the last nonzero remainder is the answer, working for 2,300 years.

remainders common divisor ancient trick
STRINGS & NUMBERS

20. Sieve of Eratosthenes

To find every prime up to n, don't test numbers one at a time — cross out each survivor's multiples; whatever never gets crossed out is prime.

primes crossing out bulk work
STRINGS & NUMBERS

21. Fast Exponentiation

Squaring what you already have doubles the exponent each time — so x⁶⁴ takes six multiplications instead of sixty-three.

repeated squaring doubling big powers

22. Approximation Algorithms

When trying every answer would take a lifetime, get a fast answer plus a proof of how close it is — provably close beats hopefully close.

hard problems guarantees good enough

23. Convex Hull

Stretch a rubber band around a set of pins and let go — the polygon it snaps into is the tightest fence that still encloses every point.

rubber band boundary outermost points

24. Voronoi & Delaunay

Color every spot on a map by whichever point is closest and it splits into territories — connecting territories that touch gives the Delaunay twin.

nearest point territories triangulation

25. Space-Filling Curves

Give every spot on a map one number by walking the blocks in a Z-shaped stroke — then a plain sorted list can answer "what's near me".

Z-order locality spatial indexes

26. Floyd's Random Sampling

Draw k distinct winners from n tickets in exactly k random picks — no retries, no shuffling the whole pile, and memory for only the picks.

random sampling k draws, no retries distinct picks
