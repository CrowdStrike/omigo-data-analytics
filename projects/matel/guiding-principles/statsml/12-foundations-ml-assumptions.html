1. Logistic Regression

Assumptions & What Breaks
  • Linear log-odds: each feature must have linear relationship with log-odds of outcome. Non-linear signal is invisible.
  • No multicollinearity: correlated features produce unstable coefficients that flip signs randomly.
  • Independence: observations must be independent (no clustering, no repeated measures).
  • Sufficient n: need 10-20 events per predictor. 5 features = min 50-100 positive cases.
  • No extreme outliers: single value (cholesterol=900) can dominate the entire coefficient.
  • Violation: assigns zero weight to features with strong LOCAL signal (e.g., U-shaped or range-specific).
  • Verify: Box-Tidwell test for linearity, VIF < 5, Cook's distance for influence.
  • Alternative: range-based binary features, GAM, or penalized regression.

Real example: Logistic regression on bimodal cholesterol: coefficient = 0.02, looks insignificant. But the [240-320] range has 76% positive class. The model cannot see range-specific signal.

2. Linear Discriminant Analysis (LDA)

Assumptions & What Breaks
  • Multivariate normality: each feature must be normal WITHIN each class separately. Not overall.
  • Equal covariance matrices: both classes share the same variance-covariance structure.
  • No multicollinearity: singular covariance matrix makes inversion fail.
  • Sufficient n > features: need more samples than features per class for stable estimates.
  • Violation: non-normal features produce suboptimal boundary; bimodal data gets systematic misclassification.
  • Violation: unequal covariance tilts the boundary, one class gets consistently misclassified.
  • Verify: Shapiro-Wilk per feature per class, Box's M test for covariance equality.
  • Alternative: QDA (relaxes covariance), non-parametric classifiers, or density estimation per range.

Real example: Age is bimodal within the positive class (young risk + elderly risk). LDA fits a single Gaussian, places the boundary at mean=52, missing both subgroups.

3. Naive Bayes

Assumptions & What Breaks
  • Feature independence: ALL features must be conditionally independent given class. P(X1,X2|Y) = P(X1|Y) * P(X2|Y).
  • Correct density model: Gaussian NB assumes normality per class. Wrong density = wrong P(feature|class).
  • No zero-frequency: unseen feature values get probability zero, killing entire class probability.
  • Violation: correlated features (e.g., weight + BMI) double-count evidence, making classifier overconfident.
  • Violation: bimodal feature assumed normal means the valley between modes gets HIGH probability (wrong).
  • Verify: within-class correlation matrix, Q-Q plots per feature per class.
  • Alternative: logistic regression (handles correlations), KDE-based density, range-based features.

Real example: Systolic BP and diastolic BP (r=0.78) both included. NB treats them as independent evidence, producing P(disease) = 0.99 when true probability is 0.65.

4. Decision Trees

Assumptions & What Breaks
  • Axis-aligned boundaries: can only split perpendicular to axes. Diagonal/curved boundaries need many splits.
  • No statistical validation: will split on n=5 if info gain is nonzero. No built-in significance check.
  • Greedy selection: picks locally optimal split, misses globally better feature combinations.
  • No class imbalance handling: with 95%/5% split, tree never finds pure minority leaves.
  • Violation: splits on noise, creates "pure" leaves with n=3 that are random chance.
  • Violation: same feature split multiple times fragments ranges, loses interpretability.
  • Verify: post-hoc significance of leaf purities vs base rate. Cross-validation for overfitting.
  • Alternative: validate each split with statistical test BEFORE accepting. CHAID uses chi-squared at splits.

Real example: Tree splits cholesterol at 245, then at 268, then at 291. Three splits on one feature that a single range [240-320] with p<1e-8 captures directly.

5. Random Forest

Assumptions & What Breaks
  • Feature relevance: with many irrelevant features, random subsets may miss the important ones.
  • Sufficient data: each tree sees ~63% (bootstrap). Small n = repetitive trees = no ensemble benefit.
  • Independent errors: averaging only helps if trees make DIFFERENT mistakes. Dominant features reduce diversity.
  • No extrapolation: cannot predict beyond training range. cholesterol=800 (unseen) gets same prediction as max(train).
  • Violation: masks per-tree overfitting but doesn't fix it. Individual trees still split on noise.
  • Violation: black-box. Cannot explain WHY a prediction was made or which range matters.
  • Verify: OOB error, feature importance stability, training range vs deployment range.
  • Alternative: range-based validated features for explainability and statistical rigor.

Real example: RF predicts "low risk" for cholesterol=750 because max training value was 603. Model confidently extrapolates from the 580-603 region (which was low-risk older patients).

6. Gradient Boosting (XGBoost/LightGBM)

Assumptions & What Breaks
  • Smooth loss landscape: gradient descent assumes smoothness. Noisy features create jagged loss surfaces.
  • No data leakage: later trees overfit to artifacts of earlier trees without careful regularization.
  • Sufficient data: more prone to overfitting than RF on small datasets. Residuals get noisier with depth.
  • Stationarity: assumes future data from same distribution. Concept drift breaks model silently.
  • Violation: boosting AMPLIFIES noise because it focuses on hard examples (which may be mislabeled or noisy).
  • Violation: near-perfect training accuracy but poor generalization; later trees memorize residual noise.
  • Verify: early stopping on validation, learning curves (train vs val gap), SHAP for post-hoc explainability.
  • Alternative: statistical validation per split. Drift detection via distribution monitoring.

Real example: XGBoost on 500 samples with 200 features. Training AUC=0.99, validation AUC=0.61. Trees 50-300 are memorizing noise in hard examples that are actually mislabeled.

7. Support Vector Machines

Assumptions & What Breaks
  • Feature scaling REQUIRED: distance-based. Unscaled features with larger range dominate the margin entirely.
  • Meaningful distance: categorical features as integers create false distance (cat 1 vs cat 3 is NOT 2x cat 1 vs 2).
  • Appropriate kernel: linear kernel assumes linear separability. Wrong kernel = boundary can't represent true separation.
  • Moderate dimensionality: in very high-D, all points equidistant. "Margin" concept becomes meaningless.
  • No heavy outliers: support vectors define boundary. Outlier support vectors distort everything.
  • Violation: feature with range [0, 1M] makes features with range [0, 1] completely invisible.
  • Verify: confirm scaling, no categorical-as-ordinal, try multiple kernels with CV.
  • Alternative: tree-based for mixed types, range-based features for explainability. SVM is O(n^2).

Real example: Income (range 0-200K) and age (range 18-90) unscaled. SVM margin determined entirely by income. Age has zero influence on the boundary despite being highly predictive.

8. K-Nearest Neighbors

Assumptions & What Breaks
  • Feature scaling REQUIRED: ALL features must be on same scale. High-magnitude features dominate distance.
  • Meaningful distance: "nearby" must mean "similar." Categorical/mixed types break this.
  • Low dimensionality: curse of dimensionality: in high-D, ALL points are approximately equidistant.
  • Dense coverage: training data must densely cover feature space. Sparse regions = unreliable predictions.
  • No irrelevant features: every feature contributes equally to distance. Noise dimensions obscure true neighbors.
  • Violation: with 50 features, nearest neighbor is barely closer than farthest point. KNN degrades to random voting.
  • Verify: features scaled, n >> 2^d, k-nearest distances small vs overall spread.
  • Alternative: tree-based for high-D, feature selection first, range-based features reduce dimensionality.

Real example: 30 features, 500 samples. Mean distance to nearest neighbor: 4.82. Mean distance to farthest point: 5.01. Ratio = 0.95. "Nearest" is meaningless.

9. Neural Networks

Assumptions & What Breaks
  • Large sample size: need orders of magnitude more data than parameters. 1000-param network needs 10K+ samples.
  • Feature scaling: unscaled inputs cause vanishing/exploding gradients. Must be ~N(0,1) or [0,1].
  • Smooth manifold: nearby inputs should produce nearby outputs. Discontinuous boundaries are hard to learn.
  • No class imbalance: optimizes for majority class. 99/1 split learns "always predict majority" = 99% accuracy.
  • Appropriate architecture: no theory for choosing. Too small = underfits. Too large = overfits.
  • Violation: small data = memorizes training set. Validation loss diverges while training loss drops to zero.
  • Verify: learning curves, feature scaling confirmed, class-weighted loss for imbalance.
  • Alternative: for tabular data < 10K rows, gradient boosting typically wins. For explainability, not suitable.

Real example: MLP on 800 patient records with 50 features. Training accuracy: 98%. Test accuracy: 54%. Network memorized every training patient by their unique feature combination.

10. PCA (Principal Component Analysis)

Finds directions of maximum variance — assumes linear relationships and meaningful variance
  • Assumes linear relationships: PCA finds linear combinations of features. Non-linear structure (curves, clusters) is invisible — variance along a curve gets split across multiple components.
  • Assumes variance = importance: The first PC captures the direction of highest variance. But if a noisy feature has high variance and the signal feature has low variance, PCA puts noise first.
  • Requires feature scaling: Features with larger ranges dominate PCs entirely. Income (0–1M) will be PC1; age (0–100) will be noise. Must standardize first.
  • Assumes continuous features: Binary/categorical features encoded as 0/1 create artificial directions. One-hot encoded features with 50 categories dominate the PC space.
  • Interpretability collapses: PC1 = 0.3×age + 0.7×income - 0.2×cholesterol. What does this mean? Nothing a domain expert can act on. Original feature meaning is destroyed.
  • Violation: Non-linear data (e.g., two spirals, concentric rings) → PCA projects onto a line through the middle, mixing classes completely. High-variance noise → signal buried in later PCs that get discarded.
  • Real example: Gene expression data with 20K features. PCA reduces to 50 PCs. But the cancer signal is in 5 low-variance genes — PCA discards them because batch effects (technical noise) have higher variance.
  • Alternatives: Non-linear → use t-SNE/UMAP for visualization, kernel PCA for reduction. Categorical data → MCA (Multiple Correspondence Analysis). When variance ≠ importance → supervised feature selection instead.

11. K-Means Clustering

Partitions data into K spherical clusters — assumes equal-size, equal-variance blobs
  • Assumes spherical clusters: K-means minimizes distance to centroid — this only works when clusters are roughly round. Elongated, crescent-shaped, or irregular clusters get split wrong.
  • Assumes equal variance: All clusters are expected to have similar spread. A tight cluster near a spread-out one → K-means gives the big cluster too much territory, steals points from the tight one.
  • Assumes equal size: Biased toward equal-membership clusters. A rare subgroup (n=20) next to a large cluster (n=5000) gets absorbed entirely.
  • Requires feature scaling: Distance-based — unscaled features dominate. Same problem as KNN/SVM.
  • Must specify K in advance: How many clusters? There's no correct answer from the algorithm itself. Elbow method and silhouette scores are heuristics, not proofs.
  • Sensitive to initialization: Different random seeds → different results. K-means++ helps but doesn't guarantee global optimum.
  • Violation: Two concentric rings → K-means draws a line through the middle, splitting both rings in half. Two clusters of different sizes → K-means equalizes membership, misassigning boundary points.
  • Real example: Customer segmentation with income ($0–$1M) and age (18–90). Without scaling, K-means clusters entirely by income (ignoring age). With scaling, it finds "young high-earners" vs "old low-earners" — but if the real structure is "3 lifestyle segments" of unequal size, K-means forces equal splits.
  • Alternatives: Non-spherical → DBSCAN, spectral clustering. Unequal sizes → Gaussian Mixture Models (GMM). Hierarchical structure → agglomerative clustering. Unknown K → DBSCAN (auto-detects), or BIC-based model selection with GMM.

12. Linear Regression (OLS)

Fits a line minimizing squared residuals — the most assumption-heavy algorithm in common use
  • Assumes linearity: Relationship between each feature and the outcome MUST be linear. A quadratic or threshold relationship is invisible — the model draws a flat line through a curve.
  • Assumes normal residuals: Errors must be normally distributed for p-values and confidence intervals to be valid. Non-normal residuals → can't trust significance of any coefficient.
  • Assumes homoscedasticity: Variance of residuals must be constant across all predicted values. "Fan-shaped" residual plots mean standard errors are wrong — typically too small, producing false significance.
  • Assumes no multicollinearity: Features must not be strongly correlated. Correlated features → coefficients become unstable (flip signs, explode in magnitude), standard errors inflate.
  • Assumes independence of errors: No autocorrelation. Violated in time series, spatial data, or clustered data. Leads to underestimated standard errors.
  • Assumes no influential outliers: One extreme point can drag the entire regression line. Cook's distance > 1 means a single observation is controlling the fit.
  • Violation: Predicting house price from square footage — relationship is linear below 3000 sqft but flat above (luxury pricing is location-driven). OLS draws one line through both regimes, underestimating small homes and overestimating large ones.
  • Real example: Ames housing: OLS reports "lot area" coefficient = $2.50/sqft (p<0.001). But residual plot shows massive fan-shape — cheap homes have tight residuals, expensive homes have huge variance. The $2.50 estimate is "significant" but its CI is 4× too narrow.
  • Alternatives: Non-linear → polynomial regression, GAM, or range-based features. Heteroscedastic → weighted least squares or robust regression. Non-normal residuals → GLM with appropriate link. Multicollinear → ridge regression, LASSO, or drop redundant features.

13. EM / Gaussian Mixture Models

Iteratively estimates latent cluster assignments and Gaussian parameters — soft clustering with probabilistic assignments
  • Assumes Gaussian components: Each cluster is modeled as a multivariate Gaussian. Non-Gaussian subpopulations (uniform blobs, skewed groups, ring-shaped clusters) are poorly fit — EM uses multiple Gaussians to approximate, wasting components.
  • Assumes correct number of components (K): Like K-means, must specify K. Too few → merges distinct groups. Too many → splits coherent groups. BIC/AIC help but aren't definitive.
  • Sensitive to initialization: EM finds local optima, not global. Different starting points → different solutions. Can converge to degenerate solutions where one component collapses to a single point (variance → 0).
  • Assumes sufficient data per component: Each Gaussian needs enough points to estimate its mean AND full covariance matrix. With d features, need at least d(d+1)/2 + d parameters per component. 10 features = 65 params per cluster.
  • Covariance estimation can fail: Singular covariance matrices when component has fewer points than dimensions. Regularization (diagonal, tied, or spherical covariance) helps but changes the model's expressiveness.
  • Soft assignments are a strength AND weakness: Points get probability of belonging to each cluster (not hard assignment). Great for overlapping populations. But makes "which cluster does this point belong to?" ambiguous when probabilities are near 50/50.
  • Violation: Fitting GMM to income data that's actually right_skew + a spike at zero (unemployed). EM uses 3-4 Gaussians to approximate the right_skew tail, "discovering" fake subpopulations that are artifacts of the wrong distributional assumption.
  • Real example: Cholesterol with two modes (normal ~200, high ~280). GMM with K=2 correctly finds both. But with K=3 it "discovers" a third group at ~240 that's just the overlap region — not a real subpopulation. BIC says K=2 but only barely.
  • Alternatives: Non-Gaussian clusters → kernel density estimation, DBSCAN. Unknown K → DPGMM (Dirichlet Process — auto-selects K). High-dimensional → factor analyzers or mixture of factor analyzers. Singular covariance → regularized GMM or diagonal constraint.

14. Comparison: Standard ML vs Our Approach

Aspect Standard ML Practice Our Approach (STATSML)
Assumptions Ignored. Hope they hold. Verified before any test or model is applied.
Feature relationships Assumed linear or left to model. Profiled per range. Non-linear signal found in specific intervals.
Splits / Boundaries Greedy, no significance check. Every split validated with appropriate statistical test.
Sample size Arbitrary min_samples_leaf=5. Minimum n computed from test requirements (power analysis).
Explainability Post-hoc (SHAP, LIME). Approximations. Built-in: every prediction has an evidence chain with p-values.
Feature engineering Manual or automated without validation. Each range becomes a binary feature only if statistically significant.
Extrapolation Silently wrong (trees) or crashes (linear). Knows what it knows. Flags unseen regions explicitly.
Drift detection Noticed when accuracy drops in production. Distribution monitoring detects drift before accuracy drops.
Multiple models per feature One model, one vote. Multiple candidate models kept. Agreement = confidence.
The Core Principle: Every ML algorithm has assumptions. Standard practice ignores them. We verify them. The result: predictions you can trust, explain, and defend — because every claim has statistical backing, not just a number from a black box.
