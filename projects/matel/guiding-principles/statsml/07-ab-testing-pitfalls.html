A/B Testing: Tricks, Pitfalls & Malpractice

The most abused tool in data-driven decision making. Every org "does A/B testing." Almost none do it correctly. The complete catalog of what goes wrong — accidentally and deliberately.

The single best defense: pre-registration. Write down your hypothesis, primary metric, sample size, test duration, and decision rule BEFORE the test runs. Publish it where it can't be edited. Then follow it. Everything else is theater with a statistics department.
STATISTICAL

1. Peeking / Optional Stopping

Check p-value daily until p<0.05, then stop. False positive rate inflates from 5% to 20-30%.
STATISTICAL

2. Underpowered Tests (Too Small N)

Run with 500 users when you need 50,000. Declare "no effect." You could only detect a 20%+ lift.
STATISTICAL

3. Multiple Comparisons Without Correction

Test 20 metrics. Report the 1 significant. At α=0.05, you EXPECTED 1 false positive out of 20.
STATISTICAL

4. No A/A Test (Infrastructure Not Validated)

Never ran A/A to verify the test system works. If A/A shows significance, your entire framework is broken.
STATISTICAL

5. T-Test on Non-Normal / Non-Independent Data

Apply t-test blindly to revenue (heavy-tailed), sessions (correlated), ratios (non-normal). Wrong test = wrong answer.
STATISTICAL

6. Sample Size for Alpha Only (Ignoring Power)

Calculate sample for false positive control (α=0.05) but never compute power (1-β). Miss real effects 60% of the time.
STATISTICAL

7. No Pre-Declared Hypothesis

No hypothesis before the test. Afterwards: "We hypothesized X all along!" Post-hoc narrative disguised as prediction.
STATISTICAL

8. High FPR + Multiple Tests = Guaranteed "Win"

20% false positive rate (bad sample) × 5 tests = 67% chance of at least one "significant" result. Guaranteed by math.
DESIGN

9. Wrong Randomization Unit

Randomize by pageview, analyze by user. 100 users × 50 pageviews = 5000 "observations." Variance wrong by 50×.
DESIGN

10. Non-Random Assignment as "A/B Test"

Beta opt-in users get treatment. They're already more engaged. You tested engaged vs average, not feature vs no-feature.
DESIGN

11. Treatment Contamination (SUTVA Violation)

Treatment users influence control via network effects. Referral test: treatment users refer control users. Control is treated.
DESIGN

12. Survivorship Bias in Test Population

Treatment drives 10% of users away. Remaining 90% look great. You measured the survivors, not the treatment effect.
DESIGN

13. Novelty / Primacy Bias

Anything new gets explored → 2-week spike. You measured curiosity, not long-term preference. True effect is at week 4+.
DESIGN

14. Ratio Metric Traps

ARPU went up! Because you lost cheapest customers. Survivors spend more. Numerator flat, denominator shrank.
DESIGN

15. Proxy Metric Optimization (Goodhart's Law)

Clicks up 20%! Users are confused and clicking desperately. Downstream: purchase down, satisfaction down, retention down.
DELIBERATE

16. Asymmetric Infrastructure

Treatment on new fast servers. Control on degraded legacy. You tested infrastructure, not the feature.
DELIBERATE

17. Duration Manipulation (Stop When Winning)

Stop when treatment wins (day 7). Extend when losing ("need more data"). Asymmetric stopping rule = rigged test.
DELIBERATE

18. Post-Hoc Segmentation

Overall: no effect. Check 50 segments. One hits p=0.03. "Works for young male iOS users in California!" That's noise.
DELIBERATE

19. Test Reset Until You Win

Control winning? "Logging bug — restart." Still losing? "Contamination — restart." Treatment wins? "Ship it!" 3 tries = 14% FPR.
DELIBERATE

20. Hiding Downstream Costs

Conversion +10%! (Refunds +40%, support tickets +25%, NPS -15). A/B test only measured above the waterline.
ORG

21. HiPPO Override

VP already decided. A/B test is theater to confirm. If it disagrees: "test wasn't set up right." Feature ships regardless.
ORG

22. No-Loss Framing

Win → "Ship it!" Lose → "Valuable learning!" Both outcomes celebrated. The test has zero authority over decisions.
ORG

23. Twyman's Law Ignored

+40% conversion from a button color? That's a logging bug, not a discovery. Too-good results shipped without checking pipes.
ORG

24. Interaction Effects (Simultaneous Tests)

5 tests running. Each claims independent credit. Sum: +15%. Actual combined: +4%. Interactions eat the gains.
ORG

25. Cargo Cult A/B Testing

"We A/B test everything" = culture signal. No test has ever killed a feature. Decision-reversal rate: <5%. The test is decoration.
CONFOUND

26. Placebo Effect

The act of receiving any intervention produces measurable change. Two-arm tests (treatment vs nothing) cannot separate belief from mechanism. Requires a three-arm design.
MINDSET

27. Testing to Justify, Not to Learn

The hypothesis is backwards — the test exists to produce evidence for a pre-decided launch. Post-hoc metric selection, window manipulation, and segment mining deployed together as institutional p-hacking.
POWER

28. Metric Too Far

Measuring a micro-feature against a macro-metric guarantees inconclusive results. A tooltip improvement can't move GMV in any feasible sample size — that's a power problem, not a feature problem. Measure the proximate metric instead.
