Cloud Security Pitfalls

1. Ephemeral Workloads
Container runs for 5 minutes and is gone. By the time the alert fires, the container has already terminated and evidence is destroyed. You cannot do forensics on a workload that no longer exists. You must capture at runtime or lose everything.
2. IAM Policy Explosion
cloud provider account with 2000 IAM roles, 500 policies, nested assume-role chains. Effective permissions are nearly impossible to compute. "Least privilege" is a theoretical goal but an operational nightmare. One misconfigured role equals account compromise.
3. Multi-Account Blast Radius
Organization with 200 cloud provider accounts. Cross-account role allows Account A to access Account B. Compromise of one account means potential access to all. The "blast radius" of a single credential leak is undefined without full graph analysis.
4. Shared Responsibility Confusion
cloud provider secures the infrastructure; you secure your configuration. But the boundary is unclear — is a misconfigured S3 bucket cloud provider's fault or yours? Neither party monitors the gap between their responsibilities.
5. IaC Drift from Deployed State
Terraform says "security group allows port 443 only." Someone clicked in the console and added port 22. Terraform state and reality diverge. Security reviews the IaC (wrong) not the deployed state (actual).
6. Serverless Visibility Gap
Lambda function runs with no OS to install an agent on, no process monitoring, no file system to scan. Traditional security tools designed for VMs and containers simply do not work. New execution model equals blind spots.
