Sub-User Splitting in Web Experiments

Randomizing at session, cookie, device, or GUID level when the decision-making entity is the user. The same person ends up in both arms — independence is an illusion.

The Core Problem
  • A user has a phone, a laptop, a tablet, and maybe a work browser. Each generates a different cookie/session/GUID. Cookie-based splitting assigns each device independently.
  • Result: the same person sees Treatment on their phone and Control on their laptop. Their eventual conversion (purchase, signup, subscription) is a single user-level decision — not three independent observations.
  • You count 3 "observations" but have 1 independent unit. Variance is underestimated. Correlations within-user are ignored. Everything looks more significant than it is.
Key insight: The unit of analysis must match the unit of decision. If conversion is a user-level event, randomization must be user-level. Anything more granular creates correlated observations masquerading as independent ones.
How It Manifests
  • Cookie-based split: User clears cookies, gets new assignment. Same person oscillates between arms across sessions. Neither arm gets clean exposure.
  • Session-level split: User browses a product page in Treatment (with new recommendation widget), then purchases later in a Control session. Which arm gets the conversion?
  • Device-level split: User researches on mobile (Treatment), converts on desktop (Control). Treatment's contribution is invisible; Control gets false credit.
  • GUID/install-ID split: User reinstalls app, gets fresh GUID. Now in different arm. Prior exposure still influences behavior.

Consequences: Effect dilution (same person partially in both arms), attribution confusion (conversion counted in wrong arm), inflated N (3 devices ≠ 3 users), and inconsistent user experience (breaks trust).

Fix: Split by Authenticated User ID
  • Logged-in users: Hash user-id + experiment-id to assign variant. Same assignment everywhere, every session, every device.
  • Anonymous users: This is genuinely hard. Options: (1) first-party persistent ID via fingerprinting (privacy concerns), (2) restrict experiment to logged-in users only, (3) accept noise and use session-level with larger N and robust SE.
  • Mixed auth states: User browses anonymously, logs in, then converts. If you assigned at cookie level, the pre-login sessions are in unknown arms. Reconcile by attributing all sessions to the user-id arm post-login.
  • Account sharing: Family Netflix account is one user-id but multiple people. If the decision unit is the household, user-id is correct. If it's the individual viewer, you need profile-level splitting.

The tell: Ask "can one human see both variants?" If the answer is yes through any path (multiple devices, cookie churn, reinstall), your split level is below the independence boundary.
