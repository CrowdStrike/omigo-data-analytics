Traffic/City Planning - Domain-Specific Pitfalls

Pitfall Description
Induced demand Build new highway lane → congestion relief → more people drive (latent demand activated) → same congestion in 3-5 years; model predicts "less congestion" but doesn't model behavioral response to the improvement
Sensor coverage gaps Cameras at intersections; no data between them; GPS traces from phones: biased toward smartphone-owners; traffic counts: sampled 2 days/year then extrapolated; the full picture is interpolated from sparse measurements
Simulation ≠ reality SUMO/VISSIM microsimulation: agents follow rules; real drivers: road rage, illegal U-turns, double parking, jaywalking; simulation is orderly, reality is chaotic; policy designed in simulation fails in reality
Special event disruption Concert, sports game, protest, construction: completely overrides normal patterns; model trained on "normal days" fails 50+ days/year; must detect event AND model its unique impact in real-time
Multi-modal interaction Car-bike-pedestrian-bus-scooter share space; each mode has different speed, trajectory, priority; optimizing for cars hurts cyclists; city planning must model ALL modes simultaneously; car-centric data = car-centric policy
Origin-destination matrix from partial data You know WHERE traffic is but not where it CAME FROM or WHERE it's GOING; OD estimation from link counts is massively underdetermined; many OD matrices produce same observed traffic; the inverse problem is ill-posed
