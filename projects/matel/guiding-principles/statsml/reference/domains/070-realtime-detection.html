Real-Time Object Detection

Domain-specific pitfalls for on-device, real-time visual inference systems

Pitfall Description
16ms Latency Budget 60fps = 16ms per frame for full pipeline: capture → inference → render overlay; ANY processing > 16ms = dropped frame = visible lag = nausea on head-mounted; must be fast AND correct
Power/Thermal On-Device Meta glasses: 2W power budget; running YOLO at full resolution = battery dead in 20 min; must trade accuracy for efficiency; smaller model = more errors but device stays alive
Training Images ≠ Live Camera Training: curated datasets, good lighting, centered objects; live: motion blur, partial occlusion, extreme angles, reflections, low light; domain gap between ImageNet and real glasses-cam is enormous
Motion Blur at Head-Turn Speed User turns head → 50ms exposure → entire frame is blurred; detector trained on sharp images fails; must either handle blur robustly or only process stable frames (missing 30% of time)
Privacy Constraints Limit Processing Can't store or transmit raw video of bystanders; must detect/blur faces BEFORE any processing; but face detection IS processing; circular constraint; must process to know what not to process
Occlusion from Device Geometry Glasses frame blocks 10% of visual field; nose bridge occludes center-bottom; these dead zones are ALWAYS there; objects partially hidden by your own device = missed detections in predictable locations
