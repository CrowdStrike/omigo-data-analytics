# Tracking Data: Fingerprinting Generated Content

**Page type:** detail page (two-column obj-table layout: text left 45%, canvas right 55%, one row per section)
**HTML title tag:** Tracking Data: Fingerprinting Generated Content

**Subtitle:** Three separate mechanisms mark machine-generated output: signed file metadata, perturbations in image pixels, and biased token selection in text.

## What is it?

Three mechanisms mark generated output, at three different layers.

- **Metadata / provenance:** C2PA Content Credentials attach a signed manifest — tool, model, edit history. Cryptographically verifiable, so a present manifest is trustworthy to the extent its issuer is
- **Pixel watermark:** Google's SynthID for images perturbs pixel values. Invisible, and designed to survive cropping, re-compression, and colour adjustment
- **Text watermark:** a keyed pseudorandom function splits the token vocabulary into a preferred "green" subset and the rest, then nudges sampling toward green
- **Text watermark lineage:** Kirchenbauer et al. (2023) started this line of work; Google DeepMind's SynthID-Text is a deployed example

Note callout: **Layers fail differently:** a manifest lives outside the content and is easy to remove. A pixel or token watermark lives inside the content and is harder to remove, but needs the key holder's detector to read.

## What does it collect?

- **C2PA manifest:** generating application and version, the model where the issuer declares it, creation time, subsequent edit actions
- **C2PA signature:** the signer's certificate, which is what makes tampering detectable
- **Pixel watermark:** no readable fields — a keyed perturbation present as a statistical property, not stored text
- **Text watermark:** no added characters, no invisible Unicode. The signal is which tokens were chosen
- **Not recorded by default:** the prompt and the user identity

Key-point callouts:

- **Absence is uninformative:** a manifest travels beside the pixels, so a screenshot or re-encode drops it while leaving the image intact. `manifest_present: false` says nothing about origin.
- **Base-rate problem in the detector:** the keyed watermark survives re-encoding, but a detector returns a score against a threshold, so it inherits the same base-rate problem as any rare-class test.
- **The asymmetry is the operational point:** `watermark_present` with a valid signature is positive evidence. Absence is the union of "not generated", "generated by a vendor whose key this detector does not hold", and "mark stripped in transit". Treating a negative as proof of human authorship is the error, and it is the one that gets made.

Note callout: A text watermark carries very little payload. In the basic scheme it answers one question — was this produced by a generator holding this key — not what was asked or by whom.

## Why is it embedded?

Label pill: STATED PURPOSE

- **Label synthetic media** so viewers and platforms can tell what was generated, without guessing
- **Auditable edit history** for images used in news and evidence

Label pill: ADDITIONAL CONSEQUENCE

- **Attribution, not just detection** — a watermark is a per-vendor keyed signal, so the key that answers "was this generated" also answers "by which model"

Key-point callout: **A share of a corpus is not what one verdict adds up to:** a detector reads only the marks whose keys it holds, and an ordinary re-encode drops a manifest, so items fall outside the marked class for reasons unrelated to their origin. A prevalence figure built that way partly tracks which generators mark their output and which files travelled unmodified.

## How reliable is it?

Less reliable than the framing usually suggests. Each mechanism has a specific failure mode.

Label pill: DOES NOT RESOLVE

- **Absence proves nothing** — a screenshot, a re-encode, or an upload to most social platforms strips a C2PA manifest
- **Text watermarks need length** — the test statistic counts tokens, and with few tokens its variance dominates
- **Editing degrades the signal** — paraphrasing, translation and heavy rewriting replace the token choices that carried the mark
- **The test is statistical** — no threshold gives zero false positives and zero false negatives. The correct output is a p-value or a likelihood ratio, not a yes/no verdict
- **Only cooperating generators mark output** — open-weight models can generate unmarked text, so a negative is weak evidence
- **Verification is not open** — reading a pixel or token watermark needs the vendor's detector

Note callout: Keyed watermarking is a different mechanism from the "AI detector" tools that classify text by perplexity or burstiness. Those have no key, no embedded signal, and much weaker guarantees; they have been shown to misfire disproportionately on writing by non-native English speakers. The two should not be reported as the same evidence.
