Evolution of the Default Tech Stack

The combinations the industry converged on — LAMP, the JVM enterprise stack, MEAN, and what replaced them.

Dates are approximate and mark mainstream adoption rather than first release. Bars in red ended as mainstream practice; orange survives in specific niches only.

The Eras

EraWhat changed
1996 – 2010s
The Microsoft stack
Windows Server, IIS, ASP then ASP.NET, SQL Server
A fully integrated commercial alternative with strong tooling and a single support relationship, widely adopted in corporate IT. It was the main counterweight to open source for a decade, and its later reversal is notable: .NET became cross-platform and open source, and Microsoft became a major Linux contributor.
1998 – 2010s
LAMP and the open-source default
Linux, Apache, MySQL, PHP/Perl/Python
The combination that made web development inexpensive: a free operating system, the dominant web server, a free database and a scripting language, all installable on commodity hardware. It powered an enormous share of the early web and much of it is still serving traffic. Its significance was economic more than technical — the marginal cost of trying an idea dropped to nearly nothing, and the acronym itself demonstrated that independently built components could form a recognised, documented whole.
1999 – 2010s
The JVM enterprise stack
Java EE, Tomcat, JBoss/WebSphere, Oracle, Spring
Large organisations standardised on Java servlet containers with a commercial relational database. Application servers, XML configuration and layered abstractions made it heavyweight, and Spring emerged largely as a reaction against that weight. The JVM itself proved durable well beyond the frameworks built on it.
2005 onward
Convention-driven frameworks
Ruby on Rails, Django, Laravel
Opinionated frameworks bundling routing, object-relational mapping, templating and migrations reduced a working application to hours. Convention over configuration was the central idea, and it reset expectations for what a small team could deliver — an influence visible in essentially every web framework since.
2012 onward
JavaScript everywhere
Node.js, Express, Angular/React, MongoDB
Node put JavaScript on the server, making one language span both sides of the application, and document databases removed schema migrations from early development. The reduction in context-switching was real; MongoDB's early positioning against relational databases was later moderated as transactional guarantees turned out to matter more than initially argued.
2015 onward
Containers, orchestration, and Postgres
Docker, Kubernetes, PostgreSQL, Terraform, React
The current common denominator is less a fixed stack than a set of interfaces: applications in containers, scheduled by Kubernetes or a managed equivalent, with PostgreSQL as the frequent relational default and infrastructure declared in code. Language choice became comparatively interchangeable, since the container boundary is what the platform interacts with. Alongside this, the AI stack settled into Python with GPU runtimes and a vector store — the first widely-adopted new stack in roughly a decade.
1960s – 1990s
The vendor-integrated stack
IBM mainframe, COBOL, CICS, VSAM
Hardware, operating system, database and language came from a single supplier as one product. There was no assembly decision to make and no compatibility question, and the trade was complete dependence on that vendor. Much of this is still running in banking and government, where the reliability record is genuinely difficult to reproduce.
1980s – 1990s
Proprietary Unix and expensive workstationsgone
Solaris, HP-UX, AIX, IRIX, Sun hardware
Serious server work meant a commercial Unix on that vendor's hardware — technically strong, and priced so that a single machine was a capital purchase. Each variant differed enough that portability was real work. Commodity x86 hardware running a free operating system removed the reason to pay for any of them.
2000s onward
Linux and macOS settle into place
Linux servers, macOS developer laptops
Two conventions formed and have held for roughly two decades: Linux runs the servers, and a Unix-derived desktop — predominantly macOS, with Linux common too — is where the code is written. The pairing worked because both are Unix-like, so local development approximated production closely enough. Containers later removed most of the remaining discrepancy.

What Disappeared

Ended as mainstream practice:
  • Proprietary Unix on vendor hardware — Solaris, HP-UX, IRIX and the workstation market they supported
  • Apache as the automatic choice — displaced for many workloads by Nginx and by managed load balancers
  • The heavyweight application server — WebSphere and WebLogic, and deploying archives into a running container
  • XML as the configuration format — verbose enough that YAML and JSON replaced it almost everywhere
  • MySQL as the reflexive default — still very widely deployed, but PostgreSQL is now as likely to be the starting choice
  • Manually assembling a stack from downloaded components — the LAMP installation ritual, replaced by containers and managed services
  • The named acronym stack — LAMP and MEAN were memorable because the combination was fixed; current stacks are assembled per project and mostly go unnamed
Alive, but only in niches:
  • Mainframes with COBOL — still processing core transactions in banking, insurance and government
  • PHP — still running a large share of the web, WordPress prominently, and substantially improved since its early reputation formed
  • Java and the JVM — not niche at all: still standard for large-scale enterprise systems and much data infrastructure
  • The Microsoft stack — strong in corporate environments, now cross-platform and open source
  • Bare-metal deployment — retained where predictable heavy load makes virtualisation overhead and cloud pricing unattractive
