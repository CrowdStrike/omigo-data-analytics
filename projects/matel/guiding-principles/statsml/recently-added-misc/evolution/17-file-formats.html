Evolution of Data File Formats

How data is written down — plain text that refuses to die, JSON winning by being small enough, columnar storage changing what analysis costs, and formats that carry their own history.

Dates are approximate and mark mainstream adoption rather than first release. Bars in red ended as mainstream practice; orange survives in specific niches only.

The Eras

EraWhat changed
1960s – present
Plain text, and delimiters
Fixed-width records, CSV, TSV
The oldest format still in daily use, and the one nobody can retire. A file of lines with commas between fields needs no library, opens in any tool, and is readable by a human with no software at all. Its weaknesses are equally permanent: no type information, no declared schema, and no agreement on what to do when the data itself contains a comma or a newline. Every team eventually loses a day to a quoted field or an ambiguous date, and CSV survives anyway because the alternative always requires something installed.
1980s – present
Configuration as its own problem
INI, .properties, XML, YAML, TOML
Settings needed to be edited by people, not just parsed by programs, which is a different requirement from data interchange. XML brought schemas and validation at the cost of verbosity. YAML won much of this space by being pleasant to read, and it carries a well-known hazard: meaning depends on invisible indentation, and unquoted values get coerced into types nobody asked for. It is the format most likely to break a deployment for a reason invisible on screen.
1998 – 2010s
XML as the universal interchange
XML, XSD, SOAP, RSS
For roughly a decade XML was the default answer for exchanging structured data between organisations. It was genuinely capable — namespaces, validation, transformation — and the reason it lost was not technical inadequacy but weight: several times the bytes and considerably more ceremony than most tasks needed. It persists where validation is contractual rather than optional.
2001 – present
JSON becomes the default
JSON, JSON Schema
JSON won by being the smallest format that could carry nested data, and by arriving already parseable in the browser. It has just enough types to be useful and few enough rules to implement in an afternoon. The trade-offs are known and accepted: no date type, no integer-versus-float distinction, no comments, and numbers that silently lose precision past 53 bits — which is why large identifiers are so often transmitted as strings.
2001 – present
Binary schemas for services
Protocol Buffers, Thrift, Avro, gRPC
When machines are the only readers, text is wasteful and its lack of a schema becomes a liability. These formats declare the shape in a definition file, generate code in every language, and encode compactly. The genuinely important property is not size but managed change: field numbering and defined defaults let a producer add fields without breaking older consumers, which is what makes independent deployment of services possible at all. Avro keeps the schema with the data, so a stored file remains readable without hunting for the definition.
2013 – present
Columnar storage for analytics
Parquet, ORC, Arrow
The change with the largest measurable effect on analytical cost. Storing values column by column rather than row by row means a query reading three fields from a two-hundred-field table touches only those three, and values of one type sitting together compress far better. Arrow extends the idea to memory, so tools can share data without serialising between them. This is why querying a lake became affordable, and why row formats persist only where whole records are written and read together.
2015 – present
One record per line
JSONL / NDJSON
A deliberately unremarkable format that solved a specific problem: JSON is not appendable or splittable, because a valid document has one root. Putting one object per line restores both, so a file can be written incrementally, split across workers at any newline, and tailed while being produced. It is the standard shape for logs, events and training data, and it exists because of a structural limitation rather than a performance one.
2015 – present
Markdown as the format for prose
Markdown, MDX, notebooks
Documentation converged on a format readable as plain text, diffable in version control, and renderable to anything. Its significance grew again with generation models, which both produce and consume it as their default structured-prose form — making a format designed for human convenience into a machine interchange format almost by accident.
2017 – present
Table formats and lineage
Delta Lake, Iceberg, Hudi
Files in object storage gave scale but lost the guarantees a database provided: no transactions, no consistent view during a write, no history. These formats add a metadata layer over Parquet files that tracks which files constitute the table at each version, which restores atomic commits, schema evolution and the ability to query the table as it stood at a past point. Lineage stopped being documentation and became a property of the storage itself.
2021 – present
Weights, tensors and embeddings
safetensors, GGUF, vector indexes
Model checkpoints became a storage class of their own, measured in gigabytes and needing fast partial loading rather than sequential reading. The formats emphasise memory-mapping and, notably, safety: earlier practice serialised Python objects directly, which meant loading a downloaded model could execute arbitrary code. Vector indexes are the same story for embeddings, optimised for similarity lookup rather than for retrieval by key.

What Disappeared

Ended as mainstream practice:
  • XML as the default for new interchange — still everywhere in existing systems, rarely chosen for something new
  • SOAP envelopes — the standard way services talked to each other for about a decade
  • Fixed-width record files — column positions defined in a separate document, and nowhere else
  • Proprietary binary office formats as interchange — sending data as a spreadsheet file and hoping the recipient's version could open it
  • Pickling Python objects to share data — convenient, version-fragile, and able to execute code on load
Alive, but only in niches:
  • XML and XSD — still standard where validation is a contractual requirement: finance, healthcare, publishing, government
  • Fixed-width files — still how a surprising amount of banking and payroll data moves between institutions
  • CSV — not niche at all, listed here for the opposite reason: it should have been replaced many times over and never was, because no successor kept its one advantage of needing nothing installed
