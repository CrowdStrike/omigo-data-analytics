Evolution of Data Analytics Sophistication

From "will it rain tomorrow" to fusing every record an organisation holds — how the questions we could ask of data grew.

Dates are approximate and mark mainstream adoption rather than first release. Bars in red ended as mainstream practice; orange survives in specific niches only.

The Eras

EraWhat changed
2006 onward
Analytics at web scale
MapReduce, Spark, columnar warehouses
Distributed computation removed the requirement to sample. Whole-population analysis became routine, and behavioural questions that needed every event — funnels, cohorts, sessionisation, long-tail segments — became answerable for the first time.
2018 onward
Meaning as geometry, and asking in English
Embeddings, vector search, LLM-generated queries
Text, images and behaviour became dense vectors where proximity approximates similarity, enabling retrieval by meaning rather than keyword. Most recently the query interface itself became natural language, with a model translating a spoken question into SQL — which returns the analyst's difficulty to where it began: knowing whether the answer is right.
Early 1900s – 1950s
Counting by handgone
Ledgers, actuarial tables, census tabulation
Analytics meant totals, averages and mortality tables compiled manually. The questions had to be simple because every additional cross-tabulation cost human labour, so analysis was descriptive and the dimensions were few.
1930s – 1950s
Inference from samples
Hypothesis tests, regression, experimental design
The formal machinery of statistics made it possible to answer "will it rain tomorrow" as a probability rather than a guess, and to state how confident that answer was. This is the foundational layer: sampling, significance, confidence intervals, and the designed experiment. It has not been superseded by anything since.
1950s – 1970s
Optimisation and forecasting
Linear programming, ARIMA, queueing theory
Analytics moved from describing what happened to prescribing what to do — routing, scheduling, inventory levels. Time series methods made systematic forecasting possible, and operations research put analysis directly into operational decisions.
1960s – 2000s
Sequences and probabilistic language
Markov chains, HMMs, n-gram models
Modelling what comes next given what came before. Hidden Markov models drove speech recognition and part-of-speech tagging for decades, and n-gram models were the backbone of machine translation and spelling correction. The key limitation was a short memory: the model conditioned on the last few states only, which is precisely the constraint later neural sequence models removed.
1990s – 2000s
Structured data and the reporting layer
SQL, star schemas, OLAP cubes, data mining
With the relational warehouse in place, analysis became slicing a well-defined schema by dimension — revenue by region by quarter. Data mining added automated pattern discovery on top: association rules, decision trees, clustering. The constraint was that everything had to be forced into rows and columns first.
Mid 2000s
Semi-structured data
JSON, BigTable, HBase, Cassandra, MongoDB
Wide-column and document stores accepted data whose shape was not known in advance. A record could carry nested fields and vary between rows, which suited web logs, user events and sensor feeds. Schema moved from write time to read time, making it possible to store first and decide the structure later.
2010s
Self-serve tools and continuous analysis
Tableau, Looker, Kafka, stream processing
Two parallel shifts: producing a chart stopped requiring a specialist, and analysis stopped waiting for the nightly batch. Streaming engines allowed aggregation over moving windows, so anomaly detection and operational monitoring became continuous rather than retrospective.
2010s onward
Fusing records across sources
Entity resolution, knowledge graphs, integration platforms
The frontier shifted from analysing one dataset to reconciling many. Linking records that refer to the same person or organisation across systems with no shared key — probabilistic matching, graph representations, lineage tracking. Palantir is the well-known example of this category: the product is less a model than an integration and resolution layer that makes heterogeneous sources queryable as one. It is also where the governance questions concentrate, since combining innocuous datasets can reveal what neither contained alone.

What Disappeared

Ended as mainstream practice:
  • Manual tabulation and hand-computed statistics — a profession of human "computers" producing tables by hand
  • Sampling as a technical necessity — still valid methodology, but no longer forced by the cost of processing all the rows
  • Pre-computed OLAP cubes — the standard way to make aggregation fast before columnar scans were cheap
  • Analysis waiting on the nightly batch — for a long stretch, the shortest interval at which any number could change
  • n-gram language models as state of the art — the dominant approach to text for roughly forty years, displaced by neural sequence models
  • The dedicated report-writing team — a queue you filed a request with, dissolved by self-serve tooling
Alive, but only in niches:
  • Markov and hidden Markov models — still used in bioinformatics, some speech pipelines, and wherever interpretable state transitions matter
  • Classical time series methods — ARIMA and exponential smoothing remain competitive on small, regular series and often beat neural forecasters there
  • Association rule mining — survives in retail basket analysis, largely absorbed into recommender systems elsewhere
  • Hand-written SQL — unchanged as the interface to structured data for over thirty years, now increasingly generated rather than typed
