Discord Messages API BACKLOG

Channel messages, threads, reactions, attachments, and embeds — real-time via Gateway WebSocket or historical via REST.

Last verified: August 2026

Authentication & Access

Bot Tokens & Privileged Intents
  • Bot token: created via Developer Portal, grants access to guilds the bot has been invited to
  • MESSAGE_CONTENT intent: required since September 2022 to read message body, attachments, embeds, and components in guild messages
  • Without this intent, bots only see content in DMs, messages that mention the bot, or messages the bot sends
  • Verification required: bots in 100+ servers must be verified and approved by Discord to use privileged intents
OAuth2 (User-Level)
  • OAuth2 authorization code grant for acting on behalf of a user
  • Scopes: messages.read for DM access, guild-specific permissions via bot role
  • User tokens see only what that user can see — respects channel permissions
Gateway vs. REST
  • Gateway (WebSocket): real-time event stream — MESSAGE_CREATE, MESSAGE_UPDATE, MESSAGE_DELETE dispatched as they happen
  • REST API: historical data retrieval — fetch up to 100 messages per request, paginate with before/after snowflake IDs
  • Gateway is push-based (low latency); REST is pull-based (backfill, audit)

Business Scenarios

  • Community analytics: message volume trends, active hours, engagement per channel, top contributors
  • Moderation bots: auto-detect spam, slurs, raid patterns; log deleted messages for audit
  • Customer support: ticket bots in private threads, response-time tracking, escalation routing
  • Event notifications: scheduled announcements, RSVP tracking via reactions, reminder pings
  • Sentiment monitoring: reaction ratios, thread depth as engagement proxy, emoji frequency analysis
MESSAGE_CONTENT intent restriction means analytics bots must be verified before scaling past 100 servers. Without it, message bodies are empty strings — only metadata (author, timestamp, channel) remains visible.
Restrictions & Gotchas
  • Message history fetched 100 at a time — full channel export requires pagination loops
  • Bulk delete only works on messages less than 14 days old
  • Gateway requires maintaining heartbeat or session is invalidated
  • Sharding mandatory for bots in 2,500+ guilds (one shard per ~2,500 guilds)
  • Ephemeral messages (interaction responses) are not stored and cannot be fetched later
  • Thread messages require separate channel ID — not returned in parent channel fetch
  • Snowflake IDs encode timestamp — useful for pagination but not a substitute for timestamp field
