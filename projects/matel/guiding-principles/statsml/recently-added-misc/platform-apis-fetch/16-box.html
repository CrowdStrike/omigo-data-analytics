Box BACKLOG

Files and folders with custom metadata templates, tasks, retention and legal hold, enterprise events, and watermarking

Last verified: August 2026

Overview

What It Provides

Box is a REST API over a content model that is deliberately governance-first. Beyond files, folders, and versions, it exposes structured metadata templates (typed, enterprise-scoped key/value schemas attached to content), tasks and task assignments for review workflows, retention policies and legal holds that override user deletion, an enterprise event stream, and watermarking on preview and download.

The distinguishing feature versus consumer file APIs is that governance objects are first-class and queryable — you can search on metadata field values, not only on names and content.

Authentication & Scopes

  • OAuth 2.0 (3-legged, user-delegated) for apps acting as a person.
  • JWT server authentication for service-account apps. The app gets its own Box account ("Service Account") whose root folder is empty — it sees nothing until content is explicitly shared with it or it impersonates a user.
  • Client Credentials Grant as the newer alternative to JWT for server-to-server.
  • App authorization is admin-gated. A Box admin must authorize the app in the Admin Console before its scopes take effect, and separately grant elevated scopes such as "Manage enterprise properties" (required for events, retention, and legal hold).
  • As-User header lets an app with user-impersonation scope act on another user's behalf without a per-user OAuth flow.
root_readonly root_readwrite manage_webhook manage_managed_users manage_enterprise_properties manage_data_retention manage_legal_hold

Orange badges are elevated scopes: an admin must grant them in the Admin Console before events, retention, or legal hold return anything.

The service account trap. A freshly created JWT app authenticates successfully and then returns an empty folder listing for folder id 0. This is correct behaviour, not a bug — the service account is a distinct Box user. Either impersonate a real user with As-User or collaborate the service account onto the folders it needs.

Granularity

Folder id 0 is always the root. Objects are addressed by opaque numeric-string ids. Field selection via ?fields= is not cosmetic — many fields (metadata, permissions, expires_at, tags) are omitted from the default representation entirely and only appear when explicitly requested. Metadata is scoped: global (with the built-in properties free-form template) and enterprise_<id> for admin-defined templates.

Key Endpoints

  • GET /2.0/folders/{id}/items, GET /2.0/files/{id}
  • GET /2.0/files/{id}/versions, POST /2.0/files/{id}/versions/{vid}/current (promote)
  • GET|POST /2.0/files/{id}/metadata/{scope}/{template}, PUT with JSON-Patch-style ops
  • GET /2.0/metadata_templates/{scope}/{key}/schema
  • POST /2.0/metadata_queries/execute_read — query content by metadata field values
  • GET|POST /2.0/tasks, /2.0/task_assignments
  • GET /2.0/retention_policies, /2.0/file_version_retentions
  • GET /2.0/legal_hold_policies, /2.0/legal_hold_policy_assignments
  • GET /2.0/events — user stream (stream_position) and stream_type=admin_logs / admin_logs_streaming
  • POST /2.0/web_links, PUT /2.0/files/{id}#request_watermark style watermark endpoints under /watermark

Rate Limits

Box applies per-API-key and per-user limits and returns HTTP 429 with a Retry-After header when exceeded; uploads have their own separate ceiling from general API calls. Rather than hard-coding a number, treat Retry-After as authoritative and retry with jitter. Two structural points matter more than the raw ceiling: (1) metadata_queries/execute_read is markedly more expensive than a folder listing and is the usual source of throttling in metadata-driven integrations, and (2) the admin event stream is rate-limited independently of content APIs, so a backfill of audit history will not starve your file operations.

Business Scenarios

  • Regulated-industry document control: contracts, clinical records, loan files
  • Metadata-driven routing — classify on upload, then query by field to feed downstream systems
  • eDiscovery and legal hold orchestration
  • Records-retention automation with defensible deletion evidence
  • Watermarked external review of sensitive documents

Key Restrictions & Gotchas

Version history and the audit log outlive the visible file — by design. A file under a retention policy or legal hold cannot be permanently deleted by its owner; the user sees it vanish, the content is preserved and discoverable. Separately, admin event log retention is plan-tiered: the standard admin_logs window is bounded (roughly the last year for most enterprises), while admin_logs_streaming is a near-real-time tail with only a short lookback. Neither is "forever", and the two windows are not the same.
  • admin_logs_streaming has no created_after/created_before filtering and is explicitly at-least-once — you will see duplicate event_ids and must de-duplicate. Use admin_logs for historical windows and admin_logs_streaming for the live tail; do not try to make one do both.
  • Metadata queries require an ancestor_folder_id and an indexed template field. You cannot query across the whole enterprise without scoping to a folder subtree.
  • Deleting a metadata template deletes its instances. There is no soft-delete for template schemas; the field values attached to thousands of files go with it.
  • Watermarking is a preview/download treatment, not encryption. Applying a watermark does not prevent a collaborator with download permission from obtaining the file; and the watermark is applied at render time, so the stored bytes are unmarked.
  • Tasks are not a workflow engine. The API gives you tasks, assignments, and completion state — no branching, no escalation, no SLA timers. Box Relay is a separate product and is not fully exposed as a public API.
  • No content-level diff between versions. versions gives you a chain with sizes and SHA-1 (sha1 / file_version.sha1); comparing requires downloading both.
  • Trash is a real, addressable state. Items sit in /2.0/folders/trash/items for a configurable enterprise-wide period before purge; a "deleted" file is still enumerable there, and admins can extend or disable auto-purge.
  • etag is the concurrency primitive. Updates without If-Match will happily clobber a concurrent edit.
  • Shared links expose download_count and preview_count only when requested via fields, and only for links your token is permitted to inspect — these are not available for links created by other users.
