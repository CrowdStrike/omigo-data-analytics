Twilio BACKLOG

Messaging and voice CPaaS: Message and Call resources, recordings, status callbacks, Voice Insights, and the Verify OTP service.

Last verified: August 2026

Overview

Twilio exposes a flat, resource-oriented REST API rooted at the account: https://api.twilio.com/2010-04-01/Accounts/{AccountSid}/.... Almost everything analytically interesting is a subresource of an account or of a single Message/Call SID. The API is strong on what Twilio itself did (accepted, queued, priced, recorded) and progressively weaker the further downstream you go — carrier delivery and handset receipt are reported by third parties, or not at all.

What It Provides
  • Messages — per-message record with sid, status, direction, from/to, body, num_segments, num_media, price, price_unit, error_code, error_message, messaging_service_sid, and the date_created / date_sent / date_updated triple.
  • Calls — sid, status, duration, price, direction, from/to, start_time/end_time, and answered_by (populated only when Answering Machine Detection was requested on the call).
  • Recordings — separate resources with their own SIDs, listed under the account or under a specific Call. Media is fetched from a distinct URL; the metadata resource and the audio are not the same thing.
  • Status callbacks — Twilio POSTs form-encoded (not JSON) updates to your StatusCallback URL on status transitions, carrying MessageStatus / CallStatus and, on failure, ErrorCode.
  • Voice Insights — per-call summary plus network-quality metrics (jitter, packet loss, MOS) and SIP/carrier edge detail. Higher-detail Advanced Features are a paid add-on, enabled per account.
  • Verify — a managed OTP service (Verifications and VerificationChecks) covering SMS, voice, email, and TOTP channels.
Authentication & Scopes
Account SID + Auth TokenAPI Key SID + SecretSubaccount SID(no OAuth scope model)
  • HTTP Basic authentication. The crude form is AccountSid as username and AuthToken as password; the preferred form is an API Key SID + Secret, which can be revoked independently without rotating the account credential.
  • There is no OAuth scope model on the classic REST API — a credential that can read messages can generally also send them. Least privilege is achieved structurally, via subaccounts, not via scopes.
  • Subaccounts are the standard tenant-isolation and cost-attribution boundary. Parent credentials can reach into subaccounts; subaccount credentials cannot reach out.
  • Inbound webhooks should be validated using the X-Twilio-Signature header. Without that check, your callback endpoint accepts delivery receipts from anyone.
Granularity
  • Per message and per call — one row per event, with monetary cost attached. This is unusually good for analytics: cost and outcome live on the same record.
  • num_segments is the billing unit for SMS, not the message. A long body or a single non-GSM-7 character silently multiplies segments and cost.
  • price is populated asynchronously and may be null immediately after send. Pulling cost data too early yields systematic undercounting.
  • Voice Insights metrics are per call leg, and quality metrics only exist where Twilio was in the media path.
Key Endpoints
  • GET /2010-04-01/Accounts/{AccountSid}/Messages.json — filterable by To, From, DateSent.
  • GET .../Messages/{MessageSid}.json
  • POST .../Messages.json — send; accepts StatusCallback.
  • GET .../Calls.json and GET .../Calls/{CallSid}.json
  • GET .../Recordings.json, GET .../Calls/{CallSid}/Recordings.json
  • GET .../Messages/{MessageSid}/Media.json — MMS attachments.
  • Verify: POST /v2/Services/{ServiceSid}/Verifications then POST .../VerificationCheck.
  • Voice Insights: per-call Summary and Metrics resources under the Insights base path.
Rate Limits
  • API-level throttling returns HTTP 429 with Twilio error 20429. Retry with exponential backoff; do not retry sends blindly, as a retried POST can double-send.
  • Outbound SMS throughput is a separate concept from API rate limit. It is governed by the sending number type (long code, toll-free, short code), the Messaging Service pool, and carrier-imposed campaign limits — in the US, A2P 10DLC brand and campaign vetting assigns a throughput tier. Twilio queues rather than rejects excess, so oversending shows up as growing latency between date_created and date_sent, not as errors. Treat the effective messages-per-second as a property of your specific number and campaign registration, and measure it rather than assuming a documented constant.
  • List endpoints paginate with PageSize (maximum 1000) and a next_page_uri. Follow next_page_uri verbatim; do not reconstruct page URLs.
Business Scenarios
  • Deliverability analysis by carrier, region, and number type — provided you accept that "not delivered" and "no receipt" are different things.
  • Per-campaign cost reconciliation using price and num_segments against internal send logs.
  • OTP funnel measurement: verification start rate, check success rate, channel fallback rate.
  • Voice quality regression detection using Voice Insights MOS and packet loss by carrier edge.
  • Contact-centre analytics: answer rate, answered_by voicemail detection, abandonment via duration distribution.
sent is not delivered, and delivered is hearsay. sent means the carrier accepted the message. delivered means a carrier returned a delivery receipt. Some carriers and some entire regions never return DLRs, so perfectly received messages remain permanently at sent. Conversely, a few carriers return a positive DLR on accepting the message into their own queue. Any dashboard computing "delivery rate = delivered / total" is measuring carrier reporting behaviour at least as much as actual delivery, and comparing that rate across countries compares two different measurement instruments.
Silent carrier filtering looks like success. A message can be accepted, marked sent, billed, and then dropped by carrier spam filtering with no error surfaced — or surfaced late as undelivered with error 30007. Cost is incurred regardless of outcome, so revenue-per-message-sent and cost-per-message-sent do not share a denominator.
Key Restrictions & Gotchas
  • Status callbacks are not ordered or guaranteed-once. They arrive out of order and can be duplicated. Persist by MessageSid and only advance state monotonically; do not treat callback arrival order as the true transition order.
  • Terminal states are ambiguous. failed means Twilio or the carrier rejected it; undelivered means it was accepted and then reported as not reaching the handset. Collapsing both into "failed" destroys the distinction between your problem and the carrier's.
  • Message bodies are subject to redaction and retention policy. Twilio supports account-level redaction of message bodies and recording media; where enabled, historical body values read back empty. An analytics pipeline that assumes bodies are permanently retrievable will silently lose content on old records.
  • Recording a call has legal consent implications that vary by jurisdiction and by party (one-party vs all-party consent). The API will happily record where the law will not. Consent capture is your responsibility and is not represented in the Recording resource.
  • Voice Insights Advanced Features are gated and paid. Basic call summary is broadly available; the detailed metrics many teams design dashboards around require enabling the add-on, and data is not retroactively backfilled for periods before it was enabled.
  • Verify never returns the OTP code to you. You cannot log it, inspect it, or verify it yourself — only submit a user-supplied code to VerificationCheck. This is deliberate and it means Verify cannot be instrumented the way a self-built OTP flow can.
  • answered_by is empty unless AMD was requested at call creation, and it is a probabilistic classifier, not ground truth. Absence of the field is not evidence a human answered.
  • Timestamps are RFC 2822 strings in the classic API, not ISO 8601, and are UTC. date_sent is null until the carrier handoff occurs.
  • Deleting a Message resource is possible and irreversible, and deleted records vanish from list endpoints — reconciliation totals can shrink retroactively if anyone runs cleanup.
