TikTok BACKLOG

Three separate, non-composing API programmes with three different eligibility gates. Broad public-content access exists exactly once, and it is fenced behind academic vetting.

Last verified: August 2026

Overview

What It Provides

TikTok does not have one API. It has several programmes that do not compose, and which one you qualify for determines the whole design of anything built on top. Who you are decides what you can see.

  • Login Kit + Display API — any approved developer, acting for a consenting user. OAuth grants access to basic profile fields and a list of that user's own videos with per-video counters. Strictly self-scoped.
  • Content Posting API — publishes to the authenticated user's account, either as a direct post or as an upload into their drafts for manual completion, with a content-review step before the post goes live.
  • Research API — vetted academic researchers only. The only route to third-party public content at scale: query public videos by keyword, hashtag, region, date range or username; retrieve public comments; query public user info. Some programme revisions also expose account following/follower and pinned/reposted-video endpoints.
  • Commercial Content / ad-library-style transparency access — a gated route to advertising and commercial-content disclosure data.
  • Business API / Marketing API — advertisers and business accounts. Campaign, ad group, ad and creative performance reporting; audience and creative insights; business-account content metrics.

Authentication & Scopes

  • Display and Content Posting: OAuth 2.0 authorization code flow with PKCE. Access tokens are short-lived and refresh tokens themselves expire, so an integration that goes quiet loses access rather than degrading.
  • Research API: client-credentials against a research-specific token endpoint. No end user is involved — the credential represents an approved research project, not a person.
  • Business / Marketing API: advertiser-account authorization; the token is scoped to accounts you already administer.

Scopes are granted per app after review, and the user consents per scope. Research access is not a scope you can request from an ordinary developer account — it is a separate programme.

Granularity

  • Display API: one row per own-video with lifetime counters. No time series, no traffic sources, no audience breakdown.
  • Research API: one row per public video or comment, carrying create time, region code, hashtag names and engagement counts as of the instant you queried. There is no historical snapshot to re-read.
  • Marketing API: aggregated performance by campaign / ad group / ad / creative, over date ranges, with dimension breakdowns — for your own spend.
  • Growth curves must be built by polling and storing yourself. What you are sampling is a monotonically rising counter that disappears entirely if the content is removed.

Key Capabilities by Programme

  • Display: list own videos, read own profile fields, read own per-video counters.
  • Content Posting: initiate upload, direct post or draft inbox, query publish status.
  • Research: video query, comment retrieval per video, user info lookup, and in some revisions follower/following and pinned/reposted video lists.
  • Commercial Content: query disclosed commercial and advertising content.
  • Business/Marketing: campaign CRUD, reporting with metrics and dimensions, audience and creative insights.

Rate Limits & Pricing

Published figures have been revised more than once, so the mechanism matters more than any number:

  • Per-app / per-client request budgets over a rolling daily window, and separately per-user caps on Display endpoints — so a fan-out across many connected users is bounded per user, not only in aggregate.
  • Research API adds per-query result caps and cursor pagination, so a deep sweep of a large topic is a multi-day stitched job rather than one call.
  • Research queries are date-bounded: a long backfill is many adjacent windows, each with its own cursor.
  • Content Posting rate limits are deliberately low, to discourage bulk automated publishing.
  • The organic programmes are not sold as paid tiers. The Marketing API is free to call; the cost is the ad spend it reports on.

Business Scenarios

  • Creator-consented portfolio analytics — the creator connects their account, so their own numbers are read legitimately.
  • Brand campaign measurement through the Marketing API for accounts you manage.
  • Academic study of public discourse, hashtag prevalence and comment-level sentiment, under the Research programme.
  • Ad transparency research through the commercial-content surface.
  • Publishing and scheduling tools for brand-owned or creator-owned accounts.

Key Restrictions & Gotchas

Everything is approval-gated, and the gates are not interchangeable. App review covers Display and Content Posting; the Research API additionally requires an institutional application. There is no path on which an independent commercial analyst obtains broad public-content access. If a vendor offers broad TikTok content data, the first question is which programme it came from — and if the answer is not the Research API or the commercial-content library, it was scraped, and the buyer inherits that exposure.
  • Research API returns public content only, and deletions vanish. A removed, privated or moderated video simply is not in the result set. The same query re-run later returns a different, survivorship-biased population — and the bias is not random, it is largest exactly where enforcement is most active.
  • Comment retrieval is capped per video, so comment-level analysis is on a truncated head of the thread, not the thread.
  • Region filters reflect account and upload region signals, not verified user location. A region-filtered query filters on the platform's attribution.
  • Data availability windows and field sets have changed between API revisions. A field present in one extract may be absent in another.
  • Sandbox masks scope problems — in development the app works only for accounts explicitly added, so scope gaps surface at launch.
  • "View" has been redefined more than once, and the definition differs from other short-video platforms. A cross-platform or cross-revision view-count ratio compares different underlying events.
Methodological note — the discontinuity is in the access policy, not the phenomenon. TikTok's research access arrived comparatively recently and its terms have been revised. A longitudinal series that spans a programme change, a field-set change or an eligibility change contains a break caused by data availability. Combine that with public-only, deletion-sensitive results and the same query run two years apart is measuring two different populations. Do not read such a break as a real-world shift. Record the API programme, its version, the exact query and the collection date with every extract, and treat any pre/post comparison across a policy change as unidentified unless the field sets are demonstrably identical.
