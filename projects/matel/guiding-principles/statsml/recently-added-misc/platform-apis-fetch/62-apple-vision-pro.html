Apple Vision Pro BACKLOG

visionOS ARKit spatial sensing — scene mesh, planes, hand skeletons, world anchors. Raw gaze is deliberately withheld from applications.

Last verified: August 2026

Overview

What It Provides

visionOS exposes spatial understanding to a running app through ARKitSession and a set of data providers. Each provider streams anchors as the system's perception updates. There is no Apple-hosted service that stores or serves this data — everything below is an on-device, per-session stream.

  • SceneReconstructionProvider — triangle mesh anchors of the surrounding room, added/updated/removed as scanning proceeds
  • PlaneDetectionProvider — horizontal and vertical planes with extent and classification (floor, wall, table, ceiling, window, door)
  • HandTrackingProvider — left/right HandAnchor with a joint skeleton (wrist, per-finger knuckle/intermediate/tip) as transforms in world space
  • WorldTrackingProvider — device pose (head position and orientation) and persistent WorldAnchors that survive across sessions
  • ImageTrackingProvider — pose of pre-registered reference images
  • Environment light estimation — ambient lighting for plausible rendering

Authorization

Providers are gated by coarse-grained authorizations requested on the session, not per-sensor toggles:

.handTracking .worldSensing

.worldSensing covers scene reconstruction, plane detection and image tracking as a group. Camera and microphone follow the standard iOS-style usage-description prompts. The user grants or denies at runtime; a denied authorization means the provider simply never yields anchors.

Granularity

  • Per-frame / per-update anchor deltas, not snapshots — the app consumes an async sequence of add/update/remove events
  • Hand joints are full 6-DoF transforms per joint, with a tracked/untracked flag
  • Mesh anchors are geometry chunks keyed by anchor ID, revised as the room is re-scanned
  • Nothing is timestamped into a queryable historical store; if the app does not persist it, it is gone

The Gaze Boundary

Raw gaze is not exposed to applications. There is no API that returns a gaze vector, fixation, or dwell trace. The system resolves the user's look plus an indirect pinch into an ordinary input event delivered to the app — the app learns what was selected, never the path the eyes took to get there. Hover highlighting is applied by the system out-of-process, so even the pre-selection highlight does not round-trip through app code.

This is a design decision, not an oversight. Gaze is a direct readout of attention and intent: it reveals hesitation, re-reading, avoidance, and interest in things the user never clicked. Making it app-visible would make every application an involuntary attention-measurement instrument. Apple's chosen contract gives the app the outcome and withholds the process.

XR Sensor Data Is OS-Mediated By Design

This generalizes past gaze. Room meshes, plane classifications and hand skeletons are all available to the app on-device and none of them are available as a queryable cloud dataset. The platform's position is that spatial sensing is an interaction substrate, not telemetry. Any spatial-analytics design therefore has to answer a question up front: what does the app itself choose to derive, aggregate and upload? The pipeline is the app developer's to build, and the raw stream never leaves the device unless the developer moves it — with consent, and subject to App Review.

Business Scenarios

  • Room-aware placement and occlusion for spatial applications
  • Hand-gesture interaction and ergonomic reach studies (from app-derived summaries only)
  • Training and guided-procedure apps anchored to real fixtures
  • Retail/industrial spatial fit checks against a scanned mesh

Key Restrictions & Gotchas

  • No gaze API — plan analytics around explicit selections, not attention
  • Most providers require a full immersive space; in the shared space an app gets little or no world sensing
  • No camera-frame or mesh access from the shared space in general — visual privacy is enforced by withholding pixels, not by policy alone
  • No server-side API: nothing to backfill, nothing to re-query, no cross-user dataset
  • Persistent world anchors are per-device and not portable across users
  • Simulator does not reproduce real sensing; sensor-dependent behaviour must be validated on hardware
Methodological note: because collection is app-mediated, a spatial dataset's coverage is a property of the app build that produced it. A change in provider usage or authorization prompt across versions changes what was collected, which shows up in the data as an apparent behavioural shift. Version-stamp every spatial record.

ARKitSession with providers — Swift

import ARKit

let session = ARKitSession()
let sceneRecon = SceneReconstructionProvider()
let planes     = PlaneDetectionProvider(
                    alignments: [.horizontal, .vertical])
let hands      = HandTrackingProvider()
let world      = WorldTrackingProvider()

// Coarse-grained, user-facing authorization
let auth = await session.requestAuthorization(
    for: [.handTracking, .worldSensing])
guard auth[.worldSensing] == .allowed else { return }

try await session.run([sceneRecon, planes, hands, world])

// Anchors arrive as add / update / remove deltas
for await update in hands.anchorUpdates {
    let hand = update.anchor          // HandAnchor
    guard hand.isTracked else { continue }
    let skeleton = hand.handSkeleton  // joint transforms
    let tip = skeleton?.joint(.indexFingerTip)
    // tip?.anchorFromJointTransform  -> 4x4 matrix
    // hand.originFromAnchorTransform -> world placement
}

for await update in sceneRecon.anchorUpdates {
    switch update.event {
    case .added, .updated:
        let mesh = update.anchor.geometry   // triangle mesh
        _ = mesh
    case .removed:
        break
    }
}

// There is no equivalent of:
//   session.gazeProvider          <- does not exist
//   anchor.gazeRay                <- does not exist
// The system converts look + pinch into a normal
// SpatialTapGesture on the targeted entity.
