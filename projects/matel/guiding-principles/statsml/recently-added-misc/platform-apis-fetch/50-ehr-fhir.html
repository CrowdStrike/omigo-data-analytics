EHR / FHIR BACKLOG

HL7 FHIR REST resources over clinical records, authorised via SMART on FHIR, with asynchronous bulk export as the only population-level path.

Last verified: August 2026

Overview

What It Provides

FHIR R4 models clinical data as typed REST resources (JSON). Each health system runs its own server — no central endpoint. Auth is OAuth 2.0 via SMART on FHIR; population-level access requires system/ scopes through SMART Backend Services (institutional approval, not developer sign-up).

FHIR is a spec, not an endpoint. Every site has its own URL, its own enabled resources, and its own extensions. What works at one Epic site may fail at the next.
Core Resources
  • Patient — demographics, identifiers, MRN
  • Observation — labs + vitals (same resource, split by category/code)
  • Condition — diagnoses (billing-influenced, stale problem lists)
  • MedicationRequest — prescriptions written (not drugs taken)
  • Encounter, Procedure, DiagnosticReport, DocumentReference

Terminologies: LOINC (labs/vitals), SNOMED CT (problems), RxNorm (meds), ICD-10-CM (billing dx). Bulk export ($export) produces NDJSON — the only realistic path to cohort-level data.

Data Traps for Analytics
An observation exists because someone ordered a test. Measurement frequency is itself a severity signal — models learn the care process, not the physiology. Missingness is never at random.
  • Time leakage. effectiveDateTime ≠ issued. A lab effective at 22:40 but issued at 03:12 next day — indexing at effective time is target leakage.
  • Same code, different instrument. ICU continuous monitoring and annual-physical vitals share a LOINC code but are different sampling regimes.
  • Codes drift. Same analyte appears under multiple LOINC codes across sites and over time within one site.
  • Prescription ≠ exposure. MedicationRequest means it was ordered, not taken. Adherence is not in the record.
  • Condition codes are billing artifacts. Problem lists go stale; coding follows reimbursement, not clinical truth.
  • Status is load-bearing. preliminary, corrected, entered-in-error are not results. Filter to final.
Access Realities
  • Each health system approves your app separately (BAA, security review, long onboarding)
  • PHI throughout — HIPAA, IRB, de-identification constraints shape pipeline design
  • Supported resources and search params vary by site and EHR version
  • No universal rate limits — vendor and site-specific
What's Missing
  • No continuous waveforms (ECG, telemetry)
  • No medication adherence
  • No consistent social determinants
  • No complete longitudinal record (siloed per health system)
  • No usable clinical notes without NLP
  • No historical coding consistency (version breaks look like clinical trends)

Target leakage: effectiveDateTime is 22:40 on the 18th but issued is 03:12 on the 19th. Indexing at effective time gives the model knowledge clinicians didn't have yet. Dual coding: local code works within one site, LOINC works across sites — neither is reliably present everywhere.
