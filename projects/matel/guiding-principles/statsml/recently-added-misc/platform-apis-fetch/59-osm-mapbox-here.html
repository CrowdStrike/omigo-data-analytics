OpenStreetMap, Mapbox & HERE BACKLOG

Three different bargains for geospatial data: own the whole database with its full edit history, or rent routing, isolines and live traffic per call.

Last verified: August 2026

Overview

What It Provides

OpenStreetMap is the outlier in the entire platform-API landscape covered by this backlog: you can have the whole dataset. Not a paginated window, not a sampled export, not a per-call answer — the complete planet as a file you host yourself.

  • Planet extracts — the full database as .osm.pbf (Protocol Buffer binary) or XML, republished on a regular cadence
  • Regional extracts — continent / country / metro subsets from community mirrors such as Geofabrik, so you rarely need the whole planet
  • Diffs — minutely / hourly / daily replication files to keep a local mirror current without re-downloading
  • Data model — node (point), way (ordered node list: line or area), relation (ordered member list: routes, multipolygons), each carrying free-form key=value tags

Mapbox and HERE sell the opposite bargain: high-quality derived answers over a proprietary road graph, delivered per request, with an SLA — and no way to mirror the graph.

Authentication & Scopes

  • OSM extracts — no authentication. Plain HTTP download. The editing API requires an account, but reading bulk data does not.
  • Overpass API — no key; a shared community service with fair-use expectations rather than a contract
  • Mapbox — access token per request, scoped to public / secret token types, billed per request or per tile load against tiered plans
  • HERE — API key (or OAuth token for some products), tiered plans per service family

Granularity

  • OSM is element-level: every node, way and relation is individually addressable by ID and by version
  • Tags are free-form, so schema is convention, not constraint — the same real-world concept may be tagged several ways
  • Mapbox and HERE expose request-level granularity: one origin/destination pair, one isoline budget, one matrix block. There is no element you can enumerate.

Key Capabilities — Overpass API

Overpass is a read-only query language (Overpass QL) over a continuously updated OSM mirror. It handles the queries a flat extract cannot: select by tag, inside this bounding box or named area, with this geometry, recursing to member nodes. Output as JSON or XML, optionally with element metadata (version, changeset, timestamp, user).

Use Overpass for targeted pulls, not bulk. It is a shared community resource, and a query that would return a country's worth of features is the wrong tool — download the regional extract instead. Treat rate as an etiquette question: back off on failure, cache aggressively, and never build a production hot path that fans out to Overpass per user request.

Key Capabilities — Full Edit History

This is the genuinely distinctive part for research. OSM records not just the current state but every edit that produced it:

  • Changesets — a bundle of edits by one user, with timestamp, comment, editor software and bounding box
  • Per-element version history — every element has a monotonic version; you can retrieve any prior version of any node, way or relation
  • Full-history dumps — the planet including all versions of all elements, so you can reconstruct the map as it stood on any past date offline
Almost no commercial geo API offers this. Mapbox and HERE give you the current graph; ask them what a junction looked like three years ago and there is no endpoint. OSM lets you rebuild the past state exactly, which makes it usable for provenance auditing, for measuring data-quality drift, and for building genuinely retrospective panels rather than as-of-today snapshots pretending to be history.

Licence — a legal constraint, not a technical one

OSM data is licensed under the Open Database Licence (ODbL). In practical terms it carries attribution and share-alike obligations on derived databases: if you build a database substantially from OSM and distribute it, the share-alike term is in scope. Rendered images and analytical results are treated differently from databases, and the boundary between "derived database" and "produced work" is exactly where the interesting cases sit.

This is a legal question, not an engineering one. Whether a particular derived dataset triggers share-alike depends on how it was built and what is being distributed — get counsel before productizing. Nothing here is legal advice. The engineering point that is safe to state: plan the licence question before the pipeline, because retrofitting attribution and share-alike onto a shipped data product is far more expensive than designing for it.

Key Capabilities — Mapbox

  • Directions — routing with profiles (driving, driving-with-traffic, walking, cycling), turn-by-turn steps, geometry
  • Map Matching — snap a noisy GPS trace onto the road network; the workhorse for telematics cleanup
  • Isochrone — the reachable polygon within a time or distance budget from an origin
  • Matrix — travel times / distances between many origins and destinations in one call
  • Geocoding — forward and reverse, with permanent vs. temporary result-storage terms
  • Tiles — vector and raster tiles, styles, plus the client SDKs

Key Capabilities — HERE

  • Routing — multi-modal, truck profiles with vehicle attributes, plus matrix routing and isoline routing
  • Geocoding & Search — forward, reverse, autosuggest, discover
  • Traffic Flow — observed speeds and jam factor on road segments as a first-class product
  • Traffic Incidents — accidents, closures, roadworks as structured records with location and validity window

Live traffic is where the commercial providers are genuinely irreplaceable. OSM has no traffic layer at all — it describes the road, not the state of the road.

Rate Limits & Pricing

Described qualitatively on purpose. Mapbox bills per API request and per tile load against a monthly free allowance and then tiered rates; some endpoints have distinct per-minute request ceilings and per-call size caps (number of coordinates, matrix dimensions). HERE prices per transaction against tiered plans, with different products metered separately. Both change their published figures; verify against current pricing pages rather than trusting a number copied into a doc.

Access-policy changes create false time-series structure. A tier change, a per-call coordinate cap, or a matrix-size limit that tightens mid-study changes how much you sampled, not what the world did. If a geospatial panel shows a step change at a date, check the billing and quota history before writing an explanation about traffic or urban form.

Business Scenarios

  • Catchment / accessibility analysis from isochrones (retail siting, service coverage)
  • Fleet and delivery routing with truck attributes and live traffic
  • Map-matching telematics traces before any speed or harsh-braking metric is computed
  • POI-density and infrastructure studies from OSM extracts
  • Data-quality and provenance auditing using OSM full history

Key Restrictions & Gotchas

  • OSM has no SLA, no uptime guarantee, and no traffic layer — it is a volunteer database, not a vendor
  • OSM tag schemas are conventions; expect synonyms, regional dialects and abandoned tagging schemes in the same extract
  • Overpass is not a bulk-extraction tool and not a production dependency
  • Geocoding results from commercial providers usually carry storage restrictions — check whether you are allowed to persist the coordinates you got back
  • Mapbox and HERE road graphs cannot be mirrored; you rent the answer, and the answer can change silently between versions
  • Matrix and isoline endpoints have per-call size caps that force you to tile large problems, which changes cost and latency structure

Methodological caution: OSM counts measure mappers

A count of OSM features is partly a measure of mapper activity, not of the world. Coverage and tag completeness are hugely uneven by geography and by tag: contributor density correlates with urbanity, with local community strength, and with one-off mapping campaigns (humanitarian activations, corporate import projects, university courses). A city with twice the mapped cafés may simply have twice the mappers.

Consequences for any analysis built on OSM feature counts:

  • Never read raw feature counts as ground-truth prevalence. They are prevalence multiplied by an unknown, spatially autocorrelated observation probability.
  • Cross-region comparisons need a completeness proxy or an internal ratio that shares the same observation bias in numerator and denominator.
  • Time series of feature counts contain campaign spikes. An import that lands ten thousand buildings in one changeset is a data event, not an urban event — and the full history is exactly what lets you find it and exclude it.
  • Tag completeness varies independently of geometry completeness: a building may exist with no building:levels, a road with no maxspeed. Missing tags are not zeros.
