Overview

API Surface

GitHub exposes two primary API interfaces:

  • REST API (v3) — resource-based endpoints returning JSON. Stable, well-documented, paginated.
  • GraphQL API (v4) — single endpoint, request exactly the fields you need. Avoids over-fetching that plagues REST for complex queries.

Both cover the same underlying data: repositories, commits, branches, issues, pull requests, reviews, comments, releases, packages, actions workflows, and user/org metadata.

Authentication
  • Fine-grained PATs — scoped to specific repos and permissions. Preferred for personal automation.
  • OAuth Apps — user-authorized access for third-party integrations.
  • GitHub Apps — installed on orgs/repos, act as their own identity. Best for CI/CD and bots.
Rate Limits
  • Unauthenticated: 60 requests/hour
  • Authenticated (PAT/OAuth): 5,000 requests/hour
  • GitHub App installations: 5,000 requests/hour (higher for some endpoints)
  • GraphQL: 5,000 points/hour (query complexity scoring)
Generous free tier — even private repos get full API access. No paid plan required for automation unless you exceed rate limits or need GHES features.

Business Scenarios

Common Integration Patterns
  • CI/CD Integration — trigger workflows on push/PR events, report build status back via commit status API.
  • Code Review Automation — bots that comment on PRs with lint results, test coverage, security scan findings.
  • Project Management — sync issues with external trackers, auto-label based on file paths, manage milestones programmatically.
  • Release Automation — create releases, upload assets, generate changelogs from merged PRs.
  • Compliance & Audit — track who committed what, enforce branch protection, verify signed commits.
Restrictions & Gotchas
  • Secondary rate limits — even within 5,000/hr, rapid concurrent requests can trigger abuse detection (HTTP 403 with retry-after header).
  • Abuse detection — creating content too fast (issues, comments, repos) triggers throttling independent of the primary rate limit.
  • Search API — separate limit of 30 requests/minute. Designed for interactive use, not bulk extraction.
  • Pagination — max 100 items per page. Large repos with thousands of commits require many sequential requests.
The gap between the primary rate limit (5,000/hr) and the secondary abuse limits means naive parallel scripts often fail despite being well under budget. Serial with backoff is more reliable than concurrent for bulk operations.
REST vs GraphQL — When to Use Which
Scenario Preferred
Single resource CRUD REST
Fetch nested data (PR + reviews + comments) GraphQL
Webhooks / event-driven REST (webhooks deliver REST payloads)
Minimize API calls GraphQL
Simple scripts / curl REST
