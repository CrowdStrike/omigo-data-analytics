ServiceNow Table API Backlog

Incidents, changes, CMDB configuration items and field-level audit history — one generic REST interface over every table in the instance.

Last verified: August 2026

Overview

What It Provides

ServiceNow does not publish a per-domain API. It publishes one generic interface — /api/now/table/{tableName} — and every module is just a table underneath. Learn the pattern once and every application is reachable.

  • ITSM records — incident, problem, change_request, change_task, sc_request, sc_req_item, sc_task.
  • CMDB — cmdb_ci and its descendants (cmdb_ci_server, cmdb_ci_service, cmdb_ci_db_instance, …) plus the relationship table cmdb_rel_ci that turns them into a graph.
  • History and audit — sys_audit (field-level before/after), sys_history_line / sys_journal_field (work notes and comments), sys_email, sys_update_xml.
  • Process metrics — task_sla (SLA attainment per record), metric_instance (duration a record spent in a given field value — ServiceNow's own time-in-state store).
  • Reference data — sys_user, sys_user_group, cmn_department, sys_choice for the label behind every numeric code.
Authentication & Access
  • Basic auth over HTTPS against a dedicated integration user. Simple and very common; the account should be non-interactive and least-privileged.
  • OAuth 2.0 — register an Application Registry entry; supports authorization-code and client-credentials style flows depending on release and configuration.
  • Mutual TLS is available on instances configured for it.
  • Authorisation is not scope strings. It is the platform's own model: assigned roles, table-level ACLs, and field-level ACLs. Relevant roles and plugins:
rest_service web_service_admin itil itil_admin catalog asset cmdb_read personalize_choices snc_read_only
Field-level ACLs silently blank fields rather than failing. If the integration user lacks read access to a field, the response contains the field with an empty value — indistinguishable from a genuinely empty field. Diagnose permissions by comparing an admin read against the integration user's read, not by looking for error codes.
Granularity
  • One record per row. Every row carries sys_id, sys_created_on, sys_created_by, sys_updated_on, sys_updated_by, sys_mod_count.
  • Reference fields return either a link+value object (default) or a flat string, controlled by sysparm_display_value and sysparm_exclude_reference_link.
  • sys_audit is one row per field change: documentkey, fieldname, oldvalue, newvalue, user, sys_created_on. This is the finest grain the platform offers.
  • metric_instance is one row per interval a record spent at a given value of a monitored field — pre-computed time-in-state, if the metric definition was switched on before the period you care about.
Key Endpoints
  • GET /api/now/table/incident?sysparm_query=…&sysparm_fields=…&sysparm_limit=…&sysparm_offset=…
  • GET /api/now/table/sys_audit?sysparm_query=tablename=incident^sys_created_on>=javascript:gs.dateGenerate('2026-08-01','00:00:00')
  • GET /api/now/table/cmdb_rel_ci — parent/child/type triples; walk these to rebuild the dependency graph.
  • GET /api/now/cmdb/instance/{classname} — CMDB Instance API, which respects class inheritance and relationship rules better than a raw table read.
  • GET /api/now/attachment — attachment metadata and binaries, separate from the parent record.
  • GET /api/now/stats/{tableName}?sysparm_count=true&sysparm_group_by=… — Aggregate API, for counts and sums without pulling rows.
  • Import Set and Scripted REST APIs — instance-specific endpoints under /api/{scope}/… that vary per customer; never assume they exist.
Rate Limits
  • Limits are configured by the instance administrator, not fixed by the vendor: inbound REST rate-limit rules per user, per role, or per API, plus a semaphore pool that caps concurrent transactions. There is no universal figure to quote.
  • The binding constraint is usually not a rule but instance capacity: a wide unindexed sysparm_query against a large table can exceed the transaction cancel threshold and be killed server-side, degrading the instance for interactive users at the same time.
  • Always send sysparm_fields. Default reads return every column on the table, which on incident in a mature instance is a very wide row.
Business Scenarios
  • MTTR and reopen-rate analysis — resolution durations from incident, reopen events from sys_audit on state.
  • Change-failure correlation — join change_request windows to incidents opened shortly afterwards on the same CI.
  • Blast-radius estimation — traverse cmdb_rel_ci from a failing CI to dependent business services.
  • SLA attainment — task_sla rather than recomputing from timestamps, which misses pause/schedule rules.
  • Assignment-group churn — how many groups a ticket passed through before resolution, from audit rows on assignment_group.
  • Configuration drift and compliance — CMDB attribute changes over time from audit rows.
Restrictions & Gotchas
  • Auditing is per-field opt-in. A column has history only if audit was enabled on its dictionary entry, and only from the moment it was enabled. An empty sys_audit result means "not audited or not changed" — the API cannot tell you which.
  • sys_audit is pruned. Instances run cleanup jobs against audit and history tables on a retention policy chosen locally. Old history may simply not be there, and the horizon differs per instance.
  • Display values versus raw values are a constant trap. sysparm_display_value=true returns localised, formatted strings — dates in the user's format and timezone, choices as labels. false returns UTC-ish raw values and sys_ids. Mixing the two across runs corrupts a time series. Pick all if you want both, and store which one you used.
  • Offset pagination on a live table skips and duplicates rows. New inserts shift the window between pages. Page by an ordered immutable key (sys_id or sys_created_on with a tie-break) instead of trusting sysparm_offset.
  • Business rules can fire on your writes. Table API POST/PUT executes business rules, workflows and notifications unless suppressed — a bulk load can email thousands of people. Reads are safe; writes are not inert.
  • Table inheritance hides rows. Reading cmdb_ci returns rows of every descendant class with only the base columns; reading a child class returns extended columns but not siblings. Neither read alone is "the CMDB".
  • Numeric states are instance-specific. state=6 is not universally "Resolved" — customers redefine choices. Resolve labels through sys_choice for that table and element.
  • Personal data and work notes. sys_journal_field holds free-text work notes that frequently contain customer identifiers and credentials. This is the one place the platform does hold user-authored content, and it needs handling accordingly.
With the exception of journal fields and attachments, this is metadata about work, not the work itself. An incident record tells you a P1 was raised, routed twice and closed in four hours; it does not tell you what was broken or what fixed it. Root-cause text lives in the free-text fields, which are unstructured, inconsistently filled, and the least reliable column on the table.
