Pages, databases, blocks, and comments — structured content as composable block trees

Last verified: August 2026

Overview

Content as Block Trees

Every Notion page is a tree of typed blocks. Supported block types include:

  • Text: paragraph, heading_1, heading_2, heading_3
  • Lists: bulleted_list_item, numbered_list_item, to_do
  • Rich: toggle, code, image, callout
  • Structure: divider, table, column_list

Blocks can nest arbitrarily deep — a toggle can contain paragraphs, which can contain other toggles.

Integration-scoped access: An integration can only access pages and databases explicitly shared with it. There is no global workspace access — every resource must be individually shared by a user.
Integration Types
  • Internal integrations: Created within a workspace, automatically trusted. Ideal for internal tools and automations.
  • Public OAuth integrations: Use OAuth 2.0 flow to request access from users across workspaces. Required for third-party apps.
Rate Limits & Pagination
  • Rate limit: 3 requests/sec average per integration
  • Pagination: max 100 results per page (use start_cursor for next page)
  • Block children: limited to 100 per request
Business Scenarios
  • Knowledge base sync (CMS to Notion or vice versa)
  • Project management integration (sync tasks, status updates)
  • Content publishing pipelines (draft in Notion, publish externally)
Restrictions: No real-time updates — polling required. Block children limited to 100 per request. Nested blocks require separate API calls to retrieve children.
