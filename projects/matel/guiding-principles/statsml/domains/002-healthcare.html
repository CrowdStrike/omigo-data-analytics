Healthcare Domain: Data Pitfalls

EHR data is generated by care delivery, not research protocols — informative missingness, coding noise, and time biases distort every naive analysis.

Missing Data Means Healthy (Informative Missingness)

Missing Data Means Healthy (Informative Missingness)
  • Lab tests are ordered when clinicians suspect illness, creating selection bias in observed values
  • Patients with missing lab values are systematically healthier than those with recorded values
  • Imputing missing values with population means or medians biases toward sicker patients
  • EHR data is generated by care delivery, not research protocols - missingness is never random
  • A "normal" creatinine in the database is still from someone sick enough to be tested
Example: In a hospital database, average recorded blood glucose is 142 mg/dL. But this only includes patients whose doctors ordered the test. The true population average is ~100 mg/dL. Building a diabetes risk model on observed-only data dramatically overestimates baseline risk.

Sub-Population Reference Ranges

Sub-Population Reference Ranges
  • Normal lab ranges vary significantly by age, sex, ethnicity, and altitude of residence
  • A single "normal range" misclassifies healthy individuals from different demographics
  • Hemoglobin: males 13.5-17.5, females 12.0-16.0, high-altitude residents +1-2 g/dL
  • Creatinine "normal" for a muscular 25-year-old male is "abnormal" for an 80-year-old female
  • Pediatric ranges differ dramatically from adult ranges and change with development
Example: An ML model flags 40% of healthy African American patients as having abnormal eGFR because it uses a single reference range. Race-adjusted formulas (now controversial) were introduced to address this but created their own biases in kidney transplant eligibility.

Immortal Time Bias

Immortal Time Bias
  • Time between cohort entry and treatment start is "immortal" - patient must survive to receive treatment
  • Attributing immortal time to the treatment group artificially inflates survival estimates
  • Common in observational studies of drug effectiveness from EHR data
  • Can create apparent 30-50% survival benefits that are entirely artifactual
  • Landmark analysis or time-varying covariates are proper fixes
Example: A study finds statin users have 45% lower cancer mortality. But "statin user" is defined as anyone who filled a prescription during follow-up. Patients had to survive long enough to get the prescription - the immortal time is misclassified as "protected" time.

Diagnosis Code Noise (ICD Coding Errors)

Diagnosis Code Noise (ICD Coding Errors)
  • ICD-10 has 72,000+ codes; coders choose under time pressure with incomplete information
  • Same condition can map to multiple codes (e.g., diabetes has 100+ ICD-10 codes)
  • Estimated 15-30% of diagnosis codes have meaningful errors or imprecision
  • "Rule-out" diagnoses are often coded the same as confirmed diagnoses
  • Coding practices vary by institution, payer, and financial incentives (upcoding)
Example: A sepsis prediction model trained at Hospital A (which codes aggressively for billing) shows 60% higher sepsis prevalence than Hospital B. The difference is not in patient populations but in coding practices. The model fails catastrophically when deployed at Hospital B.

Small n, Many Features (p >> n)

Small n, Many Features (p >> n)
  • Genomics/proteomics studies: 50-200 patients, 20,000+ features per patient
  • Any ML model can achieve perfect training accuracy by memorizing - overfitting is guaranteed
  • Standard cross-validation still overfits when feature selection is done before splitting
  • Published gene signatures rarely replicate: ~85% fail independent validation
  • Multiple testing correction (Bonferroni) is too conservative; FDR methods essential
Example: A cancer genomics study with 50 patients and 20,000 genes reports a 30-gene signature with 95% accuracy (CV). An independent lab with 200 new patients finds accuracy is 52% - no better than a coin flip. The original result was pure overfitting.

Lead Time Bias

Lead Time Bias
  • Earlier detection appears to improve survival even if treatment has zero effect on death date
  • Screening programs can show "improved survival" purely through earlier diagnosis
  • 5-year survival rates are systematically misleading for cancers detected by screening
  • Only mortality rate (deaths per population) avoids lead time bias; survival time does not
  • Overdiagnosis compounds the problem: finding "cancers" that would never cause symptoms
Example: Prostate cancer screening shows "5-year survival" went from 70% to 99% after PSA testing was introduced. But overall mortality barely changed. Men were simply diagnosed 8 years earlier on average, making them appear to "survive longer" while dying on the same date.
