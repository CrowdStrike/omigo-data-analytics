Endpoint Security Pitfalls

1. Fileless Malware
Lives only in memory with no file to scan. Abuses PowerShell, WMI, and other scripting engines. Traditional file-hash-based detection is completely blind to these attacks. The malware leaves no artifacts on disk, so signature scanners find nothing. Security must analyze behavior (memory patterns, API calls, script execution) rather than file artifacts.
2. Living-off-the-Land Binaries (LOLBins)
Attackers use legitimate Windows tools: certutil, mshta, regsvr32, rundll32. These same binaries are used by IT admins daily for legitimate administration. What makes usage "malicious" is context, not the binary itself. One person's admin task is another's attack vector. Blocking the binary blocks legitimate work; allowing it enables attacks.
3. Process Tree Context Required
cmd.exe alone is normal. cmd.exe spawned by Word.exe is suspicious. cmd.exe spawned by Word.exe spawned by Outlook.exe receiving an email attachment is VERY suspicious. Security requires the full process ancestry tree, not just a single process in isolation. Without parent-child context, every process looks benign individually.
4. Signature Delay
New malware appears in the wild. AV vendor obtains a sample, analyzes it, creates a signature, tests it, and pushes the update. This cycle takes 4-72 hours. During that entire window there is zero protection from signature-based detection. The gap between "in the wild" and "detected" is precisely when the most damage occurs.
5. Per-Machine Behavioral Baseline
A developer machine regularly runs compilers, debuggers, and scripts — all normal activity. An accountant machine running those same tools is highly suspicious. A single behavioral model applied uniformly to all endpoints produces either massive false positives on developer machines OR missed attacks on non-developer endpoints. Each role needs its own baseline.
6. Kernel/Ring-0 Rootkit Blindness
If malware compromises the kernel, it controls what the EDR agent CAN SEE. The agent runs in user-space (Ring 3) while the rootkit operates at Ring 0. The agent reports "all clear" because the rootkit hides processes, files, and network connections from it. You cannot trust a sensor that runs inside the compromised system it is supposed to monitor.
