Email/Spam Detection Pitfalls

Why spam filtering is an adversarial, label-noisy, non-stationary classification problem.

Adversarial Text Evolution

Adversarial Text Evolution
Spammers constantly evolve: Unicode lookalikes, zero-width characters, image-only emails, HTML tricks. A model trained last month is already partially evaded. The adversary adapts faster than retraining cycles allow.

Legitimate Marketing ≈ Spam

Legitimate Marketing ≈ Spam
Promotional newsletters from opted-in services: technically not spam but users report them. "Buy now" language identical to spam. The boundary is subjective and user-dependent — one person's wanted coupon is another's junk.

User Report Bias

User Report Bias
Some users report EVERYTHING as spam including legit receipts. Some never report anything. "Reported as spam" label is noisy, inconsistent, and lazy. Training on these labels inherits all that human variance.

Ham Corpus Decay

Ham Corpus Decay
Your "good email" training set ages. Email patterns change — new services, new formats, new platforms. 2020 ham doesn't represent 2024 ham. Models trained on stale legitimate email misclassify new legitimate patterns.

Phishing vs Spam: Different Problems

Phishing vs Spam: Different Problems
Spam = annoying but harmless. Phishing = credential theft = catastrophic. Same inbox, vastly different false-negative costs. One model with a uniform threshold can't serve both — missing phishing is 100x worse than missing spam.

Sender Reputation Gaming

Sender Reputation Gaming
New domain → no history → clean reputation → send spam for 2 weeks → domain burned → spin up new domain. Reputation systems have a bootstrapping vulnerability — trust-by-default is exploitable.
