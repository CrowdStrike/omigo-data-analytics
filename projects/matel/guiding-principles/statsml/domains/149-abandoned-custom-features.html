Abandoned Custom Features Polluting Pipelines

Short-term research projects add custom tracking and features. The project ends or the feature doesn't launch. The instrumentation stays — consuming compute, adding latency, polluting schemas, confusing future engineers. Nobody removes it because nobody owns it.

The core problem: Adding a feature to a pipeline takes 1 day. Removing it requires: understanding all downstream dependencies, confirming nothing else uses it, getting approval from the pipeline owner, and accepting risk that removal breaks something silently. The asymmetry (easy to add, hard to remove) means features accumulate monotonically. After 3 years: 40% of pipeline compute serves dead features.

The "Temporary" Addition That Becomes Permanent

Added for Q3 Research → Still Running 2 Years Later
  • The pattern: "I need scroll-depth tracking for my personalization experiment." Added in 2 days. Experiment concluded: scroll depth isn't predictive. But the event still fires on every page load, 50M times/day, stored forever.
  • Why nobody removes it: The person who added it moved teams. New pipeline owner sees the event, doesn't know its history. "Maybe something depends on it." Leaves it. Safe choice — but expensive long-term.
  • The compound effect: 10 researchers/year × 3 custom features each × 3 years = 90 abandoned features. Combined: 5 hours of daily compute, 200GB/day storage, 40ms added latency from dead instrumentation.

Schema Pollution — Dead Columns That Confuse Everyone

200 Columns in the Feature Store. 80 Are From Dead Projects.
  • The confusion: New hire sees `exp_q3_2024_scroll_v2`, `tmp_user_affinity_test`, `model_candidate_b_score`. Are these active? Deprecated? Safe to use? No documentation. Creator gone.
  • The accidental usage: AutoML picks up a dead feature (it happens to correlate with the target because it was computed from related data). Model trains on it. Feature stops updating 6 months later (compute was finally decommissioned). Model silently degrades because a key input went stale.
  • The cleanup cost: To safely remove 1 dead column: trace all downstream consumers (dashboards, models, reports, exports). Confirm zero dependencies. This takes 2-4 hours PER COLUMN. 80 dead columns = 160-320 hours of cleanup. Nobody has that bandwidth, so it never happens.

Latency and Cost Creep — Death by a Thousand Cuts

Each Addition Is Small. Together They're Crippling.
  • Per-feature cost: 2ms latency, 10min compute/day, 5GB storage/day, $30/month. Negligible individually.
  • 50 abandoned features: 100ms latency (user-noticeable), 8 hours compute/day (entire cluster capacity), 250GB storage/day ($170/month), $1,500/month total. Significant.
  • The invisible tax: Pipeline takes 12 hours to run. Stakeholders complain it's slow. 40% of that time is computing features nobody reads. But nobody knows WHICH 40% — so you can't speed it up without auditing everything.
  • The irony: Team requests more compute budget because "the pipeline is too slow." Gets approved. Real fix: remove dead features. But that requires effort nobody is incentivized to do (no one gets promoted for deleting code).
