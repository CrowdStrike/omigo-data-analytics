Silent Bugs Poisoning Data

Pipeline bugs that corrupt values without triggering alerts — row counts match, schemas validate, but the numbers are wrong. Models train on poison and dashboards report fiction.

The core problem: Most validation checks structural correctness (schema, nulls, types, counts), not semantic correctness. A bug producing wrong-but-plausible values passes every check and poisons everything downstream silently.

JOIN Fanout — Silent Row Multiplication

One-to-Many JOIN Silently Duplicates Revenue
  • The bug: JOINing orders to items repeats each order's total once per item, so SUM(order_total) counts every order N times.
  • Why it's silent: Row counts grow, no nulls appear, and inflated revenue looks like good news — no alert fires.
  • Discovery timeline: Weeks to months, usually when a human notices revenue can't be 4× last quarter or annual finance reconciliation disagrees.
  • Blast radius: Every downstream model, forecast, budget, and headcount plan built on the inflated number.

Timezone/Encoding Bugs — Correct Structure, Wrong Values

Every Row Looks Valid. Every Value Is Shifted.
  • Timezone shift: A server migration flips PST to UTC, shifting every timestamp +8 hours — all values valid, all time-of-day features poisoned.
  • Encoding flip: A Latin-1 to UTF-8 change makes "José" ≠ "José" at the byte level, silently breaking string matching and dedup.
  • Null representation change: Upstream sends empty strings instead of NULL, so IS NOT NULL filters admit garbage and averages dilute toward zero.
  • Silent type coercion: An INT-to-FLOAT change makes join keys "100" ≠ "100.0", silently dropping rows — a 30% revenue shrink reads as "normal variance."

Stale Cache / Snapshot — Data Stops Updating but Looks Current

The Pipeline Ran Successfully. It Just Read Yesterday's Data.
  • The bug: A materialized view refresh fails silently, so the ETL "succeeds" on yesterday's data and the dashboard shows stale numbers.
  • The cache variant: An expired cache falls back to last-known values, freezing features like user_last_login so the model sees everyone as inactive.
  • The snapshot variant: A hardcoded path re-reads last month's export, so the model "retrains" on identical data and looks stable while actually frozen.
  • Discovery: Usually a human noticing "this number hasn't changed in 3 days" — automated checks pass because data exists with the right shape.

Upstream Schema Change — Silent Semantic Shift

Column Name Didn't Change. Meaning Did.
  • The classic: A new enum value like 'add_to_cart' falls outside your event_type filter, silently dropping a funnel step and faking a conversion drop.
  • The reuse: Upstream reuses deprecated status=7 for enterprise leads, so your "exclude expired trials" filter now excludes enterprise deals.
  • The backfill: An upstream backfill leaves two formula versions in your processed history, and models learn the discontinuity as a "pattern."
  • The default change: A default change from 0 to NULL shrinks AVG's denominator — the metric "improves 40%" with nothing real happening.

Partial Failure — Some Rows Poisoned, Most Fine

99% of Data Is Correct. The 1% Corrupts Downstream.
  • Race condition: Reading a table mid-write leaves ~2% of rows with mixed-vintage columns — all types valid, revenue wrong for those orders.
  • Sparse corruption: A -999 sensor sentinel treated as a real reading drags averages down and teaches the model an impossible temperature.
  • Silent truncation: VARCHAR(50) silently clips longer values, mangling URLs, product names, and addresses in ~1% of rows.
