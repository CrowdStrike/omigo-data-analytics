3. Splunk SPL

Pipe-based, time-ordered — narrow a stream stage by stage
SQL assumes you are combining tables. Log analysis assumes you are narrowing a stream. Each stage takes previous output and reduces it further — search, filter, transform, present.
What It Is Search Processing Language — Splunk's proprietary query language for searching, filtering, transforming, and visualizing machine-generated data (logs, events, metrics).
Core Idea Pipeline of commands chained with pipes: search | where | stats | eval | sort. Time is a first-class citizen. Schema-on-read means fields are extracted at query time, not ingestion time.
Strengths Intuitive for log exploration — each pipe stage narrows results visibly. Time-bucketing built in (earliest, latest, span). Field extraction at search time (no upfront schema). Interactive drill-down in the UI. Strong ecosystem of apps and add-ons.
Weaknesses No real joins — only lookup tables (static enrichment). Limited aggregation flexibility compared to SQL. Expensive at scale (license by daily ingestion volume). Proprietary — no portability. Performance degrades on non-indexed fields.
Business Use Case Security operations (SIEM — detecting threats, correlating alerts), IT operations monitoring, application log analysis, compliance auditing, incident investigation and root cause analysis.
Example 
index=web sourcetype=access_combined status=5*
| stats count by status, uri_path
| where count > 100
| sort -count
| head 20
