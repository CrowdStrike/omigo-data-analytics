4. Kusto KQL

Azure's pipe-forward language for telemetry at scale
Tabular operators chained left-to-right. Like SPL but with stronger typing and a more formal grammar. Designed for massive telemetry ingestion where schema-on-write enables faster queries.
What It Is Kusto Query Language — a read-only, pipe-forward query language used in Azure Data Explorer, Azure Monitor, Microsoft Sentinel, and Application Insights.
Core Idea Pipe-forward tabular operators: source | where | summarize | extend | render. Strong typing and schema-on-write. Each operator takes a table in, produces a table out.
Strengths Readable left-to-right flow (no nested subqueries). Built-in time-series functions (make-series, series_decompose). Scales to petabytes. Integrated across the Azure ecosystem. Rich rendering hints for visualization.
Weaknesses Azure-locked — not available outside Microsoft ecosystem. Smaller community than SQL. Learning curve for SQL users (different keyword ordering). Limited join semantics (innerunique default surprises people). No write/update operations.
Business Use Case Azure Monitor logs, Application Insights telemetry, Microsoft Sentinel (cloud SIEM), IoT telemetry analysis, game telemetry, large-scale operational monitoring.
Example 
requests
| where timestamp > ago(1h)
| where success == false
| summarize failed_count = count() by bin(timestamp, 5m), operation_name
| where failed_count > 50
| order by failed_count desc
