12. NL to Generated SQL

Plain language as input — it still compiles to SQL, not a new language
Natural language is an input to the pipeline, not a new link in it. It resolves by being translated into SQL and executed normally. The failure mode is not a syntax error — the query runs cleanly and answers a different question than the one asked.
What It Is A pattern where a Large Language Model translates a natural language question into a SQL query, which then executes against a database. The LLM acts as a compiler from ambiguous intent to precise structured query.
Core Idea LLM translates natural language question into SQL, which executes against a database. The output is still SQL — natural language is just a new front-end to the same execution engine. The hard problem is semantic correctness, not syntax.
Strengths Zero SQL knowledge needed for the asker. Fast exploration and iteration. Democratizes data access across the organization. Good for simple, common query patterns. Reduces bottleneck on data teams for routine questions.
Weaknesses Wrong queries run silently — no syntax error when semantics are wrong. Schema context limits accuracy (LLM must know table/column meanings). Hard to validate results without SQL knowledge. Hallucinated column or table names. Ambiguous questions produce confident but arbitrary interpretations. Fails on complex joins and business logic.
Business Use Case Business user self-service analytics, data exploration for non-technical stakeholders, chat-with-your-data products, rapid prototyping of queries, reducing data team ticket load for simple questions.
Example 
-- User asks: "How many users signed up last month?"

-- Generated SQL (looks correct):
SELECT COUNT(*) FROM users
WHERE created_at >= '2024-02-01'
  AND created_at < '2024-03-01';
-- Result: 3,847 ✓

-- User asks: "What's our conversion rate?"

-- Generated SQL (subtly wrong):
SELECT
    COUNT(CASE WHEN purchased = true THEN 1 END) * 100.0
    / COUNT(*) AS conversion_rate
FROM users;
-- Result: 4.2%

-- Problem: includes ALL users ever created, not just
-- those in the conversion window. The real rate for
-- recent cohorts is 11.3%. Query ran cleanly.
-- No error. Wrong answer. Confident delivery.
