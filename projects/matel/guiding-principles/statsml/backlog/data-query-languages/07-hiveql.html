8. HiveQL

SQL-like grammar over MapReduce — brought SQL users back to Hadoop
Don't force SQL users to learn MapReduce. Give them familiar grammar, compile it to distributed jobs underneath. The retraining cost of a new language is the real barrier to adoption — not technical limitations.
What It Is A SQL-like query language for Apache Hive that compiles queries into MapReduce (later Tez/Spark) jobs executing over data stored in HDFS. Developed at Facebook (2009) to make Hadoop accessible to analysts.
Core Idea SQL syntax compiled to MapReduce/Tez jobs on HDFS data. Schema-on-read — data is stored as files, schema is applied at query time via a metastore. Familiar grammar eliminates retraining.
Strengths Familiar SQL syntax for analysts who refused to write Java. Schema-on-read flexibility. UDFs for custom logic. Partitioning and bucketing for performance. Works on massive HDFS datasets (petabyte scale). Hive Metastore became a shared catalog.
Weaknesses High latency — batch-oriented, minutes for simple queries. Limited SQL compliance (no UPDATE/DELETE originally). No real-time or interactive queries. Hive Metastore adds operational complexity. Query optimization was primitive initially.
Business Use Case Data warehouse queries on Hadoop clusters, batch reporting, ETL in the Hadoop ecosystem, ad-hoc analysis by SQL-trained analysts who needed access to HDFS data without writing MapReduce.
Example 
-- Partitioned table for efficient time-range queries
CREATE EXTERNAL TABLE web_events (
    user_id STRING,
    event_type STRING,
    page_url STRING,
    duration_sec INT
)
PARTITIONED BY (dt STRING, hour INT)
STORED AS PARQUET
LOCATION '/data/warehouse/web_events';

-- Query with partition pruning
SELECT event_type, COUNT(*) as event_count,
       AVG(duration_sec) as avg_duration
FROM web_events
WHERE dt = '2024-03-15' AND hour BETWEEN 9 AND 17
GROUP BY event_type
HAVING COUNT(*) > 1000
ORDER BY event_count DESC;
