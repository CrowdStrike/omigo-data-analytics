9. Spark SQL

Declarative queries compiled to distributed plans — SQL that scales
The correction to MapReduce. Keep a high-level declarative language, compile it to distributed work. Catalyst optimizer builds logical plans, optimizes them, and emits physical stages across the cluster — the programmer never specifies how.
What It Is A module in Apache Spark that provides a SQL interface and DataFrame API, using the Catalyst optimizer to compile queries into distributed execution plans across a cluster.
Core Idea SQL + DataFrame API unified under one optimizer. Catalyst builds logical plans, applies rule-based and cost-based optimization, then generates physical plans distributed across executors. In-memory processing eliminates MapReduce disk overhead.
Strengths Fast — in-memory processing avoids disk I/O between stages. Real optimizer (Catalyst) with extensible rules. Unified API — same engine for SQL, DataFrames, streaming, and ML. Streaming support via Structured Streaming. Large community and ecosystem.
Weaknesses JVM memory management complexity (GC pauses, OOM on skewed data). Cluster resource tuning is non-trivial (executor memory, cores, partitions). Shuffle-heavy operations still slow. Small-data overhead — Spark adds latency for simple queries.
Business Use Case Large-scale ETL on data lakes, interactive analytics on petabyte datasets, streaming pipelines with exactly-once semantics, ML feature engineering at scale, unified batch+streaming architectures.
Example 
-- Spark SQL with Catalyst optimization
EXPLAIN EXTENDED
SELECT
    category,
    COUNT(*) as purchase_count,
    AVG(amount) as avg_amount,
    PERCENTILE_APPROX(amount, 0.95) as p95_amount
FROM transactions
WHERE event_date >= '2024-01-01'
  AND status = 'completed'
GROUP BY category
HAVING COUNT(*) > 100;

-- Catalyst produces:
-- 1. Logical Plan (parsed)
-- 2. Analyzed Plan (resolved references)
-- 3. Optimized Plan (predicate pushdown, column pruning)
-- 4. Physical Plan (hash aggregate, columnar scan)
