44. Data Query Languages Survey

Comparison of query paradigms — declarative vs procedural, batch vs streaming, schema-on-read vs schema-on-write.

Core tension: Every query language embeds assumptions about data shape, execution model, and scale. SQL assumes relations and set operations. SPL assumes time-ordered events. Pig assumes dataflow DAGs. Choosing a language is choosing a worldview — and the wrong one fights your data's natural structure.

Design Dimensions

1. Declarative vs procedural: SQL says WHAT, Pig says HOW. Trade-off: optimizer freedom vs explicit control.

2. Time as first-class: SPL assumes temporal ordering; SQL bolts it on with window functions.

3. Nested data: SQL struggles with arrays/structs natively; Pig/Splunk handle them more naturally.

4. Scale model: Single-node optimizer (SQL) vs distributed DAG (Pig/Hive) vs search-time extraction (Splunk).

Anti-Patterns

• Using SQL for event-stream analysis (forcing temporal into relational)

• Using Pig/Hive for interactive exploration (batch latency kills iteration)

• Treating SPL as a general-purpose ETL language (no joins, limited aggregation)

• Assuming query language choice doesn't affect what questions get asked
