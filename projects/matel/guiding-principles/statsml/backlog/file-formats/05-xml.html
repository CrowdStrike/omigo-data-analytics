5. XML

Verbose structured markup with schemas and namespaces.

Core trade-off: Validation and contractual precision that lets two organizations agree on a data format — at the cost of weight and ceremony that makes simple things complex.
What It Is A markup language descended from SGML that uses nested tags to represent hierarchical data. Accompanied by a rich ecosystem of standards: XSD for validation, XSLT for transformation, XPath/XQuery for querying, namespaces for avoiding name collisions across organizations.
Structure / Syntax Prolog (<?xml version="1.0"?>), root element, nested child elements with attributes. All tags must close. Namespaces declared with xmlns. Schema defined externally via XSD or DTD. CDATA sections for unescaped content. Comments with <!-- -->.
Strengths XSD validation gives contractual data agreements between organizations. Namespaces prevent collisions when combining documents. XSLT enables declarative transformation. Mature tooling in every enterprise language. Self-documenting with descriptive tag names.
Weaknesses Verbose — 3-10x the size of equivalent JSON. The spec ecosystem (XSD, XSLT, XPath, XQuery, DTD, SAX, DOM) is enormous. Parser diversity leads to security issues (XXE attacks). Attributes vs elements is a perpetual design debate. Namespaces confuse everyone.
Business Use Case Finance (FIXML, ISO 20022). Healthcare (HL7 v2/FHIR). Publishing (EPUB, DocBook). Government interchange (tax filings, customs). SOAP web services. Configuration (Maven pom.xml, .NET configs). Any domain requiring formal contracts between organizations.
Example 
<?xml version="1.0" encoding="UTF-8"?>
<order xmlns:pay="http://example.com/payment"
       xmlns:ship="http://example.com/shipping">
  <item sku="A-100" qty="2">
    <name>Widget</name>
    <pay:price currency="USD">29.99</pay:price>
  </item>
  <ship:address type="residential">
    <ship:city>Portland</ship:city>
  </ship:address>
</order>
Namespaces (pay:, ship:) let payment and shipping teams define their own elements without collision — useful when the document crosses organizational boundaries.
