6. JSON

Smallest format carrying nested data.

Core trade-off: Just enough types to be universally useful — but no dates, no comments, and precision loss past 53 bits silently corrupts large IDs.
What It Is JavaScript Object Notation — a text format with six types: string, number, boolean, null, array, and object. Derived from JavaScript syntax but language-independent. The dominant format for web APIs and configuration since the mid-2010s.
Structure / Syntax Objects: {"key": value}. Arrays: [value, value]. Strings in double quotes only. Numbers without quotes (no integer/float distinction). Booleans: true/false. Null: null. No trailing commas. No comments. UTF-8 encoding.
Strengths Native in every browser (JSON.parse/stringify). Simple spec fits on one page. Nested structures map naturally to objects/dicts in every language. Universal parser support. Human-readable with pretty-printing. Sufficient for 90% of data interchange needs.
Weaknesses No date/time type — dates are strings with no standard format. No integer vs float distinction — all numbers are IEEE 754 doubles, losing precision past 2^53. No comments allowed. Large IDs (Snowflake, Twitter) need string encoding. No schema built-in.
Business Use Case REST API request/response bodies. Configuration files (package.json, tsconfig.json). Document databases (MongoDB, CouchDB). Web application state (localStorage, Redux). Message formats between microservices. The default choice when you need structured data on the web.
Example 
{
  "user_id": "9007199254740993",
  "name": "Alice Chen",
  "roles": ["admin", "analyst"],
  "prefs": {
    "theme": "dark",
    "notifications": true
  },
  "created_at": "2024-03-15T10:22:01Z",
  "deleted_at": null
}
Note: user_id is a string because the integer 9007199254740993 exceeds 2^53 and would silently round in JavaScript. The date is a string with no type guarantee — the consumer must know to parse it.
