1. CSV / TSV

Delimited plain text, universal, no schema.

Core trade-off: Needs nothing installed and works everywhere — but breaks the moment your data contains the delimiter itself.
What It Is A plain-text tabular format where each line is a record and fields are separated by a delimiter character — comma (CSV) or tab (TSV). No metadata, no types, no schema. The file is the data and nothing else.
Structure / Syntax One header row (optional), followed by data rows. Fields separated by , or \t. Quoting with double-quotes when a field contains the delimiter, newlines, or quotes themselves. RFC 4180 is the closest thing to a spec, but many producers ignore it.
Strengths Universal tooling — every language, database, and spreadsheet reads CSV. Human-readable in any text editor. Streamable line-by-line without loading the whole file. Trivial to generate. Tiny overhead (just the delimiter characters).
Weaknesses No type information — everything is a string until parsed. No schema enforcement. Quoting rules are ambiguous across implementations. Cannot represent nested or hierarchical data. Encoding issues (UTF-8 vs Latin-1 vs BOM). No standard for null vs empty string.
Business Use Case Data exchange between any two systems that don't share a protocol. Quick exports from databases. Spreadsheet interchange. Feed files for ad platforms. Bulk uploads to SaaS tools. The lowest common denominator when you just need to move rows.
Example 
name,city,bio
Alice,New York,"Likes commas, really"
Bob,"Portland, OR","Said ""hello"" once"
Charlie,London,
The quoting edge cases: field 2 of row 2 contains a comma inside quotes. Field 3 of row 2 contains escaped double-quotes. Row 3's last field is empty — is it null or empty string? The spec doesn't say.
