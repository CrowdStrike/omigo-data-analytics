13. safetensors / GGUF

Model weight storage formats for ML.

Core trade-off: Safety (no arbitrary code execution) and speed (memory-mappable) — but the ecosystem is fragmented between formats and tooling is still evolving.
What It Is Formats designed specifically for storing neural network weights (tensors). safetensors (by Hugging Face) is a safe, fast alternative to Python's pickle for model distribution. GGUF (by the llama.cpp project) is designed for local inference with quantization support. Both solve the security disaster of pickle-based model files.
Structure / Syntax safetensors: A JSON header (tensor names, shapes, dtypes, byte offsets) followed by raw tensor data. Header is at the start for fast metadata access. GGUF: A single-file format containing model metadata (architecture, tokenizer, hyperparameters) plus quantized weight tensors. Both are memory-mappable — the OS loads pages on demand.
Strengths Safe — no arbitrary code execution (unlike pickle, which can run anything on load). Memory-mappable — load a 70B parameter model without reading the entire file into RAM. Fast partial loading — load specific layers on demand. GGUF supports multiple quantization levels (Q4, Q5, Q8) in a single format. safetensors enables lazy loading for large models.
Weaknesses Ecosystem fragmentation — safetensors for Hugging Face/PyTorch world, GGUF for llama.cpp/Ollama world. Tooling still evolving rapidly. GGUF is specific to the llama.cpp ecosystem and its model architectures. safetensors has no built-in quantization. Converting between formats requires extra tooling.
Business Use Case Model distribution on Hugging Face Hub (safetensors is now the default). Local inference with llama.cpp, Ollama, LM Studio (GGUF). Checkpoint storage during training. Model deployment where security matters (no pickle exploits). Any scenario where you download model weights from the internet and need to trust they won't execute malicious code.
Example 
Why pickle is dangerous:
─────────────────────────
import pickle
# Loading a model file can execute ANYTHING:
# pickle.loads(malicious_bytes)
# → runs os.system("rm -rf /") or installs backdoor
# The format has no boundary between "data" and "code"

Why safetensors is safe:
────────────────────────
# Header: {"layer1.weight": {"dtype":"F32","shape":[768,768],
#           "data_offsets":[0, 2359296]}, ...}
# Body: raw bytes at those offsets. Nothing executable.
# Parser: reads header JSON, mmap's data region. Done.
# No __reduce__, no exec, no eval. Pure data.

GGUF adds quantization:
───────────────────────
# Same 70B model at different quality/size tradeoffs:
# - F16:  140 GB (full precision, needs 140GB RAM)
# - Q8:    70 GB (8-bit, minimal quality loss)
# - Q4_K:  40 GB (4-bit, fits on consumer GPU)
# - Q2_K:  25 GB (2-bit, noticeable quality loss)
# Single format handles all quantization levels.
The fundamental insight: pickle conflates "data" with "code" — loading a file means executing arbitrary Python. safetensors enforces a strict data-only contract: header describes layout, body is raw numbers, nothing more.
