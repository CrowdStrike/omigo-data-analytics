PINs & Numeric Secrets

The deliberately tiny credential — a secret so small it is only safe inside a system that counts and limits guesses, which makes it the clearest case of security living outside the secret.

Design: A PIN is not a small password — unlike a password, which must survive offline guessing on its own, a PIN assumes it will never face offline guessing at all and delegates its entire security to rate-limiting, lockout, and hardware try-counters around it.

1. What a PIN is designed for

  • Design goal: a tiny secret built for the numeric keypad.
  • Input surfaces: cash machines, phone lines, door pads, lock screens.
  • Usability: enterable one-handed and in seconds.
  • Trade-off: accept a minuscule secret, move security elsewhere.
  • Arithmetic: ten thousand 4-digit values, roughly 13 bits.
  • Offline risk: any offline attacker exhausts the space instantly.
  • Survival condition: guesses must be counted and stopped.
Key question: never "how strong is the number" but "what happens on the wrong guess" — without an enforced try budget, a PIN is not a credential at all.

2. Where the security actually lives

  • Hardware try-counter: card chips enforce the budget in silicon.
  • Permanent block: a few wrong entries and the chip blocks for good.
  • Reset path: only an out-of-band reset unblocks the chip.
  • Tamper-resistant: attackers cannot reset the counter or read the PIN.
  • Server-side lockout: the server counts failures for remote PINs.
  • Remote scope: phone banking, centrally verified app PINs.
  • Response: lock the account or force a step-up check.
  • Software weakness: only as good as discipline on every entry path.
  • Escalating delays: each lock-screen failure waits longer.
  • Attacker cost: brute force stretches from minutes into years.
  • Owner cost: barely inconveniences two honest mistypes.
Try budget: the same four digits have completely different security per enforcement layer — the attacker's real budget is tries set by the layer, not combinations.

3. Human digit-choice skew

  • Heavy clustering: the chosen distribution is nothing like uniform.
  • Date patterns: birth years and other dates dominate picks.
  • Digit patterns: four identical digits, ascending or descending runs.
  • Keypad shapes: patterns traced on the keypad grid.
  • Entropy collapse: effective entropy sits far below the designed 13 bits.
  • Coverage skew: the top few percent covers a large user share.
  • Uniform assumption: try-budget math silently assumes uniform choice.
  • Risk math: three guesses in ten thousand reads as a 0.03% risk.
  • Skew multiplier: clustering boosts the odds on those same guesses.
Distribution problem: a core theme of this repo — the model assumed a uniform distribution, the humans supplied a heavily skewed one, and every downstream risk number inherited the error; the entropy gap is a distribution problem, not a cryptography problem.

4. Conventions, and current vs historical practice

  • Banking cards: standardized on four digits almost everywhere.
  • Regional norm: six digits in some regions and sectors.
  • SIM PINs: default to four with longer values allowed.
  • Device unlock: shifted from a 4-digit to a 6-digit default.
  • Digit-only inputs: cash-machine keypads, door locks, phone lines.
  • Accessibility: it too demands digit-only entry.
  • Persistence: survives every prediction of its death.
  • Modern role: device PINs now gate hardware-held keys.
  • Behind the PIN: a secure element holds passkeys and payment credentials.
  • Strength inversion: those credentials far outclass the PIN itself.
  • Hardware budget: the secure element enforces the try budget.
Front door: the humble PIN has quietly become the front door to the strongest credentials a person carries — acceptable only because the hardware behind it converts "13 skewed bits" into "a handful of tries against tamper-resistant silicon".
