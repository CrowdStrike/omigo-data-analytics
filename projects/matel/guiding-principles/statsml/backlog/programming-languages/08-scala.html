8. Scala

Best of Java and functional programming — built for data pipelines, actors, and DSLs

Core trade-off: Unify OOP and FP on the JVM. Use Java's ecosystem but write in a functional style. Ideal for data pipelines (Spark), reactive systems (Akka actors), and creating domain-specific languages. Power and expressiveness at the cost of complexity.
What It Is A statically-typed language running on the JVM that fuses object-oriented and functional programming. Everything is an object AND functions are first-class. Interoperates seamlessly with Java libraries. Designed by Martin Odersky (2004).
Unique Contribution OOP + FP fusion on the JVM — pattern matching, immutable collections, higher-kinded types alongside classes and inheritance. Actor-based concurrency (Akka). The native language of Apache Spark. Powerful enough to create internal DSLs that read like custom languages.
Strengths Full JVM interop (use any Java library), pattern matching for expressive data handling, type inference reduces boilerplate, implicits enable DSL creation, Spark native language, strong concurrency models (Akka actors, Futures).
Weaknesses Slow compile times, complex type system (higher-kinded types, path-dependent types), two communities pulling in different directions (FP purists vs pragmatists), steep learning curve, declining industry adoption as Kotlin/Go gain ground.
Business Use Case Apache Spark data pipelines (Spark is written in Scala), reactive systems (Akka/Pekko), financial systems (trading platforms), creating internal DSLs for business rules, backend services at Twitter, LinkedIn, and similar scale.
Example 
import org.apache.spark.sql.SparkSession

val spark = SparkSession.builder.appName("ETL").getOrCreate()

// Spark transformation pipeline — reads like a DSL
val result = spark.read.parquet("s3://data/events/")
  .filter($"event_type" === "purchase")
  .groupBy($"user_id", window($"timestamp", "1 hour"))
  .agg(
    sum($"amount").as("hourly_spend"),
    count("*").as("num_purchases")
  )
  .filter($"hourly_spend" > 100)

// Pattern matching — exhaustive, compiler-checked
sealed trait PaymentResult
case class Success(txId: String) extends PaymentResult
case class Failure(reason: String) extends PaymentResult

def handle(r: PaymentResult): String = r match {
  case Success(id) => s"Processed: $id"
  case Failure(msg) => s"Failed: $msg"
}
