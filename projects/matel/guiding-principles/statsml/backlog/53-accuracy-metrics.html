Accuracy Metrics

Decision framework for choosing the right evaluation metric — what each metric actually measures, when it lies, and which problem characteristics dictate the choice.

Goal

Build a practical lookup: given the problem type, class distribution, cost structure, and operational context — which metric(s) should you report, optimize against, and use for model selection? No single metric is universally correct; the goal is knowing exactly when each one applies.

Classification Metrics — When to Use What

MetricUse WhenFails When
AccuracyBalanced classes, equal misclassification costAny imbalance; trivial baseline looks good
PrecisionFP is expensive (spam filter, ad targeting, recommendations)Used alone — ignores how much minority class you're missing
Recall / SensitivityFN is expensive (disease screening, fraud, safety systems)Used alone — you can get 100% recall by predicting everything positive
F1Need one number balancing precision and recall; moderate imbalanceWhen FP and FN costs aren't equal (use F-beta instead)
F-betaAsymmetric FP/FN costs; beta > 1 weights recall, beta < 1 weights precisionHard to interpret for stakeholders; beta choice is often arbitrary
AUC-ROCComparing models across all thresholds; balanced or moderate imbalanceSevere imbalance — ROC is optimistic because TN dominates; use AUC-PR instead
AUC-PRSevere imbalance; care about minority class retrieval qualityBalanced data — PR curve adds complexity without insight over ROC
MCCSingle balanced summary regardless of class ratio; binary classificationMulticlass (extensions exist but lose interpretability)
Cohen's KappaAgreement above chance; inter-annotator reliability; prevalence-awareParadoxes with very high/low prevalence (Kappa can be low even with high accuracy)
Log LossProbability calibration matters; ranking + calibration both neededCare only about hard decisions, not probability quality
Brier ScoreOverall probability accuracy; proper scoring ruleExtreme imbalance — dominated by majority class calibration
Lift / GainOperational: "top-k" retrieval, marketing campaigns, prioritized reviewNeed full-population performance summary

Regression Metrics — When to Use What

MetricUse WhenFails When
MSE / RMSELarge errors are disproportionately bad; Gaussian error assumptionsOutliers dominate the metric; units are squared (MSE) making interpretation hard
MAEAll errors equally bad regardless of size; robust to outliersYou genuinely care more about large errors (use MSE)
MAPERelative error matters; comparing across different-scale targetsActual values near zero → MAPE explodes; asymmetric (under-predictions penalized more)
R²Quick "how much variance explained" summary; comparing models on same dataCross-dataset comparison; can be negative; doesn't indicate bias direction
Quantile LossAsymmetric costs (over-prediction vs. under-prediction); prediction intervalsSymmetric cost scenarios — adds unnecessary complexity

Decision Framework

  • Step 1: What's the cost structure? — Are FP and FN equally bad? If not, asymmetric metrics (F-beta, cost-sensitive)
  • Step 2: What's the class distribution? — Balanced → accuracy/ROC fine. Imbalanced → PR curve, MCC, F1 on minority
  • Step 3: Do you need a threshold or a ranking? — Fixed threshold → point metrics. Ranking/retrieval → AUC, lift, gain
  • Step 4: Do probabilities matter? — Yes → log loss, Brier, calibration plots. No → threshold-based metrics
  • Step 5: Who consumes the metric? — Stakeholders → accuracy, precision, recall (interpretable). ML team → MCC, AUC-PR, log loss (informative)

Key Questions

  • When do AUC-ROC and AUC-PR disagree, and which one is telling the truth?
  • Is F1 ever the right optimization target, or should you always optimize a proper scoring rule and threshold post-hoc?
  • How does metric choice interact with hyperparameter tuning — optimizing for log loss vs. F1 gives different models, not just different scores
  • What's the minimum test-set size for a metric estimate to be statistically meaningful (confidence interval width)?
  • Multi-metric reporting: which 2–3 metrics should always be reported together to avoid a single-metric blind spot?
