Credential & Token Design

How credential artifacts themselves are designed — format, embedded claims, entropy, lifetime, and revocability — from API tokens to recovery codes. The mechanisms that deliver or verify them are a separate story; this survey is about the artifact.

1. API Tokens & Keys

  • Format: prefix + random core + checksum, shown once
  • Why prefixes: secret scanners spot leaks in public code
  • Entropy: length × alphabet — hex vs base62 trade-off
opaque tokens prefixes entropy

2. Structured Signed Tokens

  • Design: claims + signature, verified with no lookup
  • Wins: stateless, portable across services
  • Costs: size, readable claims, no true revocation
JWT claims stateless

3. Session Cookies & Anti-Replay Design

  • Three designs: session ID, signed, encrypted
  • Anti-replay: bind to hashed IP, device fingerprint
  • Trade-off: theft resistance vs mobile false logouts
cookies replay binding

4. Revocation & Lifetime Semantics

  • The split: lookup dies instantly; signed lives to expiry
  • Denylist: revocation that re-adds the lookup
  • Compromise: short access + rotating refresh tokens
revocation TTL refresh tokens

5. Password Composition Rules

  • The arc: short caps → forced complexity → length-first
  • Why it reversed: humans made complexity predictable
  • Varies by: country, regulator, and sector
passwords policy history

6. Password Storage Design

  • The ladder: plaintext → salted → slow memory-hard
  • Framing: design only matters after the database leaks
  • Consequence: storage decides which rules matter

7. PINs & Numeric Secrets

  • Entropy: ~13 bits — the system carries the security
  • Enforcement: try-counters, lockout, secure elements
  • Human skew: dates and patterns shrink it further

8. Security Questions & KBA

  • Static Q&A: public, low-entropy, unrotatable answers
  • Dynamic KBA: credit-file questions, broker-dependent
  • Trend: retired for possession-based recovery

9. Recovery Credentials

  • Catalog: reset links, one-time codes, backup keys
  • Design flaw: secondary-email loops are circular
  • Principle: weakest recovery path sets real strength
