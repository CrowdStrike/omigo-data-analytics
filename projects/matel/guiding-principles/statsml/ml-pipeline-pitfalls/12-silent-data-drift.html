Pitfall: Silent Data Drift (Schema/Pipeline Changes)

Upstream data changes without notification, model degrades silently.

The Problem

Your model was trained on data in one format. The upstream data pipeline changes without notice, and the model receives different schema, units, encodings, or value ranges. The model continues to run without error, but predictions become meaningless.

  • Currency column changes from dollars to cents (100x shift)
  • Categorical encoding switches from one-hot to label encoding
  • Date format changes from YYYY-MM-DD to Unix timestamp
  • Missing value convention changes from -1 to NULL
  • Feature scaling applied upstream that training never saw
Impact: The model receives technically valid data types but semantically different values. No error is raised. Predictions degrade silently. By the time you notice, weeks of bad decisions have accumulated.

Example: Loan model trained on "income" in thousands (e.g., 65.5 = $65,500). Upstream ETL changes to dollars. Model now sees 65500 and interprets as $65.5M income. Approves everyone.

Why It Happens

ML models sit at the end of long data pipelines. Changes upstream are made for good reasons—code refactoring, database migrations, new data sources—but the downstream impact on models is not considered or communicated.

  • Different teams own the pipeline and the model with no shared schema contract
  • Data types remain the same (float → float) so no type error is raised
  • Pipeline changes are deployed as "internal refactoring" without model team notification
  • No automated checks compare training data distribution vs. production data distribution
  • Model monitoring tracks accuracy, not input data statistics
Mechanism: The model expects mean=50, std=10. Production data now has mean=5000, std=1000. Model applies coefficients learned on the old scale. Predictions are nonsense, but syntactically valid.

Example: Feature engineering changes from "log(price)" to "price". Model trained on log scale now receives raw prices. Predictions shift by orders of magnitude. No error, just wrong.

Detection & Mitigation

You cannot prevent upstream changes, but you can detect them immediately and fail fast. Monitor input statistics, enforce schema contracts, and set drift alarms.

  • Store training data statistics (min, max, mean, std, cardinality) for every feature
  • Before prediction, check that production data statistics are within tolerance (e.g., ±20%)
  • Enforce schema contracts with data validation libraries (Great Expectations, Pandera)
  • Alert if feature distributions shift beyond threshold (KS test, PSI > 0.2)
  • Version your data pipeline and require model retraining on major changes
  • Fail loudly—reject predictions and page oncall rather than returning garbage
Fix: Implement input validation that compares production data stats to training data stats. If drift exceeds threshold, halt predictions and alert. Schema contracts prevent silent changes.

Example: Log training data stats: income_mean=67.3, income_std=22.1. Production sees income_mean=67300. Drift detector triggers: "Mean shifted 1000x. Pipeline change detected. Halting predictions."
