Pitfall: Class Imbalance Mishandling

Treating 95/5 class ratio naively → model predicts majority class always

The Problem

"Model is 95% accurate!" — but it just predicts "negative" for everything. Recall on positives = 0%. Oversampling minority in train but evaluating on original distribution → inflated metrics.

  • "Model is 95% accurate!" — but it just predicts "negative" for everything. Recall on positives = 0%
  • Oversampling minority in train but evaluating on original distribution → inflated metrics
  • Using accuracy as metric when classes are imbalanced → meaningless number

Example: Fraud (2%). Model predicts "no fraud" always → 98% accuracy, 0% fraud detection. Completely useless. Precision-recall or F1 on the minority class tells the real story.

Defense: Use precision/recall/F1 for rare class. Stratified splits. If oversampling: only on train, never on test. Evaluate at multiple thresholds (PR curve).

Why It Happens

Teams use accuracy as the primary metric without considering class distribution. When 95% of samples are negative, a model that always predicts "negative" achieves 95% accuracy while being completely useless. Naive random splits may further distort the class ratio in individual folds.

  • Using accuracy as the primary metric when classes are imbalanced (95/5 or worse)
  • Naive random splits can create folds with zero minority samples
  • Default classification threshold of 0.5 assumes balanced classes
  • Oversampling applied globally (before split) inflates test performance on minority class

Example: Credit card fraud (0.2% positive). Model trained with cross-entropy loss: predicts P(fraud) between 0.01-0.03 for all transactions. At threshold 0.5, it predicts zero fraud. Accuracy: 99.8%. Fraud detected: 0%.

Root Cause: Accuracy rewards the majority class. A 95/5 split means a trivial "always predict negative" classifier scores 95%. The model's gradient descent finds this trivial solution because the loss from 5% misclassified positives is overwhelmed by the reward from 95% correct negatives.

The Correct Approach

Use stratified splits to preserve class ratios in each fold. Evaluate with precision, recall, and F1 on the minority class. Use PR curves instead of ROC for imbalanced data. Tune the classification threshold on validation data using business-relevant criteria.

  • Stratified splits (StratifiedKFold): preserve class ratio in every fold
  • Evaluate on minority class: precision, recall, F1 — not overall accuracy
  • PR curves over ROC curves: PR is more informative when positives are rare
  • Threshold tuning on validation set: optimize for business metric (e.g., cost of FP vs FN)
  • If oversampling: apply ONLY on training fold, never on validation/test

Example: Same fraud model. Switch to PR-AUC metric, stratified 5-fold CV, threshold tuned to maximize F1. Result: precision=0.45, recall=0.72 at threshold=0.08. Catches 72% of fraud with 55% false alarm rate on flagged transactions. Actually useful.

Fix: Replace accuracy with F1 or PR-AUC as the primary metric. Use StratifiedKFold to ensure every fold has minority samples. Tune threshold on validation using the business cost function (e.g., cost of missing fraud vs cost of false alarm).
