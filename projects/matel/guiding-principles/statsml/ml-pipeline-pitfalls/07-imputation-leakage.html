Pitfall: Imputation Leakage

Filling missing values using information from the full dataset

The Problem

Impute with column mean → mean computed over train+test → test info leaks. KNN imputation: nearest neighbors may come from the test set → using test values to fill train gaps.

  • Impute with column mean → mean computed over train+test → test info leaks
  • KNN imputation: nearest neighbors may come from the test set → using test values to fill train gaps
  • Imputation strategy itself can leak: "if missing → likely negative" was learned from the full dataset

Example: Income missing for 20% of records. Impute with median=$52k (computed globally). Test set median is actually $48k (different demographic). Leaked the higher train median into test imputation.

Defense: Impute using train-only statistics. Better: encode "missing" as its own signal (a feature "is_missing_income" may be predictive without needing imputation).

Why It Happens

SimpleImputer (or any imputer) is fit on the full dataset before splitting. The imputation values (mean, median, mode, KNN neighbors) incorporate test data. This is the same class of error as scaling leakage but specifically for missing value handling.

  • SimpleImputer.fit(X_full) computes fill values using train+test rows combined
  • KNN imputation: nearest neighbors may come from test set to fill train gaps
  • Iterative imputation (MICE): builds models using all data including test rows
  • The imputation strategy itself (which values are missing) may encode test patterns
Root Cause: Imputation is a form of model fitting — it estimates a value from observed data. If the "observed data" includes test rows, the imputed values carry test information into training features. Same principle as scaling leakage, often more impactful because missing values can be 20-40% of a column.

Example: 40% of "income" column is missing. Global median = $52k (includes test). Train-only median = $48k. Every imputed training row gets $52k instead of $48k — a $4k bias toward test. For a model predicting default, this shifts the decision boundary.

The Correct Approach

Fit imputer on training data only. Transform both train and test using train-derived fill values. Alternatively, encode missingness as a feature — a binary "is_missing" column preserves the information signal without needing imputation.

  • Fit imputer on TRAIN ONLY: imputer.fit(X_train), then transform both splits
  • Use Pipeline to enforce: imputation step fits only on training data within CV
  • Alternative: encode missingness as a feature (is_missing_income = 1/0) — often predictive
  • For KNN imputation: neighbors must come from training set only
  • Validate: compare imputed values between "global fit" and "train-only fit" — difference reveals leak magnitude
Fix: imputer = SimpleImputer(strategy='median'). imputer.fit(X_train). X_train_filled = imputer.transform(X_train). X_test_filled = imputer.transform(X_test). Or better: add a "missingness indicator" column that captures the signal of why data is missing.

Example: After fixing: train median = $48k used for all imputation. Test rows get $48k fill (not $52k). Additionally, "is_missing_income" flag added. Model uses the flag and achieves 2% better recall — missingness was informative about default risk.
