Pitfall: Silent Column Semantics Change

Column name stays the same but meaning or encoding changes over time

The Problem

A column keeps its name but upstream changes alter its definition, encoding, or units. The model trained on old semantics continues making predictions but is now processing fundamentally different data.

  • "revenue" switches from gross to net without renaming the column
  • "country" changes from ISO-2 codes (US, GB) to ISO-3 (USA, GBR)
  • Boolean flips from 1/0 to true/false string encoding
  • Timestamp format changes from UTC to local timezone
Impact: Model fails silently because column exists and has plausible values. Predictions become nonsensical but no error is raised. Fix: Schema versioning, semantic validation checks, distribution monitoring.

Example: A churn model trained when "days_active" meant calendar days. Upstream changes to business days. Model still runs but now overestimates activity by 28%.

Why It Happens / Detection / Common Sources

Upstream teams rename columns rarely but change definitions frequently. Naming conventions and lack of schema contracts make these changes invisible to downstream consumers.

  • Upstream team "improves" metric definition without versioning
  • No schema registry or data contracts enforcing stability
  • Column name is treated as the contract rather than semantic meaning
  • Changes buried in ETL code, never communicated to ML team
Detection: Track distribution statistics (mean, variance, unique values, nulls) over time. Alert when distributions shift beyond expected bounds. Maintain schema versioning with semantic descriptions.

Example: E-commerce site changes "price" from pre-tax to post-tax. Distribution shifts 10% higher. Model trained on pre-tax data now systematically underpredicts demand.

Prevention / Correct Approach

Treat semantic changes as breaking changes requiring versioning. Implement automated distribution monitoring and schema contracts.

  • Maintain schema registry with semantic descriptions and version history
  • Monitor distribution stats (percentiles, cardinality, nulls) continuously
  • Alert on distribution shifts beyond thresholds
  • Require backward-compatible changes or explicit versioned columns
Best practice: Version columns when semantics change (revenue_gross_v1, revenue_net_v2). Run distribution checks on every pipeline run. Treat semantic drift as a critical incident requiring retrain.

Example: When changing from gross to net revenue, create "revenue_net" column. Deprecate "revenue_gross" with 6-month sunset. ML team retrains on new semantics before cutover.
