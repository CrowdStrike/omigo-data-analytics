Pitfall: Aggregation Destroys Signal

Summarizing into one number loses the pattern that matters.

The Problem

You aggregate time series, transaction sequences, or behavioral data into summary statistics—mean, sum, count—to create features. But the pattern within the data (volatility, trend, seasonality, sequence) is more predictive than the aggregate. By collapsing to a single number, you discard the signal.

  • Two customers with $5,000 annual spend: one steady ($400/month), one lumpy ($4,800 in Dec, $200 rest). Loyalty differs.
  • Average session time = 5 min. But one user is 50 sessions × 6s (bouncing), other is 1 session × 5 min (engaged).
  • Mean glucose = 110 mg/dL for both. One is stable, other swings 60-180 (diabetic).
  • Total revenue = $100K. But trend is up (+15% YoY) vs. down (-10% YoY). Future differs.
Impact: Aggregation erases the structure of the data. Two entities with identical summary statistics can have completely different underlying patterns—and completely different target outcomes. Your model cannot distinguish them.

Example: Churn model. "Average monthly usage" = 50 hours for all users. But churners show declining trend (80→40→30), loyal users show stable pattern (50→50→50). Model sees only the mean. Cannot predict churn.

Why It Happens

Aggregation is convenient. Most ML models expect fixed-length feature vectors. Time series and sequences are variable-length. So you collapse them into scalars. But this destroys the temporal structure, variance, and dynamics that drive the outcome.

  • Tabular models (logistic, tree-based) expect one row per entity, one column per feature. No natural way to encode sequences.
  • Computing mean/sum/count is trivial. Computing trend, volatility, autocorrelation requires more thought.
  • Data pipelines built for reporting (total spend, average score) are reused for ML without considering what the model needs.
  • Aggregation reduces dimensionality, which seems like a good thing—but it's lossy compression that discards predictive information.
Mechanism: The target depends on dynamics (trend, volatility, sequence). You give the model only level (mean, total). Model has no access to the pattern that drives the outcome. Predictive power is capped.

Example: Fraud detection. "Total transactions = 12" and "Average amount = $83." But fraud is a rapid burst: 12 transactions in 8 minutes. Legitimate users: 12 over 30 days. Pattern matters. Summary hides it.

Detection & Mitigation

Before aggregating, extract features that capture the pattern: variance, trend, slope, autocorrelation, recent vs. historical comparison, sequence-based features. Or use models that natively handle sequences.

  • Add variance/std alongside mean. Volatility is often more predictive than level.
  • Add trend: linear regression slope over time, or ratio of recent to historical.
  • Add recency-weighted features: last 7 days vs. last 30 days.
  • Binned counts: how many periods above/below threshold, longest streak, time since last event.
  • For sequences: use RNN/LSTM/Transformer models that consume the full sequence rather than summaries.
  • Compare model performance with aggregated features vs. pattern-based features. The lift tells you how much signal aggregation destroyed.
Fix: Don't stop at mean/sum/count. Add variance, trend, recency, streaks. Better yet: model the sequence directly. Use LSTM for time series, transformers for behavioral sequences.

Example: Loan default. "Total income = $78K" (mean over 12 months). Add trend: slope = -$800/month. Add volatility: std = $14K. Add recency: last 3 months = $52K (down from $90K). Model accuracy: +12%.
