Pitfall: Multicollinearity Blindness

Correlated features inflate importance and destabilize coefficients

The Problem

height_cm and height_inches: r=1.0. Model gives wild coefficients to both (+500 and -498). Net = sensible but individual importances are garbage. Feature importance splits credit randomly among correlated features → all look weak individually.

  • height_cm and height_inches: r=1.0. Model gives wild coefficients to both (+500 and -498). Net = sensible but individual importances are garbage
  • Feature importance splits credit randomly among correlated features → all look weak individually
  • Removing one correlated feature → the other suddenly becomes very important. Instability = collinearity.

Example: 5 blood lipid features are intercorrelated (r>0.8). Random Forest: each gets 4% importance. Drop 4 of them → remaining one gets 18%. The "weak" features were cannibalizing each other's signal.

Defense: VIF check. Cluster correlated features and pick one representative. Or: use regularization (Lasso) that naturally selects among correlated features.

Why It Happens

Teams collect all available features without checking inter-feature correlations. When features are highly correlated (r > 0.8), they carry redundant information. Linear models split coefficients arbitrarily among correlated features, creating unstable and uninterpretable results.

  • Collecting all available features without correlation analysis — "more features = better" mentality
  • Data sources with multiple representations of the same concept (height_cm, height_in, height_ft)
  • Derived features that are linear combinations of existing ones (total = part1 + part2)
  • Feature importance algorithms split credit among correlated features — each looks individually weak
Root Cause: In linear models, if X1 ≈ X2, then β1*X1 + β2*X2 has infinite solutions along the line β1 + β2 = constant. The optimizer picks one arbitrarily (depends on initialization, regularization). Small data perturbations cause wild coefficient swings.

Example: height_cm and height_inches have r=0.999. Logistic regression assigns β_cm = +342, β_inches = -340. Net effect ≈ +2 (sensible). But the individual coefficients are meaningless and unstable. Remove one → the other gets β = +2 (stable).

The Correct Approach

Compute VIF (Variance Inflation Factor) for each feature. Cluster correlated features (r > 0.8) and select one representative per cluster. Alternatively, use Lasso regularization which naturally selects among correlated features.

  • VIF check: VIF > 5-10 indicates problematic multicollinearity — investigate and remove
  • Correlation clustering: group features with |r| > 0.8, keep one representative per cluster
  • Lasso (L1) regularization: naturally drives redundant feature coefficients to zero
  • PCA as alternative: transform correlated features into orthogonal components
  • Domain knowledge: choose the most interpretable/reliable feature from each cluster
Fix: (1) Compute pairwise correlation matrix. (2) Cluster features with |r| > threshold. (3) From each cluster, keep the feature with highest univariate predictive power or best interpretability. (4) Verify with VIF < 5 on remaining features.

Example: 5 income-related features (income, salary, earnings, compensation, pay_grade) all r > 0.85. Keep "income" (most interpretable). VIF drops from 45 to 3.2. Feature importance goes from 5×4% to 1×18%. Model accuracy unchanged but interpretation is now reliable.
