Pitfall: Label Shift (Train ≠ Deploy Distribution)

Class proportions in production differ from training

The Problem

Trained on 50/50 balanced data. Production is 99/1. Calibration is wrong — model over-predicts the rare class. Threshold set at 0.5 in training is wrong when base rate is 1% — should be much lower.

  • Trained on 50/50 balanced data. Production is 99/1. Calibration is wrong — model over-predicts the rare class
  • Threshold set at 0.5 in training is wrong when base rate is 1% — should be much lower
  • Even well-calibrated models break when deployed to different prevalence populations

Example: Disease prediction model trained on case-control (50% disease). Deployed in general population (1% disease). At threshold 0.5: flags 30% of population as positive. Useless. Need threshold recalibration.

Defense: Know your deployment base rate. Recalibrate predictions using Platt scaling or isotonic regression on deployment-representative data.

Why It Happens

Training data is artificially balanced (50/50 sampling) when the production environment is heavily imbalanced (99/1). The model learns calibrated probabilities for the balanced distribution, but these probabilities are wrong when the base rate changes. The threshold selected on balanced data is inappropriate for production.

  • Balanced sampling for training (50/50) when production is imbalanced (99/1 or worse)
  • Case-control study design: equal cases and controls, but deployment has natural prevalence
  • Model probabilities calibrated to training base rate, not deployment base rate
  • Threshold = 0.5 works for 50/50 but is catastrophically wrong for 99/1

Example: Disease prediction. Training: 50% disease (case-control design). Model outputs P(disease)=0.6 for a patient. In production (1% prevalence), the true P(disease|features) for the same patient is ~0.012. The model's 0.6 output is 50x too high because it was calibrated to 50% base rate.

Root Cause: P(Y=1|X) learned by the model is calibrated to training P(Y=1) = 0.5. In production P(Y=1) = 0.01. By Bayes' theorem, the posterior shifts. A score of 0.5 in training corresponds to a much lower true probability in production. The model is not wrong — it is miscalibrated for a different prevalence.

The Correct Approach

Know the deployment base rate. Recalibrate model predictions using Platt scaling or isotonic regression on deployment-representative data. Adjust the classification threshold to match production prevalence and business costs.

  • Know your deployment base rate: measure P(Y=1) in production data
  • Platt scaling: fit a logistic function to map model scores to calibrated probabilities for production prevalence
  • Isotonic regression: non-parametric calibration on a deployment-representative validation set
  • Threshold adjustment: solve for optimal threshold given production base rate and cost matrix
  • Monitor: track prediction rate vs observed rate — divergence signals distribution shift

Example: Model trained on 50/50 data. Production base rate = 1%. Apply Platt scaling on production-representative validation set. New threshold = 0.03 (not 0.5). Result: flags 5% of population (not 30%), catches 70% of true positives. Practical and deployable.

Fix: (1) Train model on balanced data (fine for discrimination). (2) Calibrate on data with production prevalence using Platt scaling. (3) Set threshold using production base rate: threshold = prior_ratio * cost_ratio. (4) Monitor deployed prediction rates vs observed outcome rates.
