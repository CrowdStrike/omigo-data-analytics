Pitfall: Proxy Variables (Hidden Sensitive Attributes)

Model learns protected attributes through correlated features despite explicit removal.

The Problem

You remove sensitive attributes like race, gender, or age from your model to ensure fairness. But correlated features act as proxies, allowing the model to reconstruct the protected attribute and discriminate anyway.

  • Zip code correlates 0.85 with race in many US cities
  • First name can predict gender with 95% accuracy
  • Job title and years of experience proxy for age
  • Credit score and income correlate with protected classes
Impact: Removing the protected attribute from the feature set does not prevent discrimination. The model finds indirect pathways through correlated features, producing the same disparate outcomes while appearing compliant.

Example: Credit model removes gender, but uses "cosmetics purchase frequency" (F=94%, M=6%) and "automotive parts" (M=89%, F=11%) which perfectly reconstruct it.

Why It Happens

Protected attributes are not isolated random variables. They are deeply embedded in the social and economic structure of your data. Correlations with non-protected features are strong, systematic, and numerous.

  • Geographic features (zip, neighborhood) encode race via residential segregation
  • Purchasing patterns, browsing history, and product preferences differ by gender
  • Job sequences, tenure, and seniority correlate with age
  • Many seemingly neutral features are downstream consequences of protected attributes
Mechanism: If feature X correlates 0.7+ with protected attribute Y, and X is predictive of the outcome, the model implicitly learns Y through X. Removing Y from the feature list does nothing if X remains.

Example: Remove "age" but keep "years since account creation" (r=0.92 with age), "preferred payment method" (older→check, younger→digital), and "device type" (older→desktop, younger→mobile).

Detection & Mitigation

Fairness cannot be achieved by feature exclusion alone. You must measure disparate impact, audit proxy correlations, and use fairness-aware training methods.

  • Compute correlation between each feature and protected attributes (even if removed)
  • Train a model to predict the protected attribute from remaining features — if AUC > 0.7, proxies exist
  • Measure disparate impact: does the model produce different approval/rejection rates across groups?
  • Use fairness constraints (demographic parity, equalized odds) during training
  • Apply adversarial debiasing or reweighting techniques
Fix: Audit your model for disparate impact on protected groups. If found, use fairness-constrained optimization, reweighting, or adversarial training. Simply removing features is insufficient.

Example: Loan model achieves 82% approval for group A, 53% for group B despite removing race. Audit reveals zip code is the proxy (correlation 0.87). Apply demographic parity constraint to equalize approval rates.
