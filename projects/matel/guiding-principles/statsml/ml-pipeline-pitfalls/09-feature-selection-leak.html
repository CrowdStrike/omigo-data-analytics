Pitfall: Feature Selection on Full Dataset

Selecting features using test data → optimistic performance

The Problem

Run correlation/importance analysis on FULL data → select top 10 features → split into train/test → evaluate. Problem: feature selection used test data to decide which features to keep → test is not independent.

  • Run correlation/importance analysis on FULL data → select top 10 features → split into train/test → evaluate
  • Problem: feature selection used test data to decide which features to keep → test is not independent
  • The "top 10" might include features that are only coincidentally good on this specific test fold

Example: 500 features. Univariate selection picks top 20 (p<0.01 against target on full data). Train/test split: 88% accuracy. Proper way (selection inside CV): 79%. The 9% gap was selection bias.

Defense: Feature selection MUST be inside the cross-validation loop. Fit selection on train fold only. Re-select for each fold.

Why It Happens

Running univariate feature selection tests (chi-squared, mutual information, ANOVA) on the full dataset before cross-validation. The selection step sees test data, so it picks features that happen to be good on this specific test set — optimistic bias that does not generalize.

  • Univariate tests (chi-squared, mutual info) run on FULL data including test labels
  • Selection criteria optimized to the specific train+test combination, not generalizable
  • With 500+ features, some will be coincidentally correlated with test labels by chance
  • The "top K features" include some that are only good on THIS particular test fold

Example: 1000 random features (pure noise). Run univariate selection on full data: ~50 features pass p<0.05 by chance. These 50 are coincidentally correlated with the test set. Train model on these 50: inflated accuracy. Proper selection inside CV: no features pass consistently.

Root Cause: Feature selection is a model fitting step — it uses the target variable to decide which features to keep. If the target from test rows participates in this decision, the selected features are biased toward the test set. This is information leakage through the selection criterion.

The Correct Approach

Feature selection MUST happen inside the cross-validation loop. Each fold re-selects features using only the training fold's data. The selected features may differ across folds — that is expected and correct. Use Pipeline with SelectKBest inside cross_val_score.

  • Feature selection INSIDE the CV loop: re-select features on each training fold
  • Use Pipeline([('selector', SelectKBest(k=20)), ('model', LogisticRegression())])
  • Selected features may differ between folds — that is correct (shows instability if so)
  • If selected features vary wildly across folds, the signal is weak — accept it
  • For final model: run selection on full training set (excluding held-out test)

Example: Pipeline with SelectKBest(k=20) inside 5-fold CV. Each fold selects its own top 20 from training data. Average accuracy: 79% (honest). Without pipeline (selection on full data): 88% (inflated). The 9% gap was selection bias.

Fix: Pipeline wraps feature selection + model. cross_val_score(Pipeline([selector, model]), X, y, cv=5). Each fold fits the selector on train-fold-only, selects features, trains model, evaluates on held-out fold. No test data touches the selector.
