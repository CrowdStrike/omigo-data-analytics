Newer-Bigger-Pricier Illusion

Using size, novelty, version number, or price as a proxy for quality — believing bigger is better, newer is improved, v10 beats v9, and expensive means good, without ever measuring.

1. The Bias: A Proxy Standing In for Quality

Quality is hard to measure. Size, recency, version numbers, and price are easy to observe. So the mind substitutes the easy attribute for the hard one — and stops asking the real question.

  • Bigger is better: more features, more data, larger model, larger team.
  • Newer is improved: the latest release must fix what the old one had.
  • Higher version means progress: v10 > v9 by definition of the number.
  • Expensive means quality: if it costs more, it must be worth more.

Example: a team upgrades a core library "because the new major version is out" — no changelog review, no benchmark. The new version has a performance regression in exactly their workload. Nobody looks, because upgrades are assumed to be improvements.

The trap: each proxy is weakly correlated with quality on average, which is why the heuristic survives. But the correlation is not monotonic, not universal, and — critically — it can be manufactured by whoever controls the proxy.

2. Why the Heuristic Exists — and Where It Breaks

The heuristic isn't stupid — it's a learned shortcut from environments where the proxy was honest. It breaks when the proxy is decoupled from quality, or actively gamed.

  • Size: more data helps — until it's more of the same biased data. A bigger model helps — until it overfits, costs 10× to serve, and gains 0.2%.
  • Novelty: new versions fix bugs — and introduce new ones. Fresh code has had the least real-world scrutiny of anything in the stack.
  • Version number: a number the vendor chooses. Nothing in "v10" is evidence; version inflation is a marketing decision.
  • Price: reflects positioning and what the market will bear — not marginal quality. Blind tests routinely erase price-driven quality ratings.
The pattern: every proxy is controlled by someone with an incentive to inflate it. Once a proxy becomes the buying signal, it stops being an honest quality signal — Goodhart's Law applied to your own perception.

3. The Exploitation: Manufacturing the Proxy

Because the bias is reliable, it gets engineered against you. Inflating the proxy is far cheaper than improving the product.

  • Version inflation: jump from v3 to v10 to signal maturity. Chrome-style rapid major versions trained users to read big numbers as progress.
  • "New & improved": relabel with a fresh design; the formula change is trivial or absent. Novelty itself is the product.
  • Premium pricing as positioning: raise the price to move upmarket. The higher price creates the quality perception it claims to reflect.
  • Spec-sheet arms race: more megapixels, more cores, more parameters — dimensions chosen because they are countable, not because they bind performance.
  • Deliberate obsolescence framing: the old version isn't broken, but the release cycle makes it feel outdated, so it gets replaced anyway.

Example: identical wine rated significantly higher when tasters were told it cost $90 vs $10 — and brain-imaging studies show the pleasure response itself changes. The price doesn't just bias the report; it biases the experience.

4. The Blindness: New Things Get Less Scrutiny

The subtler damage is asymmetric scrutiny. "Improved" is the default assumption for anything new, so its flaws start with the burden of proof against them.

  • Regressions ship silently: the new model/library/pipeline is assumed better, so nobody runs the old benchmark against it. Regressions are found by users, months later.
  • Old-version evidence is discarded: years of accumulated bug reports and workarounds documented the old system's failure modes. The new system's failure modes are unknown — which reads as "it has none."
  • Criticism of the new sounds like resistance: pointing out the new tool's flaws gets coded as "not adapting," so reviewers self-censor.
  • Bigger model, less questioning: when the larger model gives a wrong answer, it's "surprising"; when the smaller one does, it's "expected." Same error, different scrutiny.
The asymmetry: old things carry their full known defect list; new things carry an empty one. An empty defect list means unmeasured, not defect-free — but the bias reads it as the latter.

5. The Defense: Strip the Label, Then Measure

The proxy is information you can't unsee — so remove it before judging, and replace the assumption of improvement with a measurement of it.

  • Blind the comparison: evaluate old vs new without knowing which is which. If you can't tell them apart blind, the "upgrade" is a label.
  • Same benchmark, both versions: never adopt a new version without running the exact evaluation the old one passed. "Newer" is a hypothesis, not a result.
  • Ask what the proxy costs: bigger and pricier have denominators — serving cost, migration cost, complexity. Compare quality per unit cost, not raw quality.
  • Give the new thing the old thing's defect list: explicitly ask "what are the failure modes we haven't found yet?" before the accumulated evidence of the old system is thrown away.
The rule: any claim of the form "X is better because it is newer / bigger / higher-versioned / more expensive" contains zero evidence about quality. It is a claim about the proxy. Demand the measurement the proxy is standing in for.
