Gambler's Fallacy

Believing past outcomes change future odds in independent events

The Trap

The belief that past outcomes change future odds in independent events. The universe doesn't keep a ledger and doesn't owe you anything.

  • Played lottery daily for 10 years (3,650 tickets)
  • Feels like "investment" building toward a payoff
  • Today's odds: still exactly 1-in-a-million
  • Same as day 1. The 3,649 losses are invisible to today's draw

Example: Roulette shows 7 reds in a row. Half the table bets on black ("it's due"), half on red ("it's a streak"). Both are wrong. The casino displays the board precisely because it triggers both fallacies and increases betting volume.

Defense: Ask: "Does the next trial know about previous ones?" If no — if each event is independent — then streaks and droughts are stories. The past doesn't vote on the future.

Where It Strikes

Domain Fallacious Reasoning Reality
Roulette "Black is due" Each spin is independent
Model training "Loss should drop soon" after plateau Plateaus can persist indefinitely
A/B testing "It'll converge — keep running" Might be truly null — no effect exists
Interviewing "Next candidate will be great" after 5 bad ones Pool quality is fixed
Debugging "Must be close to the fix" after 8 hours Time spent ≠ proximity to solution
Lottery "My numbers are overdue" Draws are independent
Basketball "Cold shooter due for makes" Independent unless fatigued
Server ops "Won't crash again — we got unlucky" If root cause unfixed, same probability

Independent vs Dependent

The key question: does the system have memory?

  • Coin flips: no memory. Each flip is 50/50 regardless of history.
  • Card dealing: yes — the deck depletes. Drawing an ace changes remaining probabilities.
  • Model training: yes — gradient descent IS sequential. Each step depends on the previous state.

The fallacy label only applies to memoryless systems. In systems with memory, past events genuinely do change future probabilities — that's not a fallacy, that's math.

When to apply the label: If events are i.i.d. (independent and identically distributed), invoking past outcomes to predict the next one is the fallacy. If the system has state that evolves, it may be legitimate reasoning.

Pipeline Defense

Statistical tests to detect whether a process is truly independent:

  • Autocorrelation: measures correlation between a value and its lagged self. Independent processes show near-zero autocorrelation at all lags.
  • Runs test: counts sequences of same-sign values. Too few or too many runs indicates dependence.
  • Stopping rules: pre-commit to sample size / experiment duration. Never extend hoping for convergence.

If you find yourself saying "just a few more samples and it'll converge" — that's the fallacy talking. Use pre-set stopping criteria, not gut feel.

Rule: If the autocorrelation plot shows bars outside the confidence bounds, your process has memory. Don't treat it as independent draws.
