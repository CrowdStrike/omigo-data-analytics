Evolution of Cloud & Software Delivery

Shrink-wrapped boxes to browser tabs — how software reached users, and where the data ended up living.

Dates are approximate and mark mainstream adoption rather than first release. Bars in red ended as mainstream practice; orange survives in specific niches only.

The Eras

EraWhat changed
1985 – 2010s
Enterprise systems on owned hardware
ERP, CRM, long implementation projects
Large organisations ran licensed systems on their own servers, with implementations measured in months and customisations that complicated every subsequent upgrade. The data stayed inside the organisation, which is precisely why this model persists in regulated sectors.
2004 onward
The browser becomes the application
AJAX, single-page applications
Asynchronous requests allowed pages to update without reloading, making browser applications feel comparable to installed ones. This removed installation and update from the user's responsibility entirely: the deployed version became whatever the server was serving.
2006 onward
Renting infrastructure, then platforms
EC2, S3, managed databases, PaaS
Servers and storage became metered services, then the layers above them — databases, queues, identity, search — followed. Starting a company stopped requiring capital for hardware, which changed who could plausibly start one.
2006 onward
Subscription replaces purchase
SaaS, per-seat pricing, continuous delivery
Recurring payment aligned vendor revenue with continued use rather than the next upgrade cycle, and made continuous shipping normal. It also changed the customer's position: software became something rented, where price and terms can be revised, and the data lives with the vendor.
2006 onward
Documents move to the server
Google Docs, Office 365, real-time collaboration
Productivity software moved into the browser and made simultaneous multi-author editing routine, eliminating the emailed-attachment version problem. The stored document became the canonical copy, with local files as the exception.
2011 onward
The thin client returns
Chromebooks, virtual desktops, streamed applications
Devices holding little local state and running everything through a browser revived the terminal model of the mainframe era, now with the central machine belonging to a cloud provider rather than the organisation. Low cost and centralised management drove adoption in education and enterprise fleets.
2014 onward
Metered consumption, and some movement back
Usage-based pricing, cost management, repatriation
Pricing shifted toward measured consumption, which made cost a continuous engineering concern rather than an annual purchase. As bills grew, some organisations moved predictable steady workloads back to owned hardware, so the direction is no longer uniformly toward the cloud. Most recently, model inference joined the same pattern: capability rented per token through an API rather than deployed as software.
1980s – 2000s
Software as a purchased objectgone
Boxed media, perpetual licences, version upgrades
Software was bought once, installed from physical media, and replaced by a paid upgrade every few years. Vendors had no visibility into usage after the sale, and defects shipped in a release stayed in the field until the next one — which made release quality a far higher-stakes matter than it is now.
Late 1990s
Renting hosted applicationsgone
Application service providers
Vendors hosted conventional single-tenant applications and rented access, an idea that anticipated SaaS but predated the enabling technology. Without multi-tenancy or capable browsers, the economics did not work, and most providers did not survive the dot-com contraction.

What Disappeared

Ended as mainstream practice:
  • Boxed software on physical media — retail shelves of shrink-wrapped applications
  • Perpetual licences with paid major upgrades — the dominant commercial model for consumer and business software
  • Application service providers — hosted single-tenant applications, an idea that arrived before it could work
  • Emailing documents to collaborate — attachments with version numbers in the filename
  • Capacity planning before launching anything — hardware procurement as the first step of a project
  • Installing software from a CD — for most consumer software, a process that no longer exists
Alive, but only in niches:
  • On-premise deployment — standard where data residency, regulation or sustained load makes it preferable
  • Desktop applications — still preferred for professional creative and engineering work with heavy local compute
  • Self-hosted open source — a deliberate choice for organisations avoiding vendor dependence
  • Perpetual licensing — persists in specialist engineering and scientific software
