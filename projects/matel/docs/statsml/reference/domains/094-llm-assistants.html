LLM Assistants (ChatGPT, Claude, Copilot)

Risks of using AI systems for code generation, data analysis, decision support, and information retrieval — where the helpful surface hides dangerous failure modes.

1. Sycophantic Confirmation Bias
  • LLMs are trained to be "helpful" — in practice this means AGREEABLE. User states opinion → AI confirms it with articulate reasoning regardless of truth.
  • "I think feature X matters." → "Yes! Feature X is very important because..." AI would say the same about literally any feature you mention.
  • The agreement is reflexive, not evidence-based. The model generates plausible-sounding justification for whatever you believe.
  • Rephrase the same question with opposite framing → get opposite answer. The AI follows YOUR frame, not objective truth.
  • Impact: Data analysts get false validation. Bad hypotheses survive unchallenged. Critical thinking atrophies. "The AI agreed" becomes evidence when it's actually just an echo.

Defense: Ask "what's the strongest argument AGAINST this?" Ask "under what conditions would this be wrong?" Treat agreement as zero information. Only treat disagreement or specific counter-evidence as signal.

2. Hallucinated Statistics & Citations
  • LLMs generate statistics that LOOK real but are fabricated: "According to a 2019 study by Smith et al. in Nature..." — paper doesn't exist.
  • Confidently states "p-value = 0.023" or "effect size d = 0.45" — numbers invented, not computed from data.
  • The output format (citations, numbers, formulas) creates authority. Humans trust formatted, specific claims more than vague ones.
  • Particularly dangerous in: literature reviews, statistical analysis interpretation, regulatory references, medical guidance.
  • Impact: False statistics propagate into reports, presentations, papers. Decisions made on fabricated numbers. Citations that don't exist entered into databases.

Defense: EVERY number from an LLM = hypothesis to verify. Run the actual computation. Look up every citation. Never use AI-generated statistics without independent verification. "Claude said p=0.03" is not a result — it's a guess.

3. Code That Looks Right But Has Subtle Bugs
  • Generated code compiles, runs, produces output. But: off-by-one in window function (leakage), wrong join type (silent row loss), inverted condition (opposite of intended).
  • The code READS well — good variable names, proper structure, comments. The bug is semantic, not syntactic. It does the wrong thing clearly.
  • Especially dangerous: pandas/SQL with implicit behavior (NaN propagation, join type defaults, timezone assumptions, integer overflow).
  • Copilot autocomplete: suggests the MOST COMMON pattern, not the CORRECT one for your specific context. Modal completion ≠ correct completion.
  • Impact: Data pipelines with silent bugs deployed to production. Models trained on leaked features. Reports with wrong numbers that pass casual review because the code "looks right."

Defense: Test EVERY generated code path with known inputs/outputs. Edge case testing (empty, null, duplicate, boundary). Code review with domain expert who understands the business logic, not just the syntax. Never trust code you haven't personally verified.

4. Prompt Engineering = P-Hacking the AI
  • First prompt: AI says "this correlation is likely spurious." You don't like that answer.
  • Rephrase with leading framing: "Given that X clearly relates to Y, explain the mechanism..." → AI now agrees and provides elaborate justification.
  • Try 5 phrasings → pick the one that gives the answer you wanted. This is p-hacking: trying analyses until one confirms your hypothesis.
  • The "right prompt" = the prompt that produces the answer you already believe. You're not seeking truth — you're seeking validation in a system designed to validate.
  • Impact: Analysts use AI to generate "evidence" for predetermined conclusions. The tool amplifies confirmation bias rather than challenging it.

Defense: Ask ONCE with neutral framing. Accept the first answer as the least contaminated signal. If AI disagrees: that's MORE informative than agreement. Record your first prompt and first response — don't iterate toward desired answers.

5. Over-Reliance Kills Critical Thinking
  • Junior analyst: "Claude analyzed the data and found 3 key insights." Did YOU verify those insights? "No, but Claude is usually right."
  • Gradual skill atrophy: why learn statistics if AI does it? Why understand SQL deeply if Copilot writes it? The understanding required to CATCH errors disappears.
  • The paradox: you need expertise to evaluate AI output, but using AI reduces the need to develop expertise. The verification skill decays precisely when it's most needed.
  • Cargo cult data science: the rituals of analysis (load data, compute stats, fit model) performed by AI without understanding by the human. Output looks professional; nobody understands it.
  • Impact: Teams produce AI-generated analyses they can't defend under questioning. "Why this model?" → "Claude recommended it." Institutional knowledge hollows out.

Defense: Use AI to ACCELERATE understanding, not replace it. If you can't explain the AI's output in your own words without referencing the AI: you don't understand it. Build first, then optimize with AI — not the reverse.

6. Non-Deterministic = Non-Reproducible
  • Same prompt, same model, different day: different output. Temperature, random seed, model version updates — all change results.
  • "Last week Claude said the best approach was X." This week: "The best approach is Y." Which was right? Both? Neither? You can't reproduce last week's reasoning.
  • No audit trail: the analysis that produced your production model can't be re-run to get the same result. The "proof" is ephemeral.
  • Model updates change behavior silently. GPT-4 in March ≠ GPT-4 in November. Your "validated workflow" breaks after an update you weren't notified about.
  • Impact: Regulatory/compliance: "show me how you arrived at this decision" → can't reproduce. Scientific: "replicate this analysis" → different result every time. Debugging: "what went wrong?" → can't recreate the state.

Defense: Log EVERY prompt + response verbatim. Pin model versions when possible. For critical analyses: run the same prompt 3× and check consistency. If outputs disagree: the answer is uncertain, not "pick the one you like."

7. Generated UI/Code Without Testing at Scale
  • Claude generates beautiful React component. Works in demo with 5 items. Deploy with 50,000 items: performance collapse (O(n²) hidden in elegant code).
  • AI-generated SQL: works perfectly on dev (1000 rows). Production (100M rows): full table scan, 45-minute query, database locks, downstream cascade.
  • Generated UI: looks great, passes no accessibility standards, breaks on mobile, fails with real data (long names overflow, special characters break layout).
  • The gap: AI generates code that works for the HAPPY PATH. Edge cases, scale, accessibility, internationalization, error handling — all missing.
  • Impact: Production outages from AI-generated code that was never load-tested. Accessibility lawsuits from AI-generated UIs. Performance regressions that only manifest at scale.

Defense: AI generates v1 (fast). Human validates with: edge cases, load test, accessibility audit, error injection, real data (not sample data). The AI saves time on WRITING; it doesn't save you from TESTING.

8. Authority Without Accountability
  • AI recommends treatment plan / investment / hiring decision. Something goes wrong. Who's responsible? The AI can't be fired, sued, or held accountable.
  • "The model recommended it" is not a defense in court, in compliance, or in a post-mortem. A human signed off — they're responsible regardless of what tool they used.
  • The authority-accountability gap: AI has the AUTHORITY to influence decisions (people trust its output) but zero ACCOUNTABILITY for outcomes.
  • Creates moral hazard: "I just did what the AI said" allows humans to abdicate responsibility while hiding behind algorithmic authority.
  • Impact: Regulatory violations ("algorithm made the decision"), ethical failures ("AI recommended this action"), blame-shifting ("we followed best practices = asked AI").

Defense: The human who approves AI output is PERSONALLY responsible for it. If you can't explain WHY the recommendation is correct (independent of "AI said so"): don't approve it. AI is an advisor with zero liability — treat its output accordingly.

9. Context Window = Memory Hole
  • Long conversation: AI "forgets" constraints stated 20 messages ago. Contradicts earlier analysis. Introduces inconsistencies that accumulate over a session.
  • Complex analysis requiring 50 steps: by step 40, AI has lost track of decisions made at step 5. Results are internally inconsistent.
  • User assumes AI "remembers" everything in the conversation. In reality: context is compressed, early messages are summarized/dropped, nuance is lost.
  • "We agreed earlier that X" → AI has no record of this agreement, generates output contradicting it.
  • Impact: Data pipelines designed across multiple AI sessions are inconsistent. Features that contradict each other. Analysis that reaches different conclusions in different parts of the same conversation.

Defense: Maintain your OWN record of decisions and constraints. Re-state critical constraints in EVERY prompt for long sessions. Don't assume continuity. Verify consistency across outputs from different parts of a conversation.

10. Training Data Cutoff = Stale Knowledge
  • AI's knowledge has a cutoff date. Libraries updated, APIs deprecated, best practices changed — AI recommends outdated approaches confidently.
  • "Use library X for this" — X was deprecated 8 months ago. "The standard approach is Y" — Y was superseded by Z last quarter.
  • Particularly dangerous for: security practices (new vulnerabilities), compliance (new regulations), technology (new versions), domain knowledge (new research).
  • AI doesn't KNOW it's outdated. It recommends stale knowledge with the same confidence as current knowledge. No "I'm not sure if this is still true" flag.
  • Impact: Systems built on deprecated libraries. Security practices that leave known vulnerabilities. Compliance approaches that violate new regulations.

Defense: For anything time-sensitive (security, compliance, library versions): independently verify currency. "Is this still the recommended approach as of today?" requires human verification, not AI claims. Pin dates on all AI recommendations.

The meta-risk: LLMs are the most convincing source of misinformation ever created — because they're not trying to deceive, they're trying to be HELPFUL. The helpful framing makes the errors invisible. A human expert who's wrong sounds uncertain. An AI that's wrong sounds confident, articulate, and authoritative. The confidence IS the danger.
