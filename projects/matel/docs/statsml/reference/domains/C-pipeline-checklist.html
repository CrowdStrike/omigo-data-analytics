Pipeline Stage Checklist

For each pipeline stage: the questions you MUST answer before proceeding. Derived from real domain failures. If any answer is "no" or "don't know" — STOP.

Stage 1: Data Collection & Ingestion

Gate Check — Before Using This Data
Do I know WHO is NOT in this dataset? (What population is excluded?)
If no → survivorship bias. You're analyzing survivors, not the population.
Healthcare: only tested patients. Courts: only litigated cases. E-commerce: only converted users.
For every timestamp: do I know the timezone, granularity (sec/ms/μs), and whether it's UTC?
If no → potential 1-8 hour offsets or 1000× scale errors from ms/s confusion.
cloud provider multi-region. Cross-service joins. Unix epoch ambiguity.
If multiple sources feed the same table: are semantics identical across all sources?
If no → same column name, different meaning. "Amount" in dollars vs cents vs local currency.
Multi-hospital lab data. Multi-region billing. Cross-platform analytics.
Are there duplicates from retries, fanout joins, or ETL re-runs?
If yes and undetected → inflated counts, wrong averages, bogus significance.
Event pipelines. Payment retries. 1-to-many joins.
Do I know the data's latency? How old is the "freshest" record?
If unknown → you may be analyzing stale data from hours/days ago without realizing.
SEC filings (60-day lag). Feature store staleness. Billing lag (30+ days).

Stage 2: Profiling & Type Detection

Gate Check — Before Profiling
For columns with missing values: is the missingness informative (MNAR) or random (MCAR)?
If MNAR and you impute with mean → you destroy the signal that absence carries.
Healthcare: "lab not ordered" = healthy. Cybersecurity: "no log" = deleted. Survey: "no response" = unhappy.
Do sub-populations in my data have different reference ranges for the same feature?
If yes and you profile globally → universal thresholds misclassify sub-populations.
Healthcare: hemoglobin by age/sex/ethnicity. Education: test scores by developmental stage.
Has the column's MEANING changed over time? (Same name, different semantics after a migration.)
If yes and undetected → all analysis on post-change data is wrong, no error thrown.
Revenue gross→net. Status codes renumbered. Units changed (USD→cents).
Are there point masses (spike at zero, cap at max) that need separate treatment?
If ignored → spike dominates all statistics. Mean is meaningless. Histogram is useless.
Capital gain (95% zero). 2nd floor SF. Insurance claims. Sensor saturation.
What's the meta-distribution Gini? If >0.7: is adaptive bucketing planned?
If high Gini with equal-width bins → 80% of data in one bin, rest empty. Useless.
Income. Hospital charges. File sizes. Any power-law feature.

Stage 3: Shape Detection

Gate Check — Before Classifying Shape
Is n > 100 for this feature? (Below this: shape classification is unreliable.)
If no → report "insufficient for shape" and use non-parametric methods. Don't guess.
Sports: 17 games/season. Rare diseases: 50 patients. New product: 30 purchases.
Have I run at multiple bin resolutions? Does the shape persist across scales?
If shape only visible at one resolution → it's an artifact, not real structure.
Apparent bimodality that vanishes at different bin width. Noise peaks. Rounding artifacts.
Am I mixing sub-populations that should be profiled separately?
If yes → artificial multimodality. "Bimodal" is actually two populations with different means.
Male+female hemoglobin. Summer+winter energy. Pre+post migration data.
Is this feature stationary over the time range of my data?
If no → the "shape" you detected is an average across different regimes. Not real.
Revenue pre/post COVID. User behavior pre/post feature launch. Seasonal features.

Stage 4: Statistical Testing

Gate Check — Before Claiming Significance
How many tests am I running total? Have I adjusted for multiple comparisons?
If 100 features × 10 buckets = 1000 tests at p<0.05 → expect 50 false positives. Must correct.
Genomics (20K genes). Feature selection. Multi-bucket enrichment testing.
Is the enrichment PRACTICALLY significant, not just statistically significant?
At large n, trivial effects (1.006×) become "significant." But useless for classification.
Large datasets where everything is "significant." Clinical trials with negligible effects.
Is the CI lower bound still above the decision threshold?
If CI includes base rate → point estimate is meaningless. Can't trust the bucket.
Small n buckets with wide CIs. "85% purity" with CI [55%, 97%].
Am I comparing to the correct BASE RATE, not to 50%?
If base is 5%: a bucket at 10% is 2× enrichment (strong!). Comparing to 50%: "only 10%" = dismissed.
Fraud (0.1% base). Rare disease (1% base). High-value customer (5% base).
Is my test set TRULY independent of all training decisions?
If test set influenced: feature selection, threshold tuning, or hyperparameters → it's NOT independent.
Test set evaluated 50× (overfit). Features selected on full data. Threshold tuned on test.

Stage 5: Feature Engineering

Gate Check — Before Using This Feature
Would this feature ACTUALLY be available at prediction time in production?
If no → leakage. Feature computed from future events. "Collection calls made" predicts default because it FOLLOWS default.
Any derived feature using future data. Treatment-as-feature. Post-event aggregates.
Does this feature encode a protected attribute through a proxy?
If yes (zip code ↔ race, name ↔ gender) → model discriminates despite removing the protected attribute.
Hiring models. Credit scoring. Insurance pricing. Predictive policing.
Is this feature computed the SAME WAY in training (batch) and serving (real-time)?
If different (batch SQL vs streaming compute) → training-serving skew. Subtle numerical differences degrade predictions.
Feature stores. Real-time vs batch aggregation. Rolling windows with different boundaries.
If this feature is based on my own system's output: have I debiased it?
If not → feedback loop. CTR reflects position bias, not item quality. View count reflects ranking, not demand.
Click-through rate. View count. Recommendation-driven engagement.

Stage 6: Model Training & Evaluation

Gate Check — Before Trusting Results
Is train/test split at the ENTITY level, not the ROW level?
If same patient/user in both → model memorizes entities, not patterns. Accuracy inflated 10-20%.
Patient visits. User sessions. Multi-row entities. Time-series forecasting.
For time-ordered data: is the split temporal (train on past, test on future)?
If random split → model uses future info. Accuracy inflated by 10-30%.
Any financial data. User behavior. Sensor data. Event streams.
Is my model complexity appropriate for my data size?
1M parameters on 500 rows = memorization. Neural net on n=200: logistic regression will win.
Small medical datasets. Rare event prediction. Low-resource NLP.
Have I evaluated on the RARE class specifically, not just overall accuracy?
95% accuracy on 95/5 data = predicting majority always. Recall on minority = 0%.
Fraud. Disease. Cybersecurity attacks. Any imbalanced problem.
How many times have I evaluated on this test set? (>10 = burned)
Each evaluation leaks test info into decisions. After 50 rounds: effectively training on test set.
Kaggle leaderboard overfitting. Research paper p-hacking. Iterative model development.

Stage 7: Deployment & Monitoring

Gate Check — Before and After Deployment
Do I have data validation checks that alert on distribution shifts BEFORE predictions are served?
If no → silent schema change (dollars→cents) produces wrong predictions for weeks before anyone notices.
Upstream migrations. Unit changes. New category values. NULL rate changes.
Am I monitoring CORRECTNESS, not just availability/latency?
System serves wrong answers fast and confidently. Dashboard says "healthy" while predictions are garbage.
Stale caches. Feature store failures. Model serving outdated version.
Is there a mechanism to detect when the model's assumptions have been violated in production?
If no → model degrades silently over months. Blamed on "model staleness" when actual cause is upstream data drift.
Concept drift. Population shift. Seasonal patterns not in training. Policy changes.
For adversarial domains: when was the model last retrained? (>30 days in security = stale)
Adversaries adapt in days. A 6-month-old model in cybersecurity/fraud/spam is already significantly evaded.
Spam filters. Fraud detection. Content moderation. Any domain with active adversaries.
Do I have a kill switch to fall back to a simple/previous model if the new one misbehaves?
If no → a bad model in production causes damage until the next full deployment cycle (hours/days).
Canary deployment. Feature flags. Shadow mode. A/B test with abort criteria.
How to use this document: Print it. Before each pipeline stage, read the gate checks. If you can't answer YES to all questions: STOP and investigate. Each "no" represents a domain failure that has burned real teams with real consequences. The questions are simple. The consequences of skipping them are not.
