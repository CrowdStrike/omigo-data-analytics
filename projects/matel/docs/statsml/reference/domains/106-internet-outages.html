Internet Outages / Cascading Infrastructure Failures

Concept Visualization
major cloud region Takes Down Half the Internet

One region failure → thousands of companies' services go offline simultaneously. Blast radius of a single cloud region: streaming service, chat apps, streaming, smart doorbells, robot vacuums — all simultaneously. Models assuming "independent failures" between services: wrong. They're all on the same infrastructure. Correlated failure from shared dependency.
EDR vendor BSOD (July 2024): 8.5M Machines Simultaneously

Faulty update pushed to ALL Windows endpoints at once. Boot loop. No remote fix possible (machine can't boot → can't receive fix). Manual fix required per machine. Airlines grounded, hospitals dark, banks offline. The "reliability" of automated updates = single point of failure at global scale. One bad push = 8.5M bricks simultaneously.
BGP Misconfiguration Propagates Globally in Seconds

BGP (routing protocol) has no authentication. One ISP advertises wrong route → entire internet routes traffic through them → black hole. Pakistan trying to block video platform (2008) → accidentally blocked video platform globally for 2 hours. A single misconfiguration in one country → worldwide impact in <60 seconds. No human can react fast enough.
DNS Failures = Invisible (Everything Just "Doesn't Work")

DNS down: no error message. Browser just says "cannot resolve." Users think: their WiFi is broken, the website is down, their computer is broken. EVERY service fails simultaneously but with DIFFERENT symptoms. Debugging: impossible for non-experts. Data: user reports say 50 different things but root cause is ONE DNS failure.
Cascading Retry Storms Amplify the Problem

Service A calls Service B. B is slow. A retries. A retries 3x. But: 1000 instances of A all retry simultaneously → B gets 3000x normal load → B crashes → A gets errors → A retries MORE aggressively → feedback loop. The RETRY designed for resilience CAUSES the failure. Load goes: 1x → 3x → 9x → 27x in seconds. Exponential amplification.
Observability Dies WITH the System It Monitors

Monitoring service runs on the same infrastructure it monitors. cloud provider goes down → CloudWatch goes down → you can't see that cloud provider is down. The alerting system IS the thing that's broken. "No alerts" doesn't mean "no problem" — it might mean "alerting is dead." You need monitoring of your monitoring. But where does that run?
Partial Failure (Worse Than Complete)

Complete failure: obvious, immediate response. Partial failure: some requests succeed, some fail, some are slow. 10% of users affected. Which 10%? Different each minute. Monitoring: "99% success rate — healthy!" But: that 1% = some users COMPLETELY unable to use the service while most are fine. Partial failure HIDES from aggregate metrics.
DNS Poisoning / Cache Corruption

Attacker or bug corrupts DNS cache → wrong IP for domain → users sent to wrong server for TTL duration (minutes to hours). EVERY user served wrong content from the cache. You don't know it's happening because from your server's perspective: nobody is connecting (traffic went elsewhere). Detection: requires EXTERNAL probing of your own domain, not internal monitoring.
Virus/Malware Propagation (ransomware worm, destructive malware)

ransomware worm (2017): spread laterally across networks using SMB exploit. Infected machine → scans local network → infects ALL vulnerable machines in seconds. destructive malware: spread via accounting software update → destroyed 10,000+ machines at Maersk in 10 minutes. Speed of propagation: faster than human response. By the time you detect it: entire network already compromised.
Post-Mortem Data Reconstruction

After major outage: "what happened?" But: logs are ON the machines that crashed, metrics service was down, timestamps are unreliable (NTP failed too), events from different services can't be correlated (clock skew). Reconstructing the incident timeline is forensic archaeology, not data analysis. The most critical 5 minutes of data = the 5 minutes where data collection failed.
