Banking Operations

Statistical pitfalls in banking data systems — settlement timing, regulatory noise, and the gap between displayed and actual state.

1. Real-time vs Batch Settlement
Transfer initiated = "pending"; settled = 1-3 days later; balance shown to user ≠ actual settled balance. Two systems see different "truth" at the same moment. Race conditions between real-time display and batch settlement create a danger zone where data is fundamentally inconsistent — neither system is wrong, they just disagree on temporal reality.
2. Anti-money Laundering Over-filing
SARs (Suspicious Activity Reports) filed defensively: 90%+ are noise to avoid regulatory penalties for under-filing. The "suspicious" label in data = mostly CYA, not actual suspicion. Real signal is buried in defensive noise. Any model trained on SAR labels is learning "what makes compliance officers nervous about regulators" not "what is actually suspicious."
3. Multi-currency Settlement Timing
Buy EUR Monday, settle Wednesday, report Friday in USD — at which rate? Monday's? Wednesday's? Friday's? The same transaction shows different amounts depending on when you look and which FX rate you apply. Three valid answers to "how much was this transaction?" and none of them agree with each other.
4. KYC Data Staleness
Customer verified 5 years ago; address, income, employer all changed since. "Verified customer" = verified at a point in time that's long past. Risk assessment based on stale KYC = risk assessment of a ghost. The data decays silently — no flag tells you the customer's life has diverged from what's on file.
5. Check Hold / Provisional Credit
Bank credits account provisionally; check bounces 3 days later; credit reversed. In between: customer sees a "balance" that's fictional. Any model using "current balance" during the hold period is using lies. The system presents provisional state as fact, and nothing in the data schema distinguishes real money from hope.
6. Regulatory Reporting Consistency
Report the same number to 3 regulators using 3 different definitions of "exposure." Internal systems don't match ANY of the three. Reconciliation is a permanent state of "approximately right." The concept itself has no single definition — so any single number you pull from the database is both correct and wrong simultaneously.
