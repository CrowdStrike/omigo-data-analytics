Silent Data Poisoning

Pipeline bugs that corrupt data without triggering alerts. The data looks fine — row counts match, no nulls, no schema violations. But the VALUES are wrong. Downstream models train on poison. Dashboards report fiction. Business makes decisions on corrupted ground truth.

The core problem: Most data validation checks structural correctness (schema, nulls, types, row counts). Almost nobody validates SEMANTIC correctness (do the values make sense? did the distribution shift? are relationships between columns preserved?). A bug that produces wrong-but-plausible values passes every structural check and poisons everything downstream silently.

Pitfall 1: JOIN Fanout — Silent Row Multiplication

One-to-Many JOIN Silently Duplicates Revenue
  • The bug: Table A has one row per order. Table B has one row per item in the order. JOIN A to B on order_id → each order appears N times (once per item). If you then SUM(order_total), each order's total is counted N times.
  • Why it's silent: Row count increases — but "more rows" isn't inherently wrong. No nulls. No schema violation. The numbers are plausible (revenue went up — great!). No alert fires.
  • Discovery timeline: Weeks to months. Often found only when someone manually checks: "wait, revenue can't be 4× higher than last quarter." Or during annual reconciliation against finance's numbers.
  • Blast radius: Every downstream model, dashboard, and decision that used this revenue number. Forecast models trained on inflated revenue. Budget allocations based on phantom growth. Headcount plans sized for revenue that doesn't exist.

Pitfall 2: Timezone/Encoding Bugs — Correct Structure, Wrong Values

Every Row Looks Valid. Every Value Is Shifted.
  • Timezone shift: Pipeline migrates to new server. New server defaults to UTC. Old server was PST. All timestamps shift +8 hours. No error — timestamps are valid timestamps. But "morning purchases" are now "afternoon purchases." Hourly patterns completely wrong. Any time-of-day feature in a model is now poisoned.
  • Encoding flip: Upstream system changes from Latin-1 to UTF-8 encoding. Most characters identical. But accented names, special chars now render differently. String matching breaks silently. Customer "José" ≠ "José" (different byte sequences). Dedup logic fails. Same customer appears twice.
  • Null representation change: Upstream starts sending empty string "" instead of NULL. Your pipeline's `WHERE col IS NOT NULL` now includes empty strings. Aggregations include garbage. COUNT(*) jumps. Averages dilute toward zero.
  • Silent type coercion: Column changes from INT to FLOAT upstream. 100 becomes 100.0. String comparison: "100" ≠ "100.0". JOIN keys stop matching. Rows silently drop from result set. Revenue shrinks 30%. Nobody notices for a week because "some variance is normal."

Pitfall 3: Stale Cache / Snapshot — Data Stops Updating but Looks Current

The Pipeline Ran Successfully. It Just Read Yesterday's Data.
  • The bug: ETL job reads from a materialized view. View refresh fails silently (permission change, timeout). ETL succeeds — it read the view, got data, wrote output. But the data is stale. Today's dashboard shows yesterday's numbers. No error anywhere in the pipeline.
  • The cache variant: Feature store caches feature values. Cache TTL expires. Fallback: serve last known value. Feature "user_last_login" stuck at 3 days ago for all users. Model sees everyone as "inactive." Recommendations degrade. No alert because the feature IS populated — just stale.
  • The snapshot variant: Training data is a monthly snapshot. Snapshot job silently re-reads last month's export (hardcoded path, forgot to update). Model "retrained" on identical data. Metrics don't change. "Model is stable!" No — model is frozen. New patterns in data are invisible to it.
  • Discovery: Often only when a human notices: "this number hasn't changed in 3 days" or "model predictions are identical to last week." Automated checks pass because data EXISTS and has the right shape.

Pitfall 4: Upstream Schema Change — Silent Semantic Shift

Column Name Didn't Change. Meaning Did.
  • The classic: Upstream team adds a new category to the `event_type` enum. Your pipeline filters `WHERE event_type IN ('click','view','purchase')`. New type `'add_to_cart'` silently excluded. Funnel analysis misses a step. Conversion rate drops in your dashboard (not in reality).
  • The reuse: Upstream deprecates `status=7` ("trial expired"), reuses it for "enterprise_pending." Your pipeline: `WHERE status != 7` (exclude expired trials). Now also excludes enterprise leads. Sales team wonders why pipeline is "dry" for enterprise segment.
  • The backfill: Upstream backfills historical data with a corrected formula. Your pipeline already processed the old values. Now you have two versions of truth — old formula for rows processed before the backfill, new formula for rows after. Time series has a discontinuity. Model trained across the boundary learns the discontinuity as a "pattern."
  • The default change: Upstream changes a column's default from 0 to NULL. Your pipeline: `AVG(col)` — with 0s, average was diluted. With NULLs (excluded from AVG), average jumps. "Wow, metric improved 40%!" No — the denominator changed. Nothing real happened.

Pitfall 5: Partial Failure — Some Rows Poisoned, Most Fine

99% of Data Is Correct. The 1% Corrupts Downstream.
  • Race condition: Pipeline reads table while another job is writing. 98% of rows: correct. 2% of rows: partially written (some columns updated, others still old values). No error — all columns non-null, all types valid. But some rows have price from Tuesday and quantity from Monday. Revenue calculations for those orders: wrong.
  • Sparse corruption: A sensor intermittently sends -999 as a sentinel for "no reading." Pipeline treats it as a real value. Average temperature: pulled down by occasional -999s. Anomaly detection doesn't flag it because it's "rare." But ML model learns -999 as a valid temperature → predictions nonsensical for those time periods.
  • Silent truncation: VARCHAR(50) column receives a 60-char value. Database silently truncates. No error. But the value is now wrong — a URL missing the last 10 chars doesn't resolve. A product name ending in "..." isn't searchable. An address without the zip code can't be geocoded. 1% of rows silently mangled.
