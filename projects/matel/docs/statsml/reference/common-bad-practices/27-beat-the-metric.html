Beat the Metric

Metric Manipulation — Engineering, science, and design optimized to pass the test rather than improve the system. Goodhart's Law weaponized: "When a measure becomes a target, it ceases to be a good measure."

The Practice
  • System has a defined evaluation metric (accuracy, emissions limit, test score, latency SLA).
  • Instead of improving the underlying system, engineer specifically to pass the test condition.
  • System performs well on the metric, poorly on everything the metric was supposed to proxy for.
  • The metric stops measuring what it was designed to measure — but nobody updates it because "we're hitting targets."
Real-World Examples
Volkswagen Dieselgate (2015)
Software detected EPA test conditions (wheels spinning, steering idle) and switched to low-emission mode. Passed the test at 40x actual real-world NOx emissions. Cars "beat the metric" while poisoning air for 11 million drivers.
Teaching to the Test
Schools drill students on specific test patterns to raise standardized scores. Scores rise, but students can't apply knowledge to novel problems. The metric (test score) improves; the thing it measures (learning) doesn't.
Wells Fargo Fake Accounts (2016)
Target: accounts opened per employee. Solution: open 3.5 million fake accounts without customer consent. Metric soared. Actual customer value: negative. $3B in fines.
Cobra Effect — Colonial India
British government offered bounties for dead cobras. People bred cobras to kill them for the bounty. When the program was cancelled, breeders released their stock. Cobra population increased.
Public Ratings & Rankings
US News ranks universities on selectivity, alumni giving, class size, spending per student. Schools game these (reject more applicants, reclassify spending, manipulate class sizes) rather than improving education. J.D. Power ranks cars on specific survey dimensions — manufacturers engineer for those exact survey moments. ESG ratings measure specific criteria — companies staff ESG-reporting teams instead of reducing actual environmental impact. The product stays the same; the score improves.
Tokenmaxxing (AI Products, 2024–)
Companies measure "AI adoption" by tracking token consumption — how many tokens their teams or products consume. The metric is supposed to proxy for "how effectively are we using AI to build better products." The degenerate shortcut: agents and workflows that repeatedly read irrelevant files, re-scan entire codebases for no reason, regenerate already-available context, and invoke LLMs for trivially scripted tasks — all to pump the token count. Millions of tokens burned. No additional value created. The team "leads in AI adoption" on the dashboard while shipping the same code they would have written anyway. The metric incentivizes waste, not leverage.
Pentesting as Security Theater
Company runs annual pentest on a defined scope (3 apps, 2 weeks). Engineering fixes those specific findings. Security "posture" declared improved. But: the other 47 apps, the internal APIs, the build pipeline, the CI secrets, the employee lateral movement paths — untested, unfixed, unknown. Teams over-invest in the tested surface (because those findings appear in the report) while ignoring systemic weaknesses that no pentest ever touches. The metric ("pentest findings resolved") goes to zero. Actual security posture: unchanged. The pentest scope IS the security program — everything outside it doesn't exist.
Code Review as Rubber-Stamping
Compliance requires "100% of code reviewed before merge." The metric: review coverage. The degenerate shortcut: approvals in under 60 seconds, "LGTM" on 500-line diffs, reviewers who open the PR and immediately click approve. The number says 100% reviewed. Reality: 5% actually read with intent. The metric creates an illusion of oversight while the actual defect-catching benefit approaches zero. Teams optimize for the checkbox (fast approvals, no blocking) rather than the goal (catching bugs and design flaws before production).
Unit Test Coverage Targets
Target: 100% line coverage. The trivial shortcut: write tests that execute every line but assert nothing meaningful. expect(fn()).not.toThrow() on every function. Tests that verify the code RUNS, not that it's CORRECT. Coverage report: green, 100%. Actual quality assurance: near-zero. Worse: developers spend time writing vacuous tests instead of fewer, thoughtful tests on the critical paths. The metric penalizes the team that writes 60% coverage of meaningful property-based tests and rewards the team that writes 100% coverage of assert(true).
In ML/Data Science
  • Overfitting to the test set: Model tuned until it scores 95% on held-out eval — but eval set doesn't represent production distribution. Deployed model fails on real data.
  • Optimizing proxy metrics: Maximize click-through rate → get clickbait. Maximize engagement → get outrage content. Maximize watch time → get addictive loops. The proxy diverges from the goal.
  • Adversarial test gaming: Know the test suite? Engineer features that exploit test data patterns. Model performs well on benchmark, collapses on slightly different inputs.
  • Benchmark hacking in research: Tune architecture and hyperparams on the "held-out" test set of a public benchmark. Paper reports SOTA. Model doesn't generalize to any other dataset.
Why It Persists
  • Incentive alignment: Person is rewarded for metric, not outcome. Rational to optimize the reward signal.
  • Measurement lag: Real outcome takes months/years to observe. Metric available now. Short-term metric wins attention.
  • Complexity of root cause: Actually improving the system is hard, uncertain, multi-quarter. Gaming the metric is fast, predictable, promotable.
  • Audit theater: Auditors check the metric, not the system. If number green, ship it.
