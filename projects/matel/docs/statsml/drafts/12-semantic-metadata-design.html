Semantic Metadata

Statistical significance without semantic plausibility is noise. Semantic plausibility with weak statistics is a finding worth pursuing.

1. The Problem

Pipeline finds: height correlates with credit default (p=0.02). Strong statistic. But no causal mechanism — spurious.

Pipeline finds: income correlates with credit default (p=0.08). Weak statistic. But obvious causal pathway — real signal needing more data.

Statistics can't distinguish these. Semantics can.

2. Three Layers

Layer 0 — Fact Sheet: col_name, data_dict, values, types, shapes. Mechanical. No judgment.

Layer 1 — Assessment: LLM interprets facts. Multiple hypotheses tagged as fact, derived, or guess.

Layer 2 — Lineage: Tracks transformations. Assessments get promoted or demoted as evidence accumulates.

3. Layer 0: Fact Sheet

Every column gets one. Same fields. Repeatable.

  • col_name, data_dict entry, dataset intention
  • type_scores (int_num, flt_num, cat...)
  • range, percentiles, unique count
  • shape_scores from CNN
  • sibling columns in the dataset
  • target variable and base rate

This is just what exists. Zero interpretation.

4. Layer 1: Assessment

LLM reads fact sheet → produces hypotheses:

  • fact: directly from data (trust=1.0)
  • derived: traceable inference (trust=0.7)
  • guess: hypothesis to test (trust=0.3)

Multiple assessments coexist. "Probably kg" and "could be lbs" both survive until evidence resolves.

Each has confidence + basis (which fact-sheet fields support it).

5. Layer 2: Lineage

When data is filtered, split, or transformed — assessments travel with it and evolve:

  • Promoted: "bimodal due to gender" (guess) → split by gender → two clean bells → now a fact
  • Demoted: "income predicts default" (derived) → no enrichment found → now a guess
  • Removed: "possibly bimodal" → already split → no longer applicable

Lineage = evidence accumulation. Knowledge sharpens through the pipeline.

6. The Payoff

Final strength = statistical signal × semantic relevance

  • Strong stat + strong semantic = report confidently
  • Weak stat + strong semantic = investigate deeper
  • Strong stat + no semantic = suspicious, likely spurious
  • Weak stat + no semantic = ignore

7. Pipeline Example: Weight in a Readmission Model

Step 1 — Raw ingestion:

  • Fact sheet built: flt_num=1.0, range=[38,188], n=4820, bell=0.65, bimodal=0.42
  • Assessment (LLM): "body mass in kg" (derived, 0.95), "bimodal likely gender mix" (guess, 0.6)

Step 2 — Split by gender:

  • Male subset: bell=0.91, μ=82, σ=12
  • Female subset: bell=0.88, μ=65, σ=11
  • "bimodal due to gender" promoted: guess→fact (confirmed)

Step 3 — Outlier check on male subset:

  • 3 values > 150kg. Assessment: "morbid obesity, genuine" (derived, 0.8) — not contamination because range is biologically valid
  • Without semantic: pipeline would winsorize or remove. With: keeps them.

Step 4 — Test selection:

  • bell=0.91, n=2400 → t-test valid
  • Semantic: weight causally plausible for readmission (derived, 0.7)
  • Result: p=0.04, enrichment=1.3× in top quintile → STRONG (both axes)

8. Pipeline Example: ID Column

Step 1 — Raw ingestion:

  • Fact sheet: int_num=0.8, cat=0.2, unique_ratio=1.0, range=[1,4820]
  • Assessment (LLM): "row identifier, not a feature" (derived, 0.9)

Step 2 — Without semantics:

  • Pipeline treats as numeric. Uniform shape. Runs tests. Finds spurious p=0.03 correlation with target (sequential IDs correlate with time-based outcome drift).

Step 3 — With semantics:

  • Assessment says "identifier" → auto-excluded from feature set before any test. No wasted computation, no false discovery.

Semantic metadata prevents entire classes of errors that statistical checks alone cannot catch.

9. Open Questions

Combination math: How do semantic confidence and p-value combine? Options: (a) Bayesian — semantic as prior, statistics as likelihood; (b) multiplicative penalty — p_adj = p / semantic_conf; (c) gating — below semantic threshold, don't report regardless of p. Each has different failure modes.

Archetype library: Pre-built assessment templates for common column types (age, income, identifier, date, zip_code). LLM matches column to archetype first, then customizes. Reduces cost and improves consistency. Question: how many archetypes cover 80% of columns in practice?

Depth decay: After 5 transformations, original assessments are stale. Linear decay? Exponential? Or event-based — only decay when a transformation contradicts the assessment?

Coverage metric: What fraction of pipeline decisions have semantic backing? If coverage < 40%, the metadata isn't earning its keep. If > 90%, probably over-specified. Target sweet spot?

Conflict resolution: Two assessments contradict (one says "age in years" another says "months since birth"). Resolution: which fact-sheet fields does each cite? More grounded one wins. Ties go to the one with shorter derivation chain.

Cost/benefit: LLM call per column adds latency and cost. For a 500-column dataset, is batch assessment (all columns in one prompt) accurate enough? Or does per-column prompting with sibling context matter?

Mathematical data model for transformations: Need a formal way to capture data transformations of all kinds — their inputs, outputs, and semantic implications. Currently transformations are tracked as free-text lineage. Need a structured representation that can answer: "What happened to this column? Can I invert it? Did it change the distribution?"

  • Capping/winsorizing: cap(cholesterol, max=400) — changes shape (removes right tail), invalidates kurtosis, makes max non-informative. Invertible? Only partially (original values above cap are lost).
  • Mathematical functions: log(income), sqrt(area), 1/x — each changes scale, shape, and interpretability differently. Log compresses tail; sqrt mild compression; inverse flips ordering. Need to track what quantity the result represents (geometric mean? rate?).
  • Combining columns: BMI = weight / height², debt_ratio = debt / income — derived features inherit distributions from BOTH parents. If income is bimodal, debt_ratio is too. Parent distributions predict child distribution.
  • Binning/discretization: age_group = bucket(age, [0,18,35,55,65,∞]) — continuous → categorical. Destroys within-bin variance. Boundary choices are modeling decisions.
  • One-hot / dummy encoding: Categorical → N binary columns. Each column has spike+zero distribution. Correlated by construction (sum = 1).
  • Standardization/normalization: (x - μ) / σ — linear transform, preserves shape and tests, but original scale is lost for interpretation.

The model should capture: (1) transformation type and parameters, (2) which statistical properties are preserved vs destroyed, (3) what the result means semantically in original-scale terms, (4) whether it's invertible and what information is lost. This enables the pipeline to: propagate parent assessments to derived columns, know which tests are still valid after transformation, and translate results back to meaningful units.
